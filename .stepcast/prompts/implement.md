Реализуй задачи из плана предыдущей работы.

В контексте — план: список задач с файлами и признаком выполненности, а также
слаг изменения `${jobs.propose.output.slug}`.

Правила:

- сначала прочитай `tasks.md`; перед очередной задачей читай только спеки,
  относящиеся к её файлам и критерию готовности;
- меняй только `src/`, `test/`, `docs/` и каталог изменения
  `openspec/changes/${jobs.propose.output.slug}/`;
- отмечай выполненные задачи в `tasks.md` изменения по ходу дела;
- каждая задача плана — код **и** тест: непокрытая правка движка здесь не
  считается сделанной;
- пиши в стиле окружающего кода: комментарий объясняет «почему», а не «что»,
  и появляется там, где решение неочевидно;
- нереализованное не деградирует молча — линт или движок отказывают и называют
  причину. Если возможность не доделана, она должна отклоняться с внятной
  ошибкой, а не работать наполовину;
- если изменение переводит возможность из «Пока нет» в «Работает» или снимает
  известное ограничение, отрази это в фрагменте
  `openspec/changes/${jobs.propose.output.slug}/status.md` и пересобери
  `docs/status.md` командой `npm run status:build`; собранный документ руками
  не правь — правка потеряется при следующей пересборке;
- если проверка `npm run check` упала, её вывод придёт следующим сообщением —
  чини причину, а не симптом;
- `backlog.md` не трогай — его ведёт движок петли.
