# Встроенный слой скриптов

Третий и последний слой разрешения шага `script` (`docs/pipeline-format.md`,
«Разрешение путей»): голое имя ищется сперва в `<проект>/.stepcast/scripts/`,
затем в `~/.stepcast/scripts/`, и только потом здесь — в каталоге, который
поставляет сам пакет stepcast.

Это не тот `scripts/`, что лежит в корне репозитория. Корневой `scripts/`
несёт сборочные скрипты самого stepcast (`generate-schema.ts` и подобные) —
дело сборки, а не то, что пайплайн вправе позвать по имени. Объявить его
встроенным слоем значило бы дать любому пайплайну на любой машине вызвать
внутренний инструмент сборки как `script: generate-schema.ts`. Поэтому слой
для шага `script` — отдельный каталог, и до сих пор пуст: наполняют его
следующие пункты очереди, стоящие на этом изменении (`script-step-contract`,
`script-predicate`, `reusable-steps`).

Каталог живёт под `src/`, а не рядом с `schema/`: содержимое каталога — не
исходный код, который компилирует `tsc`, а файлы, которые движок находит на
диске как есть, и пакет публикует его раздельной записью `files` в
`package.json` (`src/builtin`), не общей записью `dist`.

Файл в этом каталоге находится тем же путём, каким `packagedSchemaPath`
находит опубликованные JSON Schema пакета (`src/core/package-schema.ts`):
от расположения самого движка, а не от каталога, из которого его вызвали, —
поэтому встроенный слой работает одинаково из исходников, из `dist/`, из
`node_modules` целевого репозитория и из глобальной установки.
