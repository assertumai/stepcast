# Директория прогона

Состояние прогона — это файлы. SQLite нужен только как индекс для UI (список
прогонов, поиск), источник правды — директория. Всё, что можно сравнить
обычным `diff`, сравнивается обычным `diff`.

## Расположение

```
~/.scarp/
  projects.json                       # hash → путь репозитория
  runs/
    a3f19c2b7e40/                     # sha256(realpath корня репо)[0:12]
      2026-08-16T14-03-22Z-3f9a1c/
      2026-08-16T18-40-05Z-c81de2/
      latest -> 2026-08-16T18-40-05Z-c81de2
```

Ключ по репозиторию обязателен: без него прогоны разных проектов смешиваются, и
`resume` ищет не там. Человекочитаемое соответствие хранится в `projects.json`.

Права `0700` на дерево, `0600` на файлы: в логи агентов попадают содержимое
исходников и, при неаккуратной конфигурации, токены.

## Дерево одного прогона

```
2026-08-16T14-03-22Z-3f9a1c/
  run.json              # манифест: пайплайн, входы, git ref, итог
  pipeline.lock.yml     # пайплайн после раскрытия uses/defaults/подстановок
  status.json           # текущее состояние, самодостаточно для возобновления
  events.ndjson         # поток событий для UI и постмортема
  cost.json             # агрегат расхода
  artifacts/            # объявленные outputs работ
    implement/report.json
  jobs/
    implement/
      job.json
      iter-1/
        steps/
          01-plan/
            step.json     # ключ, статус, попытки, usage
            prompt.txt    # ровно то, что ушло бэкенду
            stdout.log
            stderr.log
            output.json   # структурированный вывод бэкенда
            expect.json   # результат каждого предиката
            diff.patch    # что шаг изменил в рабочем дереве
          02-implement/
      iter-2/
        steps/ ...
    test/
```

Итерации внутри job — это `until`-цикл. Вторая итерация видит `expect.json`
первой; протокол её проб и ошибок она не наследует.

`prompt.txt` хранится всегда и целиком. Это единственный способ потом понять,
почему шаг повёл себя так, а не иначе, и без него дифф прогонов бесполезен.

## Ключ шага

```
step_key = sha256(
    нормализованное определение шага из pipeline.lock.yml
  + развёрнутый текст промпта
  + content-hash объявленных context/inputs
  + backend id + model + версия бэкенда
  + ключи выходов, полученных от вышестоящих работ
)
```

Рабочее дерево в ключ целиком не входит — только объявленные входы. Прогон
дополнительно фиксирует в `run.json` git `HEAD` и хеш незакоммиченных
изменений, чтобы отличать «те же входы в другом состоянии репозитория».

Ключ решает три задачи разом: возобновление (шаг с совпавшим ключом и статусом
`success` не переисполняется), дифф прогонов (совпадение ключей показывает, что
именно изменилось) и запрет идентичного повтора (попытка с тем же ключом
отклоняется).

## status.json

Критерий: новая сессия без прежнего контекста должна продолжить работу, имея
только этот файл.

```json
{
  "run_id": "3f9a1c",
  "pipeline": "implement-change",
  "lock_hash": "8e21…",
  "git": { "head": "83c2513", "dirty_hash": "0f4a…" },
  "inputs": { "change": "add-oauth-e2e-tests", "skip_e2e": false },
  "status": "failed",
  "jobs": {
    "implement": { "status": "success", "iterations": 2 },
    "test": {
      "status": "failed",
      "failed_step": "02-run-tests",
      "attempt": 3,
      "expect_failed": [
        { "predicate": "exit_code", "expected": 0, "actual": 1 }
      ],
      "excerpt": "OAuthE2ETest > refresh token … expected 200, got 401",
      "log": "jobs/test/iter-1/steps/02-run-tests/stdout.log"
    },
    "ship": { "status": "skipped", "reason": "when: success(test)" }
  },
  "budget": { "tokens_used": 412000, "tokens_limit": 2000000 },
  "resume": {
    "command": "scarp resume 3f9a1c --from test",
    "blocked_by": "test"
  }
}
```

## Возобновление

```bash
scarp resume <run-id> --from <job|step> [--set k=v]
```

Создаётся новый прогон со ссылкой `resumed_from` на предыдущий. Шаги с
совпавшими ключами и статусом `success` берутся из старого прогона по ссылке и
не переисполняются. Изменение входа через `--set` меняет ключ и делает
невалидными все шаги ниже по графу.

Перенос причины отказа: при возобновлении в контекст первого переисполняемого
шага подкладывается `previous_failure.md` — выдержка из `status.json`
предыдущего прогона и `expect.json` упавшего шага. Прошлые попытки в контекст
не идут.

## Дифф прогонов

```bash
scarp diff <run-a> <run-b>
```

Сравнивает по ключам: какие шаги идентичны, какие изменились, какие появились
или исчезли. Для изменившихся показывает `diff` по `prompt.txt`, `expect.json`
и `diff.patch`. Поскольку всё лежит файлами, это `diff -r` с осмысленной
подачей, а не отдельная подсистема.

Основной сценарий — фича не взлетела со второго захода, и надо увидеть, чем
второй прогон отличался от первого.

## Стоимость

В `step.json`:

```json
"usage": {
  "backend": "claude", "model": "opus",
  "tokens_in": 18422, "tokens_out": 3110,
  "cache_read": 120340, "cache_write": 8200,
  "wallclock_ms": 41250,
  "rate_limit": { "window": "5h", "used_pct": 37 }
}
```

Деньги не хранятся как факт. При запуске по подписке биллингового сигнала нет,
поэтому фактом являются токены, время и потребление окна лимитов, а стоимость
считается производно по таблице цен и лежит отдельным полем. Иначе переход на
API-режим потребует миграции схемы.

Дефицитный ресурс на подписке — окно лимитов, а не бюджет. Именно оно
останавливает ночной прогон, поэтому его расход трекается наравне с токенами.

## Логи

`stdout.log` и `stderr.log` — построчный текст без управляющих
последовательностей: запуск идёт через pipe, эмуляция терминала не
используется, поэтому логи грепаются, диффаются и показываются в UI как есть,
без эмулятора терминала.

`events.ndjson` — по строке на событие (`job.started`, `step.attempt`,
`expect.failed`, `budget.warning`). UI читает хвост файла, ему не нужна база.

Ротация: `scarp gc` удаляет прогоны старше N дней, сохраняя `run.json`,
`status.json` и `cost.json` — сводка остаётся, тяжёлые логи и патчи уходят.
Без этого директория растёт неограниченно.

## CLI

```
scarp lint [pipeline]
scarp run <pipeline> [--input k=v] [--dry-run]
scarp status [--run <id>]
scarp resume <run-id> [--from <job|step>] [--set k=v]
scarp diff <run-a> <run-b>
scarp logs <run-id> [<job>/<step>]
scarp cost <run-id>
scarp gc [--older-than 30d]
scarp ui
```
