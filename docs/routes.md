# Маршруты витрины

Адрес экрана, его место в меню и стартовая страница — не поля кода, а
содержимое файла `routes.yml`. Формат один и тот же для встроенных адресов
(десять экранов поставки) и для адресов, которые назначает пользователь: у
маршрута нет привилегированного вида, есть только слой, из которого он
пришёл.

## Файл и три слоя

| Слой | Файл | В git |
|---|---|---|
| встроенный | `src/builtin/routes.yml` (пакет) | — |
| домашний | `~/.stepcast/routes.yml` | нет |
| проектный | `.stepcast/routes.yml` каталога, в котором поднят демон | да |

Слои складываются снизу вверх, тем же правилом, что и слои конфигурации и
дерево плагинов (`docs/config.md`): каждый следующий видит таблицу,
накопленную предыдущими, и вправе перекрыть в ней строку по `id` либо
дополнить новой. Отсутствие домашнего или проектного файла — обычное
состояние, не отказ: витрина открывается встроенной таблицей.

Проектный слой — файл каталога, в котором поднят демон (`stepcast up`), а не
любого проекта, который демон видит журналом. Файлы маршрутов прочих
проектов, о которых демон знает, в таблицу не входят.

Встроенный файл — не то же самое: его отсутствие или неразбираемость —
отказ подъёма витрины с названием файла и причиной. Без файла поставки
маршрутов нет вовсе, и поднятая с пустой таблицей витрина была бы
неотличима от той, где пользователь отключил всё сам.

## Формат строки

```yaml
routes:
  - id: pipelines
    path: /pipelines
    target: { screen: screen-pipelines }
    nav: { order: 1 }

  - id: run
    path: /runs/:projectKey/:runId
    target: { screen: screen-run }

  - id: release-usage
    path: /release/:period
    target: { screen: screen-usage }
    params:
      period: "${params.period}"
      preset: release
    values: { period: [7d, 30d] }

  - id: team-board
    path: /team
    target: { widget: my-project/team-board }
    nav: { title: Команда, order: 9 }
```

Параметры цели объявлены у маршрута на **экран**: маршрут на виджет с
объявленными `params` — названный отказ на месте цели, пока у виджета нет
контракта `props` (раздел «Цель без действующего вклада» ниже).

Поля строки:

- **`id`** — ключ строки в слиянии слоёв, как у строки дерева плагинов
  (`docs/plugins.md`). Не путь: перенос экрана на другой адрес — правка
  `path` существующей строки, а не новая строка.
- **`path`** — шаблон адреса. Сегмент `:имя` — обязательный параметр,
  `:имя?` — необязательный, допустим только последним сегментом. Значения
  параметров доезжают до цели по этим же именам, без отдельного объявления.
- **`target`** — цель ровно одним ключом вида: `screen: <id>` (по `id`
  экрана действующего состава) либо `widget: <проект>/<id>` (по ключу
  проекта и `id` виджета). Вид цели — не перечисление кода, а ключ слота
  `route.target` браузера: строка, приносящая новый вид (дашборд —
  `dashboards-as-files`), вносит вклад в этот слот, не трогая ни разбор
  адреса, ни каркас.
- **`params`** — необязательные параметры цели: литералы и подстановки вида
  `${params.<имя>}`, тем же языком, что и у пайплайнов
  (`docs/pipeline-format.md`). Подстановка на имя, которого нет в шаблоне
  `path`, — отказ сборки таблицы, названный маршрутом, файлом и именем.
  Значения параметров пути и так доезжают до цели по своим именам; `params`
  доезжают поверх них, и одноимённый литерал сильнее сегмента пути — иначе
  объявить его было бы невозможно.
- **`values`** — необязательный закрытый перечень значений параметра пути,
  по имени: `values: { period: [7d, 30d, 90d, all] }`. Значение вне
  перечня шаблону не подходит — адрес с таким значением остаётся
  неразобранным, как и любой другой неизвестный.
- **`nav`** — необязательное место в навигации: `title` (название пункта;
  не объявлено — берётся заголовок цели), `order` (порядок пункта, меньшее
  значение — выше), `active_for` (список `id` маршрутов, на которых этот
  пункт остаётся подсвеченным, хотя своего пункта у них нет). Маршрут без
  `nav` не даёт пункта меню, но его адрес всё равно открывается.
- **`enabled`** — необязательный признак; `false` убирает маршрут из
  действующей таблицы целиком — из навигации, из разбора адреса и из
  сборки ссылок. Умолчание — `true`.

Неизвестный ключ строки — отказ сборки с указанием файла и места, а не
молча пропущенное поле. Схема формата публикуется в
`schema/routes.schema.json` тем же генератором, что и схемы конфигурации и
пайплайна, и проверяется на свежесть той же проверкой
(`test/schema-generated.test.ts`).

## Слияние строк по `id`

Строка верхнего слоя с уже известным `id` сливается с одноимённой **по
листьям** — `path`, `target`, `params`, `values`, `nav.title`, `nav.order`,
`nav.active_for`, `enabled` — а не заменяет её целиком. Объявленное одно
`nav.title` меняет только название пункта, оставляя путь, цель и порядок
встроенными; строка с новым `id` дополняет таблицу, не задевая остальных.
Источник сохраняется по каждому полю отдельно, а не только по строке —
экран «Маршруты» (ниже) показывает, какой файл дал путь, а какой — название.

Это то же слияние по листьям, каким живут значения конфигурации
(`mergeLayers`), а не слияние строк дерева плагинов (замена целиком): строка
плагина — это `use` и его настройки, единая сущность, а строка маршрута —
набор независимых полей одного адреса.

Маршрут, впервые объявленный не встроенным слоем, обязан назвать `path` и
`target` сам — слить их неоткуда.

## Путь принадлежит одному маршруту

Два действующих маршрута с одинаковым **нормализованным** шаблоном пути —
отказ сборки таблицы, называющий оба `id` и оба файла. Нормализация приводит
каждый параметр шаблона к одному виду: `/runs/:projectKey/:runId` и
`/runs/:a/:b` — один и тот же адрес, имя параметра — дело маршрута, а не
адреса. Лечится правкой строки с уже занявшим путь `id`, а не второй строкой
на тот же путь.

Путь, начинающийся под адресом, который разбирает сам демон — `/api`,
`/widgets/`, `/plugins/`, `/shared/` — отклоняется тем же именованным
отказом: страница по этим адресам не открывается никогда.

Отказ сборки таблицы **не гасит витрину**: действующей остаётся последняя
успешно собранная таблица, причина едет вместе с ней и показывается на
странице — тем же правилом, каким живёт отказ сборки состава экранов
(`docs/ui-plugins.md`, «Отказ сборки состава не гасит витрину»).

## Конкретность решает, какой маршрут открылся

Сопоставление адреса идёт не «первый подошедший по порядку файлов», а по
конкретности шаблона: статический сегмент побеждает параметр на той же
позиции слева направо, а шаблон без хвостового необязательного параметра
побеждает шаблон с ним. `/runs/new` (статический маршрут) и `/runs/:id`
(параметрический) не конфликтуют — оба законны, и `/runs/new` открывает
именно себя независимо от порядка строк в трёх файлах.

## Навигация и стартовая страница

Меню собирается из маршрутов с объявленным `nav`, в порядке `nav.order` и
под названиями `nav.title` (или, если оно не объявлено, — заголовком цели).
Ни каркас, ни маршрутизатор не содержат перечня целей: список — целиком
действующая таблица.

Стартовая страница — не отдельный признак, а маршрут с путём `/`: что
открывается по корню, решает тот, кто назвал этот путь. Корневой адрес без
такого маршрута показывает перечень объявленных маршрутов и называет
причину отдельной строкой: стартовая страница не объявлена.

## Адрес без маршрута

Адрес, не разобранный ни одним действующим маршрутом, показывает перечень
объявленных маршрутов — путь, цель и источник каждого, — а не пустой экран и
не молчаливую подмену другой целью. Тот же перечень работает и тогда, когда
действующих маршрутов нет вовсе (все отключены слоями пользователя): он
называет это состояние и путь к файлу слоя, в который пишутся маршруты.

## Цель без маршрута — не ссылка, а причина

Ссылка собирается по цели (вид и идентификатор), а не по имени экрана:
`hrefFor` ищет в действующей таблице маршрут, ведущий к названной цели, и
подставляет параметры. Несколько таких маршрутов — берётся первый по
таблице (порядок слоёв и файлов), и это решение пользователя: он вправе
выключить или переставить лишний. Ни одного — ссылки нет вовсе, и место
вызова обязано показать это причиной, а не подставить адрес какой-то другой
цели: сняв маршрут страницы прогона, пользователь получит список прогонов,
где у строк честно нет ссылки, а не список, ведущий по клику на главную.

## Цель без действующего вклада

Маршрут вправе назвать цель, которой в действующем составе нет (экран
отключён патчем, виджет не найден в проекте), или вид цели, которого состав
не знает вовсе (третий вид появится вместе с `dashboards-as-files`). Оба
случая показываются названной причиной на месте цели — тем же приёмом,
каким сегодня показывается экран без доступной браузерной половины
(`docs/ui-plugins.md`).

Маршрут на виджет с объявленными параметрами цели — тоже названный отказ на
месте цели: контракта `props` у виджета пока нет (`docs/widgets.md`,
Non-Goals), и подстановка параметров сделала бы вид, что передала их, хотя
виджет их не получает.

## Правка виден в открытой витрине

Наблюдатель демона отпечатывает три файла слоёв своей частью отпечатка
(`mtime` и размер каждого) и пересобирает таблицу только по её сдвигу —
правка `routes.yml` не заставляет перечитывать очередь, виджеты или
прогоны, и наоборот. Действующая таблица и состав экранов идут потоком
событий демона (`overview`/`backlog`/…, `event: routes`, `event: screens`)
первым же обменом при подключении и дальше только при отличии от
отправленного прежде — то же правило, каким сегодня живут события `widgets`
и `plugins`. Открытая вкладка видит новый маршрут, отключённый маршрут или
изменившийся состав экранов без перезагрузки страницы.

## Правка из витрины

Встроенный экран «Маршруты» (`/routes`) перечисляет действующие маршруты —
путь, цель, место в навигации, источник каждого поля и диагностику — и даёт
добавить маршрут или поправить существующий. Строка маршрута и имя слоя
(`home` либо `project`) отправляются `POST /api/routes`; демон называет
файл, в который собирается писать, до самой записи.

Источник показан по каждому полю отдельно, а не по строке целиком: слияние
идёт по листьям, и «путь из проектного файла, название пункта — из
домашнего» — обычное состояние строки.

Отключённые маршруты перечисляются там же, отдельными строками с файлом,
который их выключил, и кнопкой «включить»: маршрут, выключенный из витрины,
иначе исчезал бы из перечня совсем, и вернуть его можно было бы только
правкой файла руками. Строка, сохранённая из витрины, всегда несёт `enabled`
явно — включённая обязана перебивать `enabled: false` нижнего слоя.

Запись идёт через `Document` библиотеки `yaml`: комментарии, порядок прочих
строк и форматирование файла пользователя переживают правку. Встроенный
файл поставки не переписывается никогда — правка встроенного маршрута
кладёт строку с его `id` в домашний либо проектный слой. Файл, который не
разбирается, тоже не переписывается: отказ называет место разбора, чтобы
одно сохранение из витрины не стёрло то, что пользователь не успел
починить.

Тот же экран — источник перечня маршрутов, показанного на неразобранном
адресе (раздел «Адрес без маршрута» выше): это вклад его строки состава в
слот экранов, а не отдельная сущность. Над перечнем в обоих случаях идёт
причина, по которой он показан, — адрес не разобран, стартовая страница не
объявлена, действующих маршрутов нет вовсе. Экран отключён патчем — каркас
показывает ту же причину и перечень адресов голым текстом, без источников и
без формы правки: витрина не должна становиться пустой страницей из-за
выключенного экрана.

## Разбор — общий модуль демона и браузера

Сопоставление адреса с шаблоном, выбор маршрута по конкретности, сборка
ссылки и подстановка параметров живут в `src/ui/routes.ts` — модуле без
единого импорта Node, общем демону и браузеру. Чтение трёх файлов, проверка
схемой, слияние по `id` и диагностика — отдельный модуль демона,
`src/ui/routesFile.ts`, у которого есть диск; страница получает уже
собранную таблицу с источниками и никогда не разбирает YAML сама.
