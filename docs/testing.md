# Тестирование

Тестовый процесс заводит все свои временные файлы в одной песочнице и убирает
её сам — вне зависимости от того, чем закончился прогон и вспомнил ли автор
теста про уборку.

## Песочница

`node --test` даёт каждому тестовому файлу свой процесс. При первом импорте
`test/tmp.ts` заводит в системном временном каталоге корень
`stepcast-test-<случайное>` и сразу переводит в него `TMPDIR`, `TMP` и `TEMP`
процесса — до того, как временный каталог успеет спросить кто-либо ещё. Из-за
этого внутрь песочницы попадает не только то, что заводит сам тест, но и
временное состояние движка, исполняемого под тестом, и дочерних процессов,
которых тест поднял (окружение наследуется).

Тесту нужен временный каталог — он зовёт `tempDir(prefix)` из `test/tmp.ts`:

```ts
import { tempDir } from './tmp.js';

const runsRoot = tempDir('runs-');
```

Имена внутри песочницы не повторяют её префикс: `tempDir('runs-')` заводит
`runs-…`, а не `stepcast-runs-…`. Отсюда прямое следствие для замера ниже —
запись `stepcast-*` в системном временном каталоге означает саму песочницу
(живую или недобранную), а не что-то внутри неё.

Корень снимается на `process.on('exit')` рекурсивно и щадяще — при успехе,
при падении теста, при исключении, брошенном мимо теста, и при завершении
процесса по `SIGINT`/`SIGTERM` (сигнал переподнимается, чтобы код завершения
остался тем же сигнальным). Регистрировать уборку самому не нужно: каталог,
заведённый через `tempDir`, убирается тем, что он в песочнице, а не тем, что
про него вспомнили. Отказ самой уборки (файл занят, каталог держит переживший
тест процесс) не красит прогон: неснятый путь печатается в поток ошибок, а код
возврата остаётся тем, что определён исходом тестов.

## Прямое создание запрещено

Импорт `mkdtempSync` из `node:fs` и `tmpdir` из `node:os` в `test/**` запрещён
правилом линта (`no-restricted-imports`, `eslint.config.js`) — единственное
исключение — сам `test/tmp.ts`. Каталог, заведённый мимо `tempDir`, минует
уборку процесса и остаётся в системном временном каталоге до следующей ручной
расчистки; правило превращает это в отказ `npm run lint`, называющий файл, а
не в утечку, которую заметят только на чужой машине.

То же самое для движка: код в `src/**`, которому нужен временный каталог вне
каталога прогона (состояние якоря сравнения, наложения, плана возобновления),
заводит его через `withTempDir(prefix, fn)` из `src/core/fs/tempDir.ts` —
каталог передаётся телу и снимается в `finally` независимо от исхода, включая
брошенное исключение. Отказ уборки и здесь не становится исходом вызова: путь
неснятого печатается в поток ошибок, а наружу уходит то же, что вернуло или
бросило тело, — иначе вместо «наложение не сошлось» пользователь получил бы
ошибку файловой системы. Исключение из того же правила линта здесь одно —
`src/core/fs/tempDir.ts` сам.

Оба запрета перечислены одной записью правила на файл: блоки плоского конфига
ESLint опции одноимённого правила не сливают, и отдельный блок молча заменил бы
собой соседний (граница ядра и поверхности живёт в том же правиле). Что запреты
действуют одновременно и что исключения остаются исключениями, проверяет
`test/eslint-config.test.ts` — не ревью.

## `STEPCAST_TEST_KEEP=1`

Разбор упавшего теста иногда требует заглянуть в то, что он оставил на диске.
Признак окружения `STEPCAST_TEST_KEEP=1` — единственный способ пережить прогон
намеренно: корень зовётся не `stepcast-test-…`, а `stepcast-test-keep-…`, и
его путь печатается в поток ошибок по завершении процесса — в том числе когда
процесс прерван с клавиатуры. Имя объявляет
намерение — `stepcast-test-keep-…`, найденный назавтра, это чей-то разбор, а
голый `stepcast-test-…` — недобранный остаток, о котором стоит завести пункт.

```sh
STEPCAST_TEST_KEEP=1 node --test dist/test/some.test.js
```

## Замер утечки

Свойство «после прогона в системном временном каталоге не осталось записей
`stepcast-*`» проверяется счётом по чистому `$TMPDIR`:

```sh
export TMPDIR="$(mktemp -d)"
before=$(find "$TMPDIR" -maxdepth 1 -name 'stepcast-*' | wc -l)
npm run check
after=$(find "$TMPDIR" -maxdepth 1 -name 'stepcast-*' | wc -l)
echo "до: $before, после: $after"
```

Исход прогона (весь набор зелёный или часть тестов упала) на результат не
влияет — уборка не зависит ни от него, ни от `STEPCAST_TEST_KEEP`, который в
этом замере не выставлен.
