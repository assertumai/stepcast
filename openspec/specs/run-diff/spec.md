# run-diff Specification

## Purpose
Сравнение двух прогонов по ключам шагов и по содержимому промпта, контекста, результатов проверок и деревьев.
## Requirements

### Requirement: Сравнение прогонов по ключам шагов

Команда `stepcast diff <run-a> <run-b>` SHALL сопоставлять шаги двух прогонов по
паре идентификаторов работы и шага и относить каждый к одной из категорий:
совпавший по ключу, различающийся по ключу, присутствующий только в одном из
прогонов. Порядок вывода MUST повторять порядок исполнения, а не порядок
обнаружения различий.

#### Scenario: Идентичные прогоны

- **WHEN** сравниваются два прогона, все шаги которых совпали по ключам
- **THEN** вывод сообщает об отсутствии различий, а команда завершается кодом 0

#### Scenario: Шаг изменился

- **WHEN** ключ шага различается между прогонами
- **THEN** шаг отнесён к различающимся

#### Scenario: Шаг есть только в одном прогоне

- **WHEN** работа второго прогона содержит шаг, отсутствующий в первом
- **THEN** шаг отнесён к присутствующим только во втором прогоне

#### Scenario: Порядок вывода

- **WHEN** различаются шаги из разных работ
- **THEN** они выведены в порядке исполнения работ и шагов внутри них

### Requirement: Для различающихся шагов показывается, чем они различаются

Для шага, чьи ключи не совпали, система SHALL показывать построчное сравнение
отправленного промпта, состава контекста и результатов предикатов, а также
сравнение состояний рабочего дерева по якорям. Различия MUST группироваться по
источнику, чтобы изменение промпта не смешивалось с изменением дерева.
Отсутствующий у шага источник MUST помечаться как отсутствующий, а не как
пустой.

#### Scenario: Разошлись промпты

- **WHEN** у различающегося шага отличается отправленный промпт
- **THEN** вывод содержит построчное сравнение промптов

#### Scenario: Разошёлся состав контекста

- **WHEN** у различающегося шага отличается состав контекста
- **THEN** вывод показывает добавленные, исчезнувшие и изменившиеся записи контекста

#### Scenario: Разошлись деревья

- **WHEN** у различающегося шага отличаются якоря рабочего дерева на конец шага
- **THEN** вывод содержит перечень путей, различающихся между деревьями

#### Scenario: Шаг команды без контекста

- **WHEN** различающийся шаг является шагом командной строки и промпта не имеет
- **THEN** источники промпта и контекста помечены как отсутствующие

### Requirement: Несравнимые прогоны отклоняются

Сравнение SHALL отклоняться, если прогоны относятся к разным проектам. При
разных пайплайнах или разных способах фиксации состояния дерева сравнение MUST
выполняться, а несравнимые части MUST помечаться, а не выдаваться за различие.

#### Scenario: Разные проекты

- **WHEN** сравниваются прогоны разных проектов
- **THEN** команда завершается ошибкой с указанием обоих проектов

#### Scenario: Разные пайплайны

- **WHEN** сравниваются прогоны разных пайплайнов одного проекта
- **THEN** сравнение выполняется, а несовпадение пайплайнов отмечено в выводе

#### Scenario: Разные способы фиксации дерева

- **WHEN** один прогон фиксировал деревья средствами git, а другой хеш-манифестом
- **THEN** сравнение деревьев помечено как невозможное, а сравнение промптов и контекста выполняется

### Requirement: Адресация прогонов в командах

Прогон SHALL адресоваться коротким идентификатором, полным идентификатором или
указателем на последний прогон проекта. Неоднозначный или неизвестный
идентификатор MUST отклоняться с перечислением подходящих кандидатов.

#### Scenario: Короткий идентификатор

- **WHEN** прогон указан коротким идентификатором
- **THEN** он разрешается в директорию прогона текущего проекта

#### Scenario: Последний прогон

- **WHEN** вместо идентификатора указан признак последнего прогона
- **THEN** он разрешается в самый свежий прогон текущего проекта

#### Scenario: Неизвестный идентификатор

- **WHEN** указанный идентификатор не соответствует ни одному прогону проекта
- **THEN** команда завершается ошибкой и перечисляет несколько последних прогонов
