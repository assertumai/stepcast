## ADDED Requirements

### Requirement: Инициализация разворачивает практику памяти по запросу

Система SHALL принимать у `stepcast init` флаг `--knowledge <источник>`, разворачивающий каталог знания, файл правил письма и секцию `project.knowledge` в проектном конфиге. Без флага инициализация практику памяти не MUST создавать.

#### Scenario: Разворачивание встроенного источника

- **WHEN** выполнено `stepcast init --knowledge fs`
- **THEN** создан каталог знания с одной единицей-образцом, файл правил письма и секция `project.knowledge` с `provider: fs`

#### Scenario: Инициализация без флага

- **WHEN** выполнено `stepcast init` без флага
- **THEN** каталог знания не создаётся, и секция `project.knowledge` в конфиге не появляется

#### Scenario: Развёрнутое проходит собственную проверку

- **WHEN** сразу после `stepcast init --knowledge fs` выполнено `stepcast knowledge check`
- **THEN** проверка проходит с нулевым кодом возврата

### Requirement: Инициализация не перезаписывает существующую практику памяти без согласия

Система SHALL отказывать `stepcast init --knowledge` при уже объявленной секции `project.knowledge` или существующем каталоге знания, называя, что именно занято, и MUST перезаписывать только по явному подтверждению — тем же правилом, каким инициализация бережёт существующий пайплайн.

#### Scenario: Каталог знания уже есть

- **WHEN** выполнено `stepcast init --knowledge fs` в репозитории с существующим каталогом знания
- **THEN** команда отказывает, ничего не изменив, и называет занятый путь

### Requirement: Существующая конфигурация проекта не переписывается никогда

Система SHALL не переписывать существующий `.stepcast/config.yml`, в том числе при `--force`: подтверждение относится к развёрнутому разворачиванием — каталогу знания и файлу правил, — а не к конфигурации проекта, в которой лежат команда проверки, границы правок и бюджеты. Вместо правки система SHALL печатать состав секции, который автору предстоит дописать самому.

#### Scenario: Подтверждение не стоит конфигурации

- **WHEN** выполнено `stepcast init --knowledge fs --force` в репозитории с непустым `.stepcast/config.yml`
- **THEN** содержимое конфигурации не изменяется, каталог знания и файл правил перезаписываются, а состав секции печатается вызывающему
