## ADDED Requirements

### Requirement: Вывод агентского шага показывается разобранным ходом

Дашборд SHALL показывать вывод агентского шага разобранным ходом, а не сырым потоком бэкенда.
Ход MUST состоять из записей, отвечающих на вопрос «что шаг делал»: реплики
модели, вызовы инструментов и итоговый ответ шага. Вызов инструмента и его
исход MUST быть сведены в одну запись по идентификатору вызова, а исход MUST
отличать успех от ошибки. Вызов, оставшийся без исхода, и исход, оставшийся без
вызова, MUST показываться как есть, а не скрываться из-за отсутствия пары.
Порядок записей MUST повторять порядок потока. Сырой файл `stdout.log` MUST
оставаться раскрываемым как файл журнала.

#### Scenario: Ход шага вместо сырого потока

- **WHEN** пользователь раскрывает вывод исполнившегося агентского шага
- **THEN** он видит реплики модели, вызовы инструментов и итоговый ответ, а не строки NDJSON

#### Scenario: Вызов инструмента показан вместе с исходом

- **WHEN** поток шага содержит вызов инструмента и пришедший на него результат
- **THEN** вывод показывает их одной записью с именем инструмента, его входом и исходом
- **AND** исход, помеченный бэкендом как ошибка, отличим от успешного

#### Scenario: Вызов, оставшийся без исхода

- **WHEN** шаг оборван на середине вызова инструмента, и результата в потоке нет
- **THEN** вывод показывает вызов записью без исхода, а не скрывает его

#### Scenario: Сырой поток остаётся доступным

- **WHEN** пользователь раскрывает `stdout.log` того же шага как файл журнала
- **THEN** интерфейс показывает содержимое файла как есть

### Requirement: Неразобранная строка потока не теряется

Строка вывода, которую разобрать не удалось, SHALL показываться как есть на своём месте в порядке потока.
Это MUST касаться всех трёх случаев: строки, не разбираемой как JSON; записи
JSON незнакомого вида; обрубка строки на краю окна усечённого вывода. Такая
строка MUST быть отличима от разобранных записей и MUST NOT отбрасываться
молча.

#### Scenario: Строка не разбирается как JSON

- **WHEN** в потоке агентского шага есть строка, не являющаяся JSON
- **THEN** вывод показывает её как есть, отдельной записью

#### Scenario: Запись незнакомого вида

- **WHEN** в потоке есть запись JSON, вид которой разбор не узнаёт
- **THEN** вывод показывает её строку как есть, а остальные записи разобраны как обычно

#### Scenario: Обрубок строки на краю окна

- **WHEN** вывод отдан усечённым и первая строка окна оборвана с начала
- **THEN** вывод показывает этот обрубок как есть

### Requirement: Вывод командного шага показывается двумя потоками

Дашборд SHALL показывать у командного шага оба его потока — `stdout` и `stderr` — с пометкой, какой из них какой.
Пустой поток MUST называться пустым, а не пропускаться молча: молчащий поток и
отсутствующий файл MUST быть различимы. Потоки MUST NOT изображаться слитыми в
один хронологический поток: отметок времени в файлах нет, и порядок между ними
неизвестен.

#### Scenario: Оба потока командного шага

- **WHEN** пользователь раскрывает вывод командного шага, писавшего и в `stdout`, и в `stderr`
- **THEN** он видит оба потока, и каждый помечен, какой это поток

#### Scenario: Пустой поток

- **WHEN** командный шаг ничего не написал в `stderr`
- **THEN** вывод называет `stderr` пустым

### Requirement: Вывод идущего шага дописывается вживую

Дашборд SHALL дописывать раскрытый вывод шага по мере того, как шаг пишет, без перезагрузки страницы и без повторного раскрытия.
Дописанное SHALL запрашиваться по логическому адресу — прогон, работа, шаг,
попытка и смещение, — а не по пути файла: путь становится известен только
после того, как шаг начал писать, и до этого момента снимок прогона его не
несёт. Демон MUST отдавать только байты после названного смещения и MUST
называть новое смещение. Демон MUST отклонять запрос с идентификатором работы
или шага, не являющимся одним сегментом раскладки, и MUST NOT читать ничего за
пределами каталога запрошенного прогона. Запрошенный вывод SHALL быть
доступен и у шага, которого нет в последнем снимке прогона.

#### Scenario: Вывод идущего шага появляется сам

- **WHEN** пользователь держит раскрытым вывод идущего шага, и шаг пишет новые строки
- **THEN** они появляются на экране без перезагрузки страницы

#### Scenario: Шаг, начавший писать после последнего снимка

- **WHEN** страница прогона открыта до старта шага, и шаг начал писать
- **THEN** его вывод доступен к раскрытию, не дожидаясь завершения шага

#### Scenario: Шаг, ещё ничего не написавший

- **WHEN** пользователь раскрывает вывод шага, который ещё не начал писать
- **THEN** интерфейс сообщает, что вывода пока нет, вместо ошибки
- **AND** это касается и шага, чей файл вывода уже заведён, но пуст

#### Scenario: Идентификатор работы за пределами раскладки

- **WHEN** демон получает запрос вывода с идентификатором работы, не являющимся одним сегментом раскладки
- **THEN** запрос отклоняется ошибкой клиента, ничего не читается

### Requirement: Дописывание прекращается, когда шаг больше не пишет

Дашборд SHALL прекращать запрашивать дописанное, когда шаг больше писать не будет.
Признак того, что дописывать нечего, SHALL приходить от демона, а не выводиться
витриной из статуса шага в снимке: снимок прогона во время исполнения шага не
пересобирается, а у брошенного прогона статус остаётся `running`. Демон MUST
называть вывод завершённым в трёх случаях: запись шага легла в его каталог;
запрошена не последняя из существующих попыток; прогон не жив. Признак MUST
считаться по каталогу запрошенного шага, а не по идентификатору шага в
состоянии прогона: состояние не различает итераций цикла, и запись прошлой
итерации объявила бы идущий шаг завершённым. Пока в запрошенном потоке
остаются непрочитанные байты, признак MUST NOT ставиться: витрина прекращает
опрос по нему, и остаток иначе не дошёл бы до читателя.

#### Scenario: Шаг завершился

- **WHEN** шаг, чей вывод раскрыт, завершается
- **THEN** витрина дочитывает остаток вывода и перестаёт запрашивать дописанное

#### Scenario: Прогон брошен

- **WHEN** раскрыт вывод шага прогона, чей процесс мёртв, а статус остался `running`
- **THEN** витрина не запрашивает дописанное бесконечно

#### Scenario: Шаг работы с циклом на новой итерации

- **WHEN** раскрыт вывод идущего шага той итерации цикла, чей одноимённый шаг прошлой итерации уже записан
- **THEN** вывод дописывается дальше, а не объявляется завершённым

### Requirement: Вывод показывается по попыткам

Дашборд SHALL показывать вывод шага по попыткам, а не склеивать попытки в один поток.
Ответ демона MUST перечислять попытки, чьи файлы вывода есть на диске.
Показываемая по умолчанию попытка MUST быть последней из существующих, и
пользователь MUST иметь возможность перейти к любой другой.

#### Scenario: Шаг с повтором

- **WHEN** шаг исполнялся дважды, и на диске лежат `stdout.log` и `stdout.2.log`
- **THEN** вывод по умолчанию показывает вторую попытку и позволяет перейти к первой

#### Scenario: Шаг с одной попыткой

- **WHEN** шаг исполнялся один раз
- **THEN** вывод показан без выбора попытки

### Requirement: Крупный вывод шага отдаётся с конца

Демон SHALL отдавать вывод крупнее своего потолка с конца, называя смещение, с которого отдан кусок.
Потолок и правило выравнивания по границе символа UTF-8 MUST быть теми же, что
у отдачи файла журнала. Тот же потолок MUST ограничивать и отдачу дописанного:
ответ MUST NOT нести больше потолка за раз, а остаток MUST дочитываться
следующими запросами от названного смещения, без пропуска в выводе. Витрина
MUST показывать, что вывод усечён с начала, пока показанное начинается с
обрезанного места, — а не только в том ответе, где усечение случилось.
Дописывание MUST продолжаться от названного смещения, поэтому идущий шаг,
перешагнувший потолок, MUST продолжать наблюдаться без перезагрузки страницы.

#### Scenario: Вывод крупнее потолка

- **WHEN** пользователь раскрывает вывод шага, чей файл крупнее потолка демона
- **THEN** показан конец вывода с явной пометкой, что начало усечено

#### Scenario: Идущий шаг перешагнул потолок

- **WHEN** вывод идущего шага перерастает потолок при раскрытом окне
- **THEN** дописывание продолжается, и новые строки появляются без перезагрузки
- **AND** пометка об усечённом начале остаётся на экране, пока начало обрезано

#### Scenario: Дописанное сверх потолка

- **WHEN** шаг дописал больше потолка между двумя запросами дописанного
- **THEN** ответ несёт кусок в потолок, а остаток приходит следующим запросом с того же места
