## 3. Адрес вывода шага у демона

- [x] 3.1 `src/ui/stepOutput.ts`: разрешение логического адреса (прогон,
  работа, шаг) в каталог шага через `findStepDir`; перечень попыток по именам
  `stdout*.log` и `stderr*.log`; выбор попытки по умолчанию — наибольшая
  существующая.
- [x] 3.2 Чтение дописанного от смещения: новые байты, новое смещение,
  выравнивание края по границе символа UTF-8 переиспользованием
  `trimPartialUtf8` из `src/ui/file.ts`, а не второй его копией.
- [x] 3.3 Отдача с конца при запросе с нулевого смещения на файле крупнее
  `MAX_FILE_BYTES`; признак усечения и смещение начала куска в ответе. Тот же
  потолок держит и дописывание: остаток сверх него уходит следующим куском с
  того же места, а не выделяется разом.
- [x] 3.4 Смещение больше текущего размера файла (файл усечён или заменён) —
  признак перезапуска чтения в ответе, по образцу `follow()`.
- [x] 3.5 Признак завершённости вывода: `step.json` уже лежит в каталоге шага
  (каталог у каждой итерации цикла свой, поэтому по нему признак и считается),
  либо запрошена не последняя из существующих попыток, либо прогон не жив
  (`isRunAlive`), — и при этом весь написанный вывод уже отдан.
- [x] 3.6 Для командного шага ответ несёт оба потока — `stdout` и `stderr` — со
  своими смещениями; отсутствующий файл отличим от пустого.
- [x] 3.7 Маршрут в `src/ui/server.ts`: только `GET`, проверка сегментов
  идентификаторов через `isSafeSegment`, ответы 400 на негодный адрес.
  Наблюдение остаётся чтением — маршрут ничего не пишет.
