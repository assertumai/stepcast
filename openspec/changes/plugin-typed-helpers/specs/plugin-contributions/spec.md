## ADDED Requirements

### Requirement: Поверхность плагина публикует хелперы объявления вкладов

Подпуть `stepcast/plugin` SHALL экспортировать четыре функции объявления — `definePlugin`, `defineBackend`, `definePredicate` и `defineStepKind`, — принимающие описание плагина либо вклада и возвращающие его же значением соответствующего типа контракта. Каждая из них MUST быть тождеством в рантайме: возвращаемое значение MUST быть тем же объектом, который передан аргументом, и хелпер MUST NOT оборачивать `evaluate`, `execute`, `create` или иное поле, проверять форму вклада, регистрировать его или обращаться к движку. Хелперы MUST оставаться необязательными: вклад, объявленный литералом с прежней аннотацией типа, и плагин, написанный на JavaScript без типов, MUST загружаться и работать как прежде.

#### Scenario: Хелпер возвращает переданный объект

- **WHEN** вклад объявлен `defineStepKind({ … })`
- **THEN** возвращённое значение — тот же объект (`===`), и его поле `execute` — та же функция, что написал автор

#### Scenario: Вклад из хелпера принимается загрузкой

- **WHEN** плагин объявлен `definePlugin` и несёт вклады, объявленные `defineBackend`, `definePredicate` и `defineStepKind`
- **THEN** он проходит проверку формы при загрузке и попадает в реестр наравне с плагином, объявленным литералами

#### Scenario: Прежний способ объявления не сломан

- **WHEN** плагин объявлен объектным литералом без единого хелпера
- **THEN** он загружается, и его вклады ведут себя ровно как прежде

### Requirement: Хелпер типизирует вход вычислителя объявленным типом при единственном приведении

`definePredicate<T>` SHALL принимать вклад, чей `evaluate` объявлен `(value: T, input)`, и возвращать `PredicateContribution`, а `defineStepKind<F>` SHALL принимать вклад, чей `execute` получает вход с полем `fields` типа `F`, и возвращать `StepKindContribution`. Приведение к неспециализированному типу контракта MUST случаться единственный раз — внутри хелпера; код вклада MUST NOT содержать приведения входа вычислителя. Вход исполнителя вида шага `StepKindInput` SHALL нести параметр типа полей с умолчанием `unknown`, так что упоминание имени без параметра MUST значить прежнее. Хук статической проверки `lint` MUST получать значение как `unknown` у обоих хелперов, потому что поле с отложенной подстановкой к моменту статической проверки схемой вклада ещё не проверено.

#### Scenario: Поля вида шага типизированы в исполнителе

- **WHEN** автор пишет `defineStepKind<{ url: string }>({ …, execute(input) { … } })`
- **THEN** `input.fields.url` имеет тип `string` без приведения, а обращение к необъявленному полю — ошибка компиляции

#### Scenario: Значение предиката типизировано в вычислителе

- **WHEN** автор пишет `definePredicate<string>({ …, evaluate(value, input) { … } })`
- **THEN** `value` имеет тип `string`, а вклад, чей `evaluate` объявлен несовместимым с параметром типа, — ошибка компиляции

#### Scenario: Неполный вклад не компилируется

- **WHEN** вклад вида шага объявлен хелпером без обязательного поля `title` либо с `waits: false`
- **THEN** компиляция отказывает

#### Scenario: Статическая проверка получает непроверенное значение

- **WHEN** вклад объявлен `defineStepKind<F>` и несёт `lint`
- **THEN** первый параметр `lint` объявлен `unknown`, и вклад сам решает, что с ним делать

### Requirement: Схема и тип вклада имеют один источник у автора

Документация плагинов SHALL описывать способ получать JSON Schema вклада и TS-тип его значения из одной модели `zod`, объявленной автором: тип — выводом из модели, схема — преобразованием модели при сборке плагина. Через границу вклада MUST по-прежнему ехать только JSON Schema: ни хелпер, ни поле вклада MUST NOT принимать zod-модель. Описанный способ MUST давать самодостаточную схему — без `$ref`, `$id`, `$schema`, `$anchor`, `$dynamicRef`, `$dynamicAnchor`, `$recursiveRef` и `$recursiveAnchor` на любом уровне, — потому что схема вклада вкладывается в публикуемую схему проекта. Репозиторий SHALL нести образец плагина движка, применяющий этот способ, и образец MUST проверяться и компилятором, и рантайм-тестом в составе `npm run check`.

#### Scenario: Схема образца самодостаточна

- **WHEN** тест обходит схемы вкладов образца на любом уровне вложенности
- **THEN** ни одного запрещённого ключа не найдено, и `ajv` компилирует каждую схему

#### Scenario: Схема образца проверяет значение

- **WHEN** значение, отвечающее модели `zod` образца, и значение, ей не отвечающее, проверяются схемой вклада
- **THEN** первое принимается, второе отклоняется с указанием поля

#### Scenario: Тип образца выведен из той же модели

- **WHEN** образец типизируется своим проектом TypeScript
- **THEN** вход вычислителя имеет тип, выведенный из модели, и второго объявления формы в образце нет

#### Scenario: Zod-модель через границу не передаётся

- **WHEN** автор пытается передать zod-модель полем `schema` предиката или `fields` вида шага
- **THEN** ни один хелпер такой формы не принимает, а загрузка отказывает проверкой формы вклада

### Requirement: Встроенные плагины пакета объявлены хелперами

Плагины, поставляемые пакетом и написанные против `stepcast/plugin` — бэкенд `codex` и вид шага `decision`, — SHALL объявляться хелперами `define*`, и приведение входа вычислителя в их коде MUST исчезнуть. Поведение этих плагинов MUST остаться прежним: имена, умолчания, схемы, диагностика и результаты исполнения MUST не измениться. Граница импорта плагинов пакета MUST остаться прежней: из `src/backends/**` и `src/steps/**` допустимы только встроенные модули Node, публичная поверхность и соседний модуль того же каталога.

#### Scenario: Вид шага decision объявлен хелпером

- **WHEN** исполняется шаг вида `decision`
- **THEN** он ведёт себя как прежде, а его исполнитель получает поля типизированными, без приведения в коде вклада

#### Scenario: Бэкенд codex объявлен хелперами

- **WHEN** плагин `stepcast/backends/codex` загружается и собирает адаптер
- **THEN** имя, умолчания записи конфигурации и поведение адаптера — прежние

#### Scenario: Граница импорта не расширена

- **WHEN** проверяется состав импортов модулей `src/backends/**` и `src/steps/**`
- **THEN** ни один из них не импортирует `zod` или иной пакет помимо встроенных модулей Node, публичной поверхности и соседей по каталогу
