## 7. Правки по ревью

- [x] 7.1 Сценарий «Zod-модель через границу не передаётся» покрыт рантайм-тестом
  (`test/plugin-helpers.test.ts`): модель полем `schema` предиката и полем
  `fields` вида шага отклоняется `StepcastPluginSchema`, и отказ называет поле.
  Правки контракта не потребовалось — `z.record` принимает простой объект и
  отклоняет экземпляр класса, каким является всякая zod-модель; проверено
  `safeParse`, а не памятью.
- [x] 7.2 Сценарий «Статическая проверка получает непроверенное значение»
  покрыт отрицательным тестом типов: `lint`, объявленный `(fields: F)` либо
  `(value: T)`, не компилируется у обоих типизированных хелперов.
- [x] 7.3 Вид шага образца объявляет схему `output` из своей zod-модели, и тест
  проверяет ею структурированный выход — той же функцией `validateAgainstSchema`,
  какой его встречает движок.
- [x] 7.4 `test/example-plugin.test.ts` собирает недостающий
  `dist/examples/plugins/typed/index.js` сам (приём `ensureDashboard` из
  `test/ui-server.test.ts`): частичные прогоны `npm test` и `npm run test:only`
  больше не падают отказом о порядке команд.
- [x] 7.5 Образец типизируется частью `npm run typecheck:plugin` — как и сказано
  в его `tsconfig.json`; в `npm run check` этот шаг переставлен после
  `npm run build`, потому что самоссылка `stepcast/plugin` требует собранного
  `dist/src/`.
- [x] 7.6 `docs/plugins.md` больше не называет состав опций преобразователя
  текстом (требование к результату — в документации, состав опций — в тесте
  образца) и не обещает предикату второй проверки схемой: значение с отложенной
  подстановкой раскрывается после единственной проверки, и `evaluate` получает
  его непроверенным по ограничениям схемы. Тем же уточнён комментарий
  приведения в `src/core/plugins/define.ts`.
