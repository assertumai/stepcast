## ADDED Requirements

### Requirement: Режим рабочей директории объявляется и переопределяется

Пайплайн SHALL объявлять режим рабочей директории значением `cwd`, `worktree`
или `copy` с умолчанием `cwd`. Работа MAY переопределить режим для себя. Режим
MUST разрешаться до начала работы, а разрешённый режим и путь рабочей
директории MUST записываться в манифест и состояние прогона.

#### Scenario: Умолчание

- **WHEN** пайплайн не объявляет режим рабочей директории
- **THEN** работы исполняются в каталоге запуска

#### Scenario: Переопределение работой

- **WHEN** пайплайн объявляет `cwd`, а работа объявляет `worktree`
- **THEN** эта работа исполняется в отдельном git worktree, а остальные — в каталоге запуска

#### Scenario: Режим виден в состоянии

- **WHEN** прогон начался
- **THEN** состояние прогона содержит режим и путь рабочей директории каждой работы

### Requirement: Режим worktree изолирует работу от текущего дерева

В режиме `worktree` система SHALL создавать на каждую работу отдельный git
worktree, ответвлённый от текущей позиции `HEAD`. Незакоммиченные изменения
рабочего дерева проекта MUST NOT попадать в него. Работы MUST NOT видеть
изменения друг друга через файловую систему. Режим MUST отклоняться до начала
прогона, если проект не является репозиторием git, — с указанием причины и
предложением режима `copy`.

#### Scenario: Ответвление от HEAD

- **WHEN** работа исполняется в режиме `worktree`
- **THEN** её рабочая директория содержит состояние проекта на текущей позиции `HEAD`

#### Scenario: Незакоммиченные изменения не переносятся

- **WHEN** в дереве проекта есть незакоммиченные изменения, а работа исполняется в режиме `worktree`
- **THEN** в её рабочей директории этих изменений нет

#### Scenario: Изоляция работ друг от друга

- **WHEN** две работы исполняются в режиме `worktree` и первая изменила файл
- **THEN** рабочая директория второй этого изменения не содержит

#### Scenario: Проект не под git

- **WHEN** объявлен режим `worktree`, а проект не является репозиторием git
- **THEN** прогон завершается ошибкой конфигурации до запуска работ
- **AND** сообщение называет причину и предлагает режим `copy`

### Requirement: Режим copy работает вне git и с незакоммиченным

В режиме `copy` система SHALL копировать рабочее дерево проекта в директорию
работы, пропуская пути, подпадающие под правила игнорирования, и служебный
каталог git. Копия MUST включать незакоммиченные изменения. Расположение копий
по умолчанию MUST находиться внутри директории прогона и MAY переопределяться
объявленным путём.

#### Scenario: Незакоммиченные изменения попадают в копию

- **WHEN** в дереве проекта есть незакоммиченные изменения, а работа исполняется в режиме `copy`
- **THEN** её рабочая директория содержит эти изменения

#### Scenario: Игнорируемые пути не копируются

- **WHEN** дерево содержит каталог, подпадающий под правила игнорирования
- **THEN** в копии его нет

#### Scenario: Копия вне git

- **WHEN** проект не является репозиторием git, а объявлен режим `copy`
- **THEN** прогон исполняется, а состояние дерева фиксируется хеш-манифестом

#### Scenario: Явный путь размещения копий

- **WHEN** объявлен путь размещения рабочих копий
- **THEN** копии создаются по нему, а не внутри директории прогона

### Requirement: Пригодность режима проверяется до первой работы

Возможность подготовить рабочую директорию в объявленном режиме SHALL
проверяться один раз до запуска первой работы: наличие репозитория git для
режима `worktree`, доступность на запись места размещения для режима `copy`.
Непригодность режима MUST быть ошибкой конфигурации до исполнения шагов, а не
отказом работы посреди прогона.

#### Scenario: Непригодность обнаружена заранее

- **WHEN** объявленный режим невозможно подготовить в текущем окружении
- **THEN** прогон завершается ошибкой конфигурации до запуска первой работы
- **AND** ни один шаг не исполнен

#### Scenario: Проверка выполняется однократно

- **WHEN** пайплайн содержит несколько работ в изолированном режиме
- **THEN** пригодность режима проверена до первой из них, а не при подготовке каждой

### Requirement: Журнал прогона отделён от рабочей директории

Директория прогона SHALL располагаться вне рабочей директории работы при любом
режиме. Шаги MUST NOT видеть журнал прогона как часть своего рабочего дерева, и
запись журнала MUST NOT изменять `tree_id` работы.

#### Scenario: Журнал не попадает в дерево

- **WHEN** работа исполняется в режиме `copy` с копией внутри директории прогона
- **THEN** файлы журнала прогона не входят в фиксируемое состояние рабочего дерева

### Requirement: Изолированные деревья сохраняются после прогона

Рабочие деревья режимов `worktree` и `copy` SHALL сохраняться после завершения
прогона. Их пути MUST записываться в состояние прогона. По завершении прогона в
изолированном режиме система MUST сообщать путь рабочего дерева и команду
возврата результата.

#### Scenario: Дерево доступно после прогона

- **WHEN** прогон в изолированном режиме завершился
- **THEN** рабочая директория каждой работы существует, а её путь есть в состоянии прогона

#### Scenario: Подсказка о возврате результата

- **WHEN** прогон в изолированном режиме завершился
- **THEN** вывод содержит путь рабочего дерева и команду наложения результата на текущее дерево

### Requirement: Команда apply возвращает результат в текущее дерево

Команда `stepcast apply <run-id>` SHALL накладывать изменения, произведённые
прогоном, на текущее рабочее дерево проекта. Ключ `--job` MUST ограничивать
наложение одной работой. Изменение MUST вычисляться из якорей дерева, а не из
состояния каталога на момент вызова. При конфликте наложения команда MUST
завершаться ошибкой, не оставляя частично наложенных изменений, и называть
конфликтующие пути.

#### Scenario: Наложение результата прогона

- **WHEN** пользователь вызывает наложение для завершившегося прогона в режиме `worktree`
- **THEN** изменения прогона появляются в текущем рабочем дереве проекта

#### Scenario: Наложение одной работы

- **WHEN** вызов ограничен одной работой
- **THEN** накладываются только изменения этой работы

#### Scenario: Конфликт

- **WHEN** текущее дерево изменено так, что наложение невозможно
- **THEN** команда завершается ненулевым кодом и перечисляет конфликтующие пути
- **AND** текущее дерево остаётся неизменным

#### Scenario: Наложение в режиме cwd

- **WHEN** прогон исполнялся в режиме `cwd`
- **THEN** команда сообщает, что результат уже на месте, и ничего не изменяет
