## ADDED Requirements

### Requirement: Практика спецификации проекта объявляется в конфигурации

Конфигурация SHALL принимать в секции `project` группу `spec` с ключами `dir`, `rules` и `tool` — объявлением того, где живут документы изменения, по каким правилам они пишутся и каким инструментом заводятся.

`dir` — каталог документов изменения; документы изменения `<слаг>` лежат в
`<dir>/<слаг>/`. `rules` — путь к файлу правил репозитория, который читает
работа, заводящая описание изменения. `tool` — имя команды инструмента
спецификации; значение открывает право на её запуск и не несёт аргументов.

Каждый ключ MUST быть необязательным сам по себе: слои конфигурации сливаются
по листьям, и объявить можно часть группы. Встроенных умолчаний у ключей MUST
NOT быть — путь, подставленный за автора, указывал бы в чужом репозитории на
несуществующий каталог.

Значения `dir` и `rules` MUST быть относительными путями от корня
репозитория: пустая строка, строка из пробельных символов, абсолютный путь и
путь, выходящий за корень сегментом `..`, отклоняются разбором конфигурации.
Причина в потребителе: `dir` раскрывается в границу правок `<dir>/**`, и
пустое значение превратило бы её в разрешение на всё дерево, а `..` вывело бы
границу за пределы проверяемого дерева. Значение `tool` MUST быть непустым по
той же причине, по какой непуста команда проверки: право, собранное из пустого
имени, либо расширяет разрешённое молча, либо отказывает без причины.

Требование непустоты MUST быть выражено и в публикуемой JSON Schema, а не
только в модели: обрезку пробелов схема не переносит, и редактор принимал бы
значение, которое движок отвергает.

#### Scenario: Группа объявлена в проектном конфиге

- **WHEN** `.stepcast/config.yml` содержит `project: { spec: { dir: "openspec/changes", rules: ".stepcast/prompts/spec-rules.md", tool: "openspec" } }`
- **THEN** действующие значения `project.spec.dir`, `project.spec.rules` и `project.spec.tool` равны объявленным
- **AND** отчёт `stepcast config` называет источником этот файл

#### Scenario: Часть группы

- **WHEN** конфигурация объявляет только `project.spec.dir`
- **THEN** конфигурация разрешается без ошибки, а `project.spec.rules` и `project.spec.tool` отсутствуют

#### Scenario: Группа не объявлена

- **WHEN** ни один слой конфигурации не задаёт `project.spec`
- **THEN** конфигурация разрешается без ошибки, а значения группы отсутствуют

#### Scenario: Пустой каталог документов

- **WHEN** конфигурация содержит `project: { spec: { dir: "   " } }`
- **THEN** чтение конфигурации завершается ошибкой, называющей файл и ключ

#### Scenario: Абсолютный путь

- **WHEN** конфигурация содержит `project: { spec: { dir: "/tmp/changes" } }`
- **THEN** чтение конфигурации завершается ошибкой, называющей ключ и требование относительного пути

#### Scenario: Выход за корень репозитория

- **WHEN** конфигурация содержит `project: { spec: { rules: "../rules.md" } }`
- **THEN** чтение конфигурации завершается ошибкой, называющей ключ

#### Scenario: Неизвестный ключ группы

- **WHEN** конфигурация содержит `project: { spec: { folder: "openspec/changes" } }`
- **THEN** чтение конфигурации завершается ошибкой о неизвестном ключе

### Requirement: Проектный-только запрет действует на вложенные ключи секции project

Запрет объявлять секцию `project` в глобальной конфигурации SHALL действовать на все ключи под ней, а не только на ключи первого уровня.

Шаблон ключей MUST допускать хвостовую форму `**` — «названный ключ и всё под
ним». Перечисление уровней вместо неё (`project.*`, `project.*.*`) MUST NOT
использоваться: сопоставление требует равного числа сегментов, и каждое
углубление секции открывало бы дыру, о которой ничто не сообщает.

Хвостовая форма MUST быть единственной допустимой формой `**` в шаблоне
ключей: в середине пути у неё нет потребителя, а сопоставление с откатом ради
неё избыточно.

#### Scenario: Вложенный ключ в глобальном конфиге

- **WHEN** `~/.stepcast/config.yml` содержит `project: { spec: { dir: "openspec/changes" } }`
- **THEN** любая команда, читающая конфигурацию, завершается ошибкой с указанием ключа `project.spec.dir`
- **AND** подсказка называет `.stepcast/config.yml` как верное место объявления

#### Scenario: Ключ первого уровня по-прежнему отклоняется

- **WHEN** `~/.stepcast/config.yml` содержит `project: { check: "npm run check" }`
- **THEN** чтение конфигурации завершается ошибкой с указанием ключа `project.check`

#### Scenario: Проектный конфиг не ограничен запретом

- **WHEN** `.stepcast/config.yml` содержит `project: { spec: { dir: "docs/changes" } }`, а глобальный конфиг секции `project` не содержит
- **THEN** конфигурация разрешается без ошибки

#### Scenario: Соседняя секция не задета шаблоном

- **WHEN** `~/.stepcast/config.yml` содержит `defaults: { model: "sonnet" }`
- **THEN** конфигурация разрешается без ошибки
