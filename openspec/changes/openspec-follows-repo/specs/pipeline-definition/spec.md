## MODIFIED Requirements

### Requirement: Пути с подстановками не проверяются статически

Проверка существования файла SHALL применяться к путям без подстановок и к путям, все подстановки которых принадлежат пространству `project`.

Пути с прочими подстановками — `inputs`, `params`, `jobs`, `run`, `env` — и
пути, производимые работами выше по графу, MUST пропускаться при статической
проверке: ими адресуют в том числе то, что прогон ещё только произведёт.
Пространство `project` объявляет обратное — то, что в репозитории есть до
прогона (команда проверки, каталог документов изменения, файл правил их
написания), и пропуск такого пути прятал бы опечатку в самом объявлении.

Пути-глобы MUST пропускаться так же, независимо от происхождения. Глобом SHALL
считаться путь, содержащий `*`, `?` либо `[`: глоб запрашивает совпадения, и их
отсутствие ошибкой не является.

#### Scenario: Путь с подстановкой

- **WHEN** `context` содержит `changes/${inputs.change}/tasks.md`
- **THEN** `stepcast lint` не проверяет существование файла и не сообщает об ошибке

#### Scenario: Путь из объявления проекта

- **WHEN** `context` содержит `${project.spec.rules}`, а объявленного этим ключом файла в дереве нет
- **THEN** `stepcast lint` сообщает об ошибке, называя раскрытый путь

#### Scenario: Глоб без совпадений

- **WHEN** `context` содержит `src/**/*.kt`, а совпадений нет
- **THEN** `stepcast lint` не сообщает об ошибке

## ADDED Requirements

### Requirement: Запись контекста может требовать совпадений

Запись контекста, объявленная формой объекта, SHALL принимать ключ `required`: при `required: true` запись, не давшая ни одного файла, MUST ронять шаг до запуска бэкенда сообщением, называющим объявленный путь.

Умолчанием MUST оставаться прежнее поведение: отсутствие совпадений у глоба —
не ошибка. Требование MUST проверяться до отсева по `context.deny` и
`context_exclude`: отсев — осознанное решение автора, о котором движок и так
сообщает событием, а речь здесь о записи, не нашедшей вообще ничего.

Хотя бы одно совпадение требование MUST удовлетворять: запись адресует набор
файлов, и неполнота набора — не то, что она проверяет.

Статически `required` не проверяется по той же причине, по какой не проверяется
глоб: на этапе линта каталог, который наполняет работа выше по графу, ещё и не
обязан существовать.

#### Scenario: Глоб без совпадений при требовании

- **WHEN** запись контекста объявлена как `{ path: "changes/demo/**/*.md", required: true }`, а совпадений нет
- **THEN** шаг завершается отказом, называющим путь записи, и бэкенд не запускается

#### Scenario: Неполный набор требование удовлетворяет

- **WHEN** та же запись находит один файл из нескольких ожидаемых
- **THEN** контекст собирается из найденного, и отказа нет

#### Scenario: Запись без требования

- **WHEN** глоб без `required` не даёт совпадений
- **THEN** контекст собирается без этой записи, и отказа нет

### Requirement: Пространство project содержит группу spec

Пространство подстановки `project` SHALL содержать, помимо имени `check`, составные имена `spec.dir`, `spec.rules` и `spec.tool` — действующие значения объявления практики спецификации репозитория.

Значения SHALL раскрываться при разборе документа наравне с `check`: они
известны до запуска прогона, и раскрытый пайплайн MUST содержать на их месте
строку, а не подстановку. Доступны они там же, где `${project.check}`, — в
документе пайплайна, файлах работ и файлах промптов, включая пути контекста,
списки `changed_only` и записи `permissions.allow`.

Документ пайплайна SHALL принимать группу `spec` внутри верхнего ключа
`project` и перекрывать ею конфигурацию — тем же порядком слоёв, каким
перекрывает `project.check`. Требования к значениям MUST быть теми же, что в
конфигурации: относительный путь у `dir` и `rules`, непустая строка у `tool`.

Обращение к необъявленному имени группы MUST быть отказом разбора, а не пустой
строкой; сообщение MUST называть оба места объявления — документ пайплайна и
`.stepcast/config.yml`. Обращение к имени вне состава пространства MUST быть
отказом, перечисляющим доступные имена, включая составные. Наличие ключей
группы MUST NOT требоваться само по себе: документ, не ссылающийся на них,
разбирается и исполняется без объявления.

#### Scenario: Каталог документов в пути контекста

- **WHEN** файл работы объявляет контекст `${project.spec.dir}/${params.change}/**/*.md`, а объявление задаёт `dir: openspec/changes`
- **THEN** работа получает контекстом документы каталога `openspec/changes/<значение params.change>/`

#### Scenario: Каталог документов в границах правок

- **WHEN** файл работы объявляет `changed_only: ["${project.spec.dir}/**"]`
- **THEN** предикат проверяет правки против объявленного каталога

#### Scenario: Инструмент в списке прав

- **WHEN** шаг объявляет право `Bash(${project.spec.tool} *)`, а объявление задаёт `tool: openspec`
- **THEN** шаг уходит в бэкенд с правом `Bash(openspec *)`

#### Scenario: Файл правил в тексте промпта

- **WHEN** файл промпта содержит `${project.spec.rules}`
- **THEN** агент получает текст с объявленным путём на этом месте

#### Scenario: Раскрытое значение попадает в снимок пайплайна

- **WHEN** пайплайн со ссылками на группу раскрыт
- **THEN** `pipeline.lock.yml` содержит на этих местах объявленные значения, а не подстановки

#### Scenario: Пайплайн перекрывает конфигурацию

- **WHEN** `.stepcast/config.yml` объявляет `project.spec.dir: "openspec/changes"`, а пайплайн — `project: { spec: { dir: "docs/changes" } }`
- **THEN** `${project.spec.dir}` во всех документах прогона раскрывается в `docs/changes`

#### Scenario: Ссылка без объявления

- **WHEN** документ содержит `${project.spec.dir}`, а ключ не объявлен ни пайплайном, ни конфигурацией
- **THEN** `stepcast lint` завершается ошибкой, называющей оба места объявления
- **AND** `stepcast run` не начинает прогон

#### Scenario: Имя вне состава пространства

- **WHEN** документ содержит `${project.spec.folder}`
- **THEN** разбор завершается ошибкой с перечнем доступных имён пространства

#### Scenario: Документ без ссылки на группу

- **WHEN** ни пайплайн, ни его работы, ни промпты не ссылаются на `${project.spec.*}`, а группа не объявлена
- **THEN** пайплайн разбирается и исполняется без ошибки
