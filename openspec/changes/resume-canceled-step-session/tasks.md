## 2. Решение плана

- [x] 2.1 `StepDecision` в `src/core/run/resumePlan.ts` пополняется видом
  `continue` с записью оборванного шага и идентификатором сессии.
- [x] 2.2 `invalidationReason` для шага со статусом `canceled` досчитывает
  остальные причины (каскад, `--from`, ключ, входы, тронутый результат,
  невосстановимый выход) вместо возврата на первой проверке.
- [x] 2.3 Условие назначения продолжения: последняя запись попытки —
  `canceled`, есть `session`, бэкенд шага объявляет `capabilities.sessions`,
  работа объявляет `session: shared` и не объявляет `until`, других причин
  невалидности нет.
- [x] 2.4 `coarsenSharedSessions` уступает продолжению: шаги той же сессии до
  продолжаемого остаются переиспользуемыми; если хотя бы один из них
  переиспользовать нельзя — продолжение снимается и работа огрубляется целиком.
- [x] 2.5 `describePlan` называет продолжение отдельной формулировкой с
  прогоном-источником; `stepcast status --explain` показывает то же.

## 3. Каталог продолжаемой работы

- [x] 3.4 `restoreForResume` исключает продолжаемую работу из восстановления.

## 4. Продолжение сессии

- [x] 4.1 `createSessionRegistry` принимает засев: псевдоним → идентификатор
  уже начатой сессии.
- [x] 4.2 `runPipeline` засевает реестр по решениям `continue` плана и теми же
  ключами отмечает `pipelineContextSent` и `jobContextSent`.

- [x] 4.4 Отказ продолжения: попытка без записи `init` от бэкенда и с ненулевым

## 6. Учёт расхода

- [x] 6.1 Запись оборванной попытки переносится в запись продолжаемого шага с
  пометкой `carried_from`; запись шага получает `continued_from`. Обе — в схеме
  журнала.
- [x] 6.2 `UsageAccumulator` принимает перенесённый расход так, чтобы сводка
  складывала его с расходом продолженной попытки, а потолки прогона, работы и
  шага его не считали.
- [x] 6.3 Счёт попыток продолженного исполнения начинается с первой:
  перенесённая запись объявленных `attempts` не расходует.

## 7. Уборка

- [x] 7.1 `stepcast gc` и `stepcast down` не удаляют каталог, названный записью
  более позднего прогона как перенятый, и не снимают его учётную запись
  рабочего дерева; отчёт называет сохранённый каталог и прогон.

## 8. Правки по ревью

- [x] 8.1 Уборка перенявшего прогона снимает перенятый каталог: путь сверяется с
  директорией того прогона, в которой каталог лежит, а владельцем считается
  последний перенявший из уцелевших — иначе после уборки обоих прогонов
  каталог и его учётная запись оставались бы навсегда.
- [x] 8.2 Удаление прогона с сохранённым каталогом вырождается в уборку: минимум
  журнала остаётся, и прогон не превращается в нечитаемый каталог.
- [x] 8.3 Дерево продолжаемой работы не откатывается и в режиме `cwd`: пути,
  произведённые её переиспользованным префиксом, изъяты из восстановления.
- [x] 8.4 Проверка каталога перед перениманием снимает якорь так же, как
  исполнитель, — с репозиторием прогона и объявленным составом вложенных
  репозиториев; иначе режим `copy` и составной якорь отказывали молча.
- [x] 8.5 Точка `--from` отменяет продолжение, только когда названа на
  продолжаемом шаге или выше, — как объявлено спекой.
- [x] 8.6 Огрубление общей сессии не подменяет настоящую причину невалидности
  шага общей сессией.
- [x] 8.7 Запись о прерывании достаётся только попытке, которая действительно
  продолжает диалог, а не каждой попытке продолжаемого шага.
- [x] 8.8 Отмена завершает шаг, не заводя следующей попытки, — объявлено спекой
  и закреплено проверкой.
- [x] 8.9 Проверки на перенесённую попытку (`carried_from`), на `session:
  per_step` и на следствие переноса в итогах работы и прогона.
