## ADDED Requirements

### Requirement: Витрина показывает расход идущего прогона

Витрина SHALL показывать накопленный расход идущего прогона на всех трёх уровнях — прогона целиком, каждой его работы и каждого её шага, — а не только после завершения прогона.

Величины MUST браться из уже записанных состояния и сводки расхода: новых точек
HTTP-API и нового потока для этого MUST NOT заводиться, а витрина MUST NOT
обходить каталоги прогона сама.

Разрез итога прогона по видам токенов MUST показываться и на идущем прогоне,
раз сводка его уже несёт.

Накопленный расход MUST NOT подписываться как итоговый: подпись, обещающая
величину «когда прогон запишет сводку», MUST заменяться на верную для обоих
случаев.

Пустая ячейка MUST оставаться только там, где величины действительно нет:
работа, которая ещё не исполнялась, и измерение, не сообщённое бэкендом, MUST
показываться признаком отсутствия, а не нулём.

#### Scenario: Расход работы и шага до конца прогона

- **WHEN** пользователь раскрывает прогон, у которого первая работа завершилась, а прогон продолжается
- **THEN** у этой работы и у каждого её шага показан расход, а не прочерк

#### Scenario: Разрез итога идущего прогона

- **WHEN** пользователь раскрывает разрез токенов у идущего прогона в обзоре
- **THEN** разрез по видам токенов показан, а подпись не обещает его появления в будущем

#### Scenario: Работа, которая ещё не исполнялась

- **WHEN** работа прогона ещё не начиналась
- **THEN** её расход показан признаком отсутствия, а не нулём

#### Scenario: Накопленное не выдаётся за итог

- **WHEN** витрина показывает расход прогона, который ещё идёт
- **THEN** из показанного видно, что величина накоплена на текущий момент, а не подведена
