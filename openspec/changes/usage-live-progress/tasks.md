## 2. Сборка сводки: признак и линейный обход

- [x] 2.1 `src/core/budget/accumulator.ts`: `report()` принимает признак незаконченности и кладёт `partial: true` в сводку, когда он поднят; без него поля в сводке нет вовсе.
- [x] 2.2 Там же: разложить `this.steps` (вместе с синтезированными `@carried`) по работам одним проходом перед циклом по работам — вместо обхода всего списка внутри каждой итерации. Разбор ключа `<работа>/<шаг>#<попытка>[@sealN]` и схлопывание переисполнений остаются прежними.
- [x] 2.3 Тест на порядок роста: две формы одного объёма записей — двадцать работ и две тысячи, — время сборки сводки на широкой форме сравнивается с временем на узкой, а не с абсолютным потолком в миллисекундах. Сторож проверен на восстановленной квадратичной реализации: на ней он краснеет (1021мс против потолка 272мс), на линейной зелен с двадцатикратным запасом.
- [x] 2.4 Тест: сводка с поднятым признаком несёт `partial: true`, без него — не несёт поля; величины в обоих случаях одни и те же.

- [x] 3.2 Признак незаконченности поднимается везде, кроме финальной записи: терминальный статус прогона — единственный повод сводку подвести.
- [x] 3.3 Снять отдельный `journal.writeUsage(...)` после `schedule()`: финальную запись делает тот же `writeStatus(finalStatus)`.
- [x] 3.4 Убедиться, что сводка пишется по всем пяти поводам — старт, `refreshStatus` после шага, `onSettled`, `beginWait` на входе и выходе, финал — и что новых вызовов записи не заведено ни одного.
