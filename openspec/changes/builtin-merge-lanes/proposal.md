## Why

Сведение дорожек — самая необратимая часть петли, и она целиком лежит скриптом
одного репозитория. `scripts/merge-lanes.mjs` накладывает дорожку на дерево
проекта, гоняет проверку, коммитит, а при красной проверке стирает дерево
`git reset --hard HEAD` и `git clean -fd`; `scripts/finalize.mjs` закрывает
исходы взятых пунктов. Ни один из двух не поставляется пакетом
(`files: ["dist", "schema"]`), ни один не покрыт проверками движка, и перенести
петлю в другой репозиторий можно только копированием обоих — с молчаливым
расхождением копий при первой же правке.

Цена непокрытости уже заплачена. `merge-lanes.mjs` искал работу проверки
склейкой строк — сначала `job.id === 'verify'`, без суффикса дорожки, — не
находил её ни для одной дорожки и объявлял обе непроверенными; собственный тест
скрипта был зелёным, потому что его мок писал в `status.json` работу с тем самым
выдуманным именем. Прогон `6995c4` из-за этого молча выбросил дорожку `b`:
зелёная реализация не влилась, пункт был помечен `failed`, и работу спасали
руками. Пока сведение остаётся скриптом, тест на настоящем прогоне ему написать
не на чем: `apply --lane`, журнал и очередь — сущности движка, а скрипт видит их
через `spawnSync` и фальшивый бинарь.

Пункт второй в группе `portable-loop` и опирается на первый: очередь и её
команда уже переехали в движок (`portable-backlog-format`), сведение — вторая
половина того же переезда.

## What Changes

- **`stepcast merge-lanes` — команда бинаря.** `stepcast merge-lanes [<run-id>]
  --lanes a,b --check "<команда>" [--file backlog.md]` сводит названные дорожки
  прогона в дерево запуска по очереди: накладывает, проверяет, коммитит зелёную,
  откатывает красную. Прогон — позиционным аргументом либо из `STEPCAST_RUN_ID`;
  «последний прогон» по умолчанию не берётся — угадывать прогон для операции,
  которая коммитит и стирает дерево, недопустимо.
- **Годность дорожки к сведению считается по её работам, а не по имени одной
  из них.** Дорожка сводится, если каждая работа с этой меткой в `status.json`
  завершилась `success`; дорожка, все работы которой пропущены (незаполненный
  слот), пропускается без отказа. Склейки `verify-${lane}` не остаётся нигде:
  именно она молча выбрасывала проверенную дорожку.
- **Команда проверки приходит ключом, а не зашита литералом.** `--check`
  обязателен и исполняется оболочкой в дереве запуска тем же исполнителем
  процессов, что и `run`-шаг. `npm run check` перестаёт быть строкой в коде и
  становится значением в файле работы `merge.yml` — откуда следующий пункт
  группы (`configurable-check-command`) унесёт его в настройку проекта.
- **Чистое дерево — предусловие команды, а не соглашение вызывающего.**
  Откат красной проверки стирает неотслеживаемое (`clean -fd`) и
  незакоммиченное (`reset --hard`); движок, дающий такую операцию любому
  вызывающему, обязан сам отказаться выполнять её на дереве с
  незакоммиченными или неотслеживаемыми изменениями. Сегодня чистоту проверяет
  работа `slots` — далеко от места, где стирают.
- **Исход дорожки проставляет сама команда сведения.** Сведённая дорожка
  получает `done` в очереди до коммита (как и сейчас — одним событием, которое
  снимает `git revert`), несведённая — `failed` с причиной, называющей, что
  именно случилось: работы дорожки не успешны, конфликт наложения, красная
  проверка, остановка на более ранней дорожке. Промежуточные файлы
  `merge-<дорожка>.json` в каталоге прогона исчезают вместе со скриптом,
  который их читал.
- **`stepcast backlog settle --run-dir <каталог>` — закрытие захода.** То, что
  делал `finalize.mjs`: каждому пункту, взятому в этот прогон (файлы
  `item-<дорожка>.json`, которые пишет `backlog pick --lanes --run-dir`) и
  оставшемуся без исхода, проставляется `failed` с причиной «заход до сведения
  дорожки не дошёл». Пункт с уже проставленным исходом не трогается. Команде
  нужен каталог прогона и файл очереди — ни журнала, ни конфигурации проекта,
  как и остальным подкомандам `backlog`.
- **BREAKING для дорожки, не изменившей дерево.** Скрипт в этом случае
  коммитил одну лишь правку очереди и объявлял пункт `done`; команда считает
  такую дорожку несведённой и помечает пункт `failed` с причиной «дорожка не
  изменила дерево» — зелёная проверка на пустом вкладе не означает улучшения.
  Остальные дорожки перечня при этом продолжают сводиться.
- **`scripts/merge-lanes.mjs` и `scripts/finalize.mjs` удалены**, а
  `test/merge-lanes.test.ts` и `test/finalize.test.ts` переписаны с запуска
  скриптов фальшивым бинарём на настоящие прогоны движка: пайплайн с двумя
  дорожками в временном репозитории, настоящие `apply --lane` и очередь. Ни
  одна заготовка не подставляет имя работы, которого в настоящем прогоне не
  бывает.
- **Работы петли зовут команды.** `.stepcast/jobs/merge.yml` — `merge-lanes`
  через `$STEPCAST_BIN` с `--check "npm run check"`,
  `.stepcast/jobs/finalize.yml` — `backlog settle` тем же путём.
- **Документация.** `docs/run-layout.md` (перечень CLI и раздел сведения
  дорожек), `docs/backlog.md` (`settle`), `docs/pipeline-format.md` (третья
  дорожка больше не требует правки скрипта).

## Capabilities

### New Capabilities

- `lane-merge`: сведение дорожек прогона в дерево запуска встроенной командой —
  отбор годных дорожек по исходам их работ, наложение, проверка объявленной
  командой, откат при красной проверке, коммит и проставление исхода пункта
  очереди.

### Modified Capabilities

- `backlog-queue`: добавляется подкоманда `settle` — закрытие исходов пунктов,
  взятых в прогон, по файлам дорожек в каталоге прогона. Базовая спека
  возможности пока живёт в неархивированном изменении
  `portable-backlog-format`, поэтому дельта здесь — `## ADDED Requirements`:
  требований этой возможности изменение не переписывает, а добавляет к ним
  одно.

## Impact

- `src/core/lanes/` — новый модуль сведения: отбор годных дорожек по
  `status.json`, порядок обхода, наложение через `applyRun`, проверка,
  откат, коммит, проставление исхода.
- `src/cli/commands/merge-lanes.ts` и `src/cli/main.ts` — регистрация команды и
  её ключей.
- `src/cli/commands/backlog.ts` — подкоманда `settle`; комментарий у
  `REASON_LIMIT` перестаёт ссылаться на исчезнувший `merge-<дорожка>.json`.
- `src/core/backlog/` — чтение файлов `item-<дорожка>.json` каталога прогона,
  общее для `settle` и сведения.
- `scripts/merge-lanes.mjs`, `scripts/finalize.mjs` — удаляются;
  `scripts/status.mjs` — комментарий ссылается на удалённый файл.
- `.stepcast/jobs/merge.yml`, `.stepcast/jobs/finalize.yml` — вызов команд
  через `$STEPCAST_BIN`; `.stepcast/jobs/implement.yml` — комментарий границ
  правок называет удалённый скрипт примером.
- `test/merge-lanes.test.ts`, `test/finalize.test.ts` — переписаны на прогоны
  движка; `test/cli-backlog.test.ts` — проверки `settle`.
- `docs/run-layout.md`, `docs/backlog.md`, `docs/pipeline-format.md`,
  `openspec/changes/builtin-merge-lanes/status.md` (фрагмент состояния).
