## 3. Остановка и отмена при идущих работах

- [x] 3.1 `fail_fast`: отказ прекращает запуск новых работ основного графа, но
      не трогает идущие; их исходы записываются на общих основаниях. То же для
      неустранимого отказа бэкенда (`isUnrunnable`)
- [x] 3.2 Отмена по сигналу: новые работы не запускаются, идущие получают
      действующий порядок отмены шага, планировщик дожидается их завершения и
      только затем возвращает результат
- [x] 3.3 Убедиться, что работы `needs: all` и `on: failure` исполняются после
      завершения всех идущих работ основного графа, а не начинают вперемешку с
      ними
- [x] 3.4 Дополнить `test/scheduler.test.ts` случаями из спецификации:
      одновременность двух готовых работ, предел числа идущих, занятие
      освободившегося места, отказ при двух идущих, отмена при двух идущих,
      отсутствие запусков после отмены
