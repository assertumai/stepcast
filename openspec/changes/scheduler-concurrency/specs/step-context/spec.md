## MODIFIED Requirements

### Requirement: Выходы предшественников подмешиваются автоматически

Перед контекстом пайплайна система SHALL добавлять блок с опубликованными выходами работ, расположенных выше по графу, включая транзитивные. Состав блока MUST определяться графом зависимостей работы, а не тем, какие работы успели завершиться к моменту сборки: выход работы, идущей или завершившейся рядом, но не находящейся выше по графу, MUST NOT попадать в блок. Блок MUST содержать идентификатор работы, путь к её выходу и, для выходов меньше порога вставки, их содержимое. Управление составом блока MUST выполняться ключом `context_upstream` со значениями `all`, `none` или списком идентификаторов работ.

#### Scenario: Выход предыдущей работы виден

- **WHEN** работа `implement` зависит от `plan`, опубликовавшей выход
- **THEN** агентские шаги `implement` получают блок с путём к выходу `plan`

#### Scenario: Отказ от блока

- **WHEN** работа объявляет `context_upstream: none`
- **THEN** блок выходов предшественников не формируется

#### Scenario: Выборочные предшественники

- **WHEN** работа объявляет `context_upstream: [plan]`
- **THEN** блок содержит только выход `plan`, даже если выше по графу есть другие работы

#### Scenario: Работа вне графа предшественников в блок не входит

- **WHEN** при `concurrency: 2` работа `review` зависит только от `plan`, а параллельная ей работа `docs` успела опубликовать выход раньше начала `review`
- **THEN** блок `review` содержит выход `plan` и не содержит выхода `docs`

#### Scenario: Состав блока не зависит от длительности соседей

- **WHEN** один и тот же пайплайн исполнен дважды при `concurrency: 2`, и во второй раз параллельная работа завершилась раньше
- **THEN** блок выходов предшественников каждой работы в обоих прогонах одинаков
