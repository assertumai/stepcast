## MODIFIED Requirements

### Requirement: Суммарный размер контекста ограничен

Собранный контекст шага SHALL проверяться на соответствие пределу
`context.max_tokens` до отправки бэкенду. Размер MUST оцениваться локально, без
обращения к модели, и трактоваться как оценка. Записи, которые формирует сам
движок, MUST приходить в сборку уже уложенными в собственный объявленный
предел. При превышении предела система MUST понижать записи в режиме `auto` с
вставки содержимого на передачу путём, начиная с самой крупной, пока оценка не
уложится в предел. Записи с явным `mode: inline` и записи `text` MUST NOT
понижаться. Если после всех понижений оценка остаётся выше предела, шаг MUST
завершаться отказом до отправки.

#### Scenario: Неудачный глоб собрал слишком много

- **WHEN** запись контекста в режиме `auto` раскрылась в набор файлов, превышающий предел
- **THEN** самые крупные записи передаются путём вместо содержимого
- **AND** в журнал событий пишется запись о каждом понижении

#### Scenario: Явная вставка не понижается

- **WHEN** предел превышен, а часть записей объявлена с `mode: inline`
- **THEN** эти записи остаются вставленными содержимым, а понижаются только записи в режиме `auto`

#### Scenario: Предел недостижим понижениями

- **WHEN** после понижения всех записей `auto` оценка всё ещё выше предела
- **THEN** шаг завершается отказом до запуска бэкенда
- **AND** сообщение называет оценку, предел и три самые крупные записи

#### Scenario: Предел контекста меньше предела выдержки

- **WHEN** шаг получает выдержку, формируемую движком, а объявленный для него предел контекста меньше объявленного предела выдержки
- **THEN** шаг завершается отказом до запуска бэкенда, а сообщение называет обе величины

#### Scenario: Узкий предел шага без выдержки

- **WHEN** объявленный для шага предел контекста меньше предела выдержки, но выдержки в контексте этого шага нет
- **THEN** шаг собирается как прежде, отказа по противоречию пределов нет

#### Scenario: Проверка до отправки

- **WHEN** контекст шага превышает предел
- **THEN** процесс бэкенда не запускается, и расход по этому шагу равен нулю

### Requirement: Результат непрошедшей проверки в контексте следующей итерации

На итерации цикла, следующей за непрохождением предикатов `check`, система SHALL
добавлять в контекст шагов работы запись с результатами этих предикатов и
выдержкой из их вывода. Запись MUST относиться только к непосредственно
предшествующей итерации, MUST быть видна в фиксируемом составе контекста и MUST
укладываться в объявленный предел размера выдержки. Предел MUST иметь
умолчание, не требующее объявления в конфигурации.

#### Scenario: Вывод проверки подмешан

- **WHEN** начинается вторая итерация после непрохождения `check`
- **THEN** состав контекста её шагов содержит запись с результатом непрошедшей проверки

#### Scenario: На первой итерации записи нет

- **WHEN** исполняется первая итерация работы с циклом
- **THEN** записи о результате проверки в составе контекста нет

#### Scenario: Берётся только предыдущая итерация

- **WHEN** начинается третья итерация
- **THEN** запись содержит результат проверки второй итерации и не содержит результата первой

#### Scenario: Многословная проверка не срывает следующую итерацию

- **WHEN** непрошедшая проверка дала вывод, превышающий предел контекста шага
- **THEN** следующая итерация исполняется, а не завершается отказом по пределу контекста

## ADDED Requirements

### Requirement: Выдержка о прошлой итерации усекается с сохранением конца вывода

Выдержка, превышающая объявленный предел размера, SHALL усекаться по границам
строк. Усечение MUST сохранять конец вывода каждого непрошедшего предиката и
MUST оставлять на месте отброшенного явную пометку с числом отброшенных строк.
Каркас записи — заголовок, имена непрошедших предикатов и закрывающая фраза —
MUST сохраняться целиком, а остаток предела MUST распределяться между выводами
непрошедших предикатов так, чтобы один многословный предикат не вытеснял
остальные. Итоговый размер выдержки MUST укладываться в объявленный предел при
любом числе непрошедших предикатов; если читаемой доли хватает не всем, лишние
предикаты MUST сворачиваться в одну строку с их числом. Каждое усечение MUST
порождать запись в журнале событий с исходным и итоговым размером выдержки;
повторные попытки одного шага MUST NOT множить эту запись — выдержка у них
общая.

#### Scenario: Сохраняется конец вывода

- **WHEN** вывод непрошедшего предиката превышает отведённую ему долю предела
- **THEN** в выдержку входят последние строки вывода, а не первые

#### Scenario: Усечение помечено

- **WHEN** выдержка усечена
- **THEN** перед сохранённым фрагментом стоит пометка об усечении с числом отброшенных строк

#### Scenario: Целые строки

- **WHEN** граница предела приходится на середину строки
- **THEN** эта строка в выдержку не входит целиком, а не входит частью

#### Scenario: Строка длиннее всей отведённой доли

- **WHEN** в долю предиката не помещается даже одна его строка целиком
- **THEN** в выдержку входит конец этой строки, а пометка называет её обрезанной

#### Scenario: Несколько непрошедших предикатов делят предел

- **WHEN** проверку не прошли несколько предикатов и вывод одного из них многословен
- **THEN** в выдержке присутствуют выводы всех непрошедших предикатов

#### Scenario: Предикатов больше, чем помещается в предел

- **WHEN** предел так мал, что каркаса с именами всех непрошедших предикатов в нём не хватает
- **THEN** выдержка всё равно укладывается в предел, а не выпавшие предикаты свёрнуты в строку с их числом

#### Scenario: Короткая выдержка не трогается

- **WHEN** выдержка укладывается в предел
- **THEN** она попадает в контекст без изменений и записи об усечении в журнале нет

#### Scenario: Усечение наблюдаемо

- **WHEN** выдержка усечена
- **THEN** в журнале событий есть запись об усечении с исходным и итоговым размером

#### Scenario: Повторные попытки не множат запись об усечении

- **WHEN** шаг с усечённой выдержкой делает несколько попыток
- **THEN** запись об усечении в журнале одна
