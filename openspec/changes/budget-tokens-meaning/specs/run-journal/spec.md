## ADDED Requirements

### Requirement: Наибольший префикс обращения виден рядом с расходом

Учёт SHALL запоминать наибольший объём одного обращения к API — сумму входных токенов, чтения кеша и записи в кеш одного сообщения бэкенда — и записывать его по попытке и по шагу (как максимум по её попыткам) в `usage.json`. Команда `stepcast usage` MUST показывать эту величину рядом со списанным трафиком тех же уровней. Бэкенд, не сообщающий расхода по отдельным сообщениям, MUST давать отсутствующее значение, а не ноль.

#### Scenario: Пик виден рядом с трафиком

- **WHEN** пользователь запрашивает отчёт о расходе прогона, где агентский шаг сделал много обращений к API
- **THEN** в строке шага рядом со списанным трафиком показан наибольший префикс одного обращения, и он на порядок меньше трафика

#### Scenario: Пик шага — максимум по попыткам

- **WHEN** шаг завершился успехом со второй попытки, и у попыток разные пики
- **THEN** пик шага равен наибольшему из пиков его попыток, а не их сумме

#### Scenario: Бэкенд не сообщает пооткликового расхода

- **WHEN** бэкенд сообщает расход только итогом за попытку
- **THEN** пик печатается прочерком и попадает в перечень несообщённых измерений, а не выводится нулём

## MODIFIED Requirements

### Requirement: Применение бюджета

Бюджеты SHALL объявляться на уровнях пайплайна, работы и шага и быть
необязательными. Бюджет пайплайна MUST накапливаться по всему прогону, бюджеты
работы и шага MUST ограничивать свою область. Величина токенов MUST считаться
как трафик области — сумма входных и выходных токенов, записи в кеш и чтения из
кеша с весом, заданным для бэкенда, по всем обращениям к API, а не как объём
данных, одновременно находящихся в контексте. Потолок токенов MUST быть
независим от окна модели и от предела `context.max_tokens`: его исчерпание не
означает переполнения контекста и не вызывает сжатия. При превышении любого из
действующих потолков текущий шаг MUST прерываться, а соответствующая область
MUST получать статус `budget_exceeded`. Сообщение о превышении токенного
потолка MUST называть переданный трафик, а не размер или объём данных.

#### Scenario: Превышение бюджета шага

- **WHEN** шаг превысил объявленный для него потолок токенов
- **THEN** его процесс прерывается, а шаг получает статус `budget_exceeded`

#### Scenario: Накопление по прогону

- **WHEN** сумма расхода всех работ достигла потолка пайплайна
- **THEN** прогон останавливается со статусом `budget_exceeded` и кодом возврата 3

#### Scenario: Чтение кеша учитывается с весом

- **WHEN** бэкенд сообщил чтение из кеша, а для него задан вес
- **THEN** в потолок засчитывается взвешенная величина, а в отчёте видна и исходная

#### Scenario: Бюджет не объявлен

- **WHEN** ни один уровень не объявляет бюджет
- **THEN** прогон исполняется без ограничения по расходу, а `stepcast lint` предупреждает об этом

#### Scenario: Сообщение о превышении говорит о трафике

- **WHEN** прогон остановлен по превышению токенного потолка
- **THEN** причина остановки говорит о переданном за прогон трафике при названном потолке, а не о размере контекста

#### Scenario: Потолок исчерпан при незаполненном окне

- **WHEN** трафик прогона превысил потолок, хотя ни одно обращение не приблизилось к окну модели
- **THEN** прогон останавливается по потолку, сжатие контекста не запускается, и причина не ссылается на переполнение контекста
