## ADDED Requirements

### Requirement: Командный шаг публикует структурированный вывод

Шаг `run`, объявивший `output_schema`, SHALL отдавать свой `stdout`, разобранный как JSON, в качестве структурированного вывода шага. Командный шаг без `output_schema` структурированного вывода иметь не MUST — как и сегодня. Разбор MUST быть строгим: снимаются только пробельные символы по краям, а всё остальное обязано быть одним JSON-документом; ни поиск первого объекта в выводе, ни склейка последней строки выполняться не MUST. Неразбираемый вывод MUST давать отказ шага с причиной, называющей шаг и то, что вывод не является JSON, и MUST подчиняться обычным правилам повторных попыток.

#### Scenario: Вывод разобран и опубликован

- **WHEN** командный шаг с `output_schema` печатает в `stdout` один JSON-объект и работа объявляет `output.from` на этом шаге
- **THEN** этот объект становится выходом работы и доступен как `${jobs.<id>.output.*}`

#### Scenario: Предикат схемы на командном шаге

- **WHEN** командный шаг с `output_schema` объявляет предикат `schema`
- **THEN** предикат проверяет разобранный `stdout` этого шага

#### Scenario: Вывод не является JSON

- **WHEN** командный шаг с `output_schema` печатает вперемешку лог и результат
- **THEN** шаг завершается отказом с причиной, называющей неразбираемый вывод, а не публикует пустой выход

#### Scenario: Командный шаг без объявленной схемы

- **WHEN** командный шаг не объявляет `output_schema`
- **THEN** структурированного вывода у него нет, а его `stdout` остаётся только текстовым результатом
