## ADDED Requirements

### Requirement: Верхний уровень пайплайна принимает триггеры

Верхний уровень пайплайна SHALL принимать необязательный ключ `triggers`, внутри которого признаётся единственный вид — `schedule`. Незнакомый вид триггера MUST отклоняться `stepcast lint` с именем ключа, а не игнорироваться. Ключ `triggers` MUST отклоняться внутри файла работы наравне с прочей обвязкой.

#### Scenario: Триггер расписания признаётся

- **WHEN** пайплайн содержит `triggers.schedule` со списком записей
- **THEN** `stepcast lint` принимает пайплайн

#### Scenario: Незнакомый вид триггера

- **WHEN** пайплайн содержит `triggers.github`
- **THEN** `stepcast lint` завершается ошибкой, называющей `github` непризнанным видом триггера

#### Scenario: Триггер в файле работы

- **WHEN** файл с `kind: job` содержит ключ `triggers`
- **THEN** `stepcast lint` завершается ошибкой, как и для прочей обвязки

### Requirement: Статическая валидация проверяет расписание

Команда `stepcast lint` SHALL проверять каждую запись `triggers.schedule`: наличие и разбор поля `cron` по поддержанной грамматике, известность IANA-имени в `timezone`, существование ближайшего момента срабатывания. Ошибка MUST называть запись и то, что именно в ней не принято.

#### Scenario: Неразбираемое выражение

- **WHEN** запись расписания содержит `cron: "не выражение"`
- **THEN** `stepcast lint` завершается ошибкой с номером записи и причиной отказа

#### Scenario: Поле cron отсутствует

- **WHEN** запись расписания содержит только `timezone`
- **THEN** `stepcast lint` завершается ошибкой об отсутствии обязательного `cron`

#### Scenario: Расписание проверено целиком

- **WHEN** пайплайн объявляет несколько записей расписания, и ошибочна вторая
- **THEN** `stepcast lint` называет именно её
