## ADDED Requirements

### Requirement: Шаг script публикует структурированный выход наравне с агентским

Структурированный выход шага `script`, прочитанный из файла контракта, SHALL быть доступен теми же путями, что и выход агентского шага: предикатам `schema` и `judge` в `expect`, ключу `output.from` работы, файлу `artifacts/<job>.json`, выражению `${jobs.<id>.output.*}` и автоматическому блоку контекста последующих работ.

Второго сорта у этого выхода быть MUST NOT: место, где движок различал бы
происхождение выхода, MUST оставаться единственным — чтение самого значения.
Шаг `run` от этого требования MUST оставаться незатронутым: его
`output_schema` по-прежнему разбирает `stdout`.

Переиспользование шага `script` при возобновлении прогона MUST переносить его
выход из исходного прогона так же, как переносится выход агентского шага:
работа, опубликовавшая выход шагом `script`, MUST публиковать его и после
переиспользования этого шага.

#### Scenario: Выход шага становится выходом работы

- **WHEN** работа объявляет `output.from` на шаге `script`, а тот записал файл выхода
- **THEN** записанное значение попадает в `artifacts/<job>.json` и читается как `${jobs.<id>.output.*}`

#### Scenario: Предикат схемы на шаге script

- **WHEN** шаг `script` объявляет предикат `schema` в `expect`
- **THEN** предикат проверяет значение, прочитанное из файла выхода, а не текст `stdout`

#### Scenario: Вход судьи

- **WHEN** шаг `script` объявляет предикат `judge`
- **THEN** судья получает прочитанное значение тем же полем, каким получает структурированный выход агентского шага

#### Scenario: Шаг run не затронут

- **WHEN** шаг `run` объявляет `output_schema` и печатает JSON-документ в `stdout`
- **THEN** его выход по-прежнему берётся из `stdout`, а файлы контракта в его исполнении не участвуют

#### Scenario: Переиспользованный шаг script

- **WHEN** возобновление переиспользует шаг `script`, чей выход публиковала работа
- **THEN** выход переносится из исходного прогона, а работа публикует его как свой

## MODIFIED Requirements

### Requirement: Работа публикует один структурированный выход

Работа SHALL публиковать не более одного структурированного выхода. Ключ
`output.from` указывает шаг, чей структурированный вывод становится выходом
работы; схема необязательна. При отсутствии `from` выходом MUST считаться
структурированный вывод последнего шага работы, способного его дать, —
агентского шага, шага `script` либо шага `run` с объявленным `output_schema`.
Работа, объявившая `output` без `from` и не содержащая ни одного такого шага,
MUST отклоняться до начала прогона. Файл выхода MUST записывать движок.

#### Scenario: Явно указанный шаг

- **WHEN** работа объявляет `output.from: review-self`
- **THEN** структурированный вывод этого шага публикуется как выход работы

#### Scenario: Умолчание по последнему агентскому шагу

- **WHEN** работа объявляет `output` без `from`
- **THEN** выходом становится структурированный вывод последнего исполненного агентского шага

#### Scenario: Умолчание по шагу script

- **WHEN** работа объявляет `output` без `from`, а её последний способный дать выход шаг — `script`
- **THEN** выходом становится значение, прочитанное из файла выхода этого шага

#### Scenario: Работа без способных дать выход шагов и без from

- **WHEN** работа объявляет `output` без `from` и содержит только шаги `run` без `output_schema`
- **THEN** система завершается ошибкой валидации до начала прогона
