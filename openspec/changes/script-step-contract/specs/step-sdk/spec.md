## ADDED Requirements

### Requirement: Пакет публикует библиотеку шага stepcast/step

Пакет SHALL публиковать вход `stepcast/step` — библиотеку для кода, исполняемого шагом, с функциями `input`, `output`, `publish`, `log` и `exec`.

Вход MUST объявляться в `exports` пакета наравне с `stepcast/plugin` и MUST
нести типы TypeScript. Состав MUST быть закрытым: экспортировано ровно то, что
обещано контрактом шага, и знание об устройстве движка через него утекать MUST
NOT.

Библиотека MUST быть тонкой поверх контракта: `output` MUST писать тот же файл,
который прочтёт движок, а `publish` MUST писать данные работы тем же кодом,
каким их пишет команда `stepcast data`, — второго писателя на `data.json` MUST
NOT появляться.

#### Scenario: Импорт из шага

- **WHEN** файл скрипта содержит `import { input, output } from 'stepcast/step'`
- **THEN** модуль разрешается из установленного пакета stepcast и импортируется без дополнительной настройки

#### Scenario: Публикация данных одним писателем

- **WHEN** скрипт зовёт `publish('slug', 'bug-42')`
- **THEN** результат неотличим от `stepcast data set slug bug-42`, включая проверку объявленного работой состава `data`

#### Scenario: Ключ, не объявленный работой

- **WHEN** скрипт публикует ключ, которого работа не объявляла в `data`
- **THEN** вызов отказывает тем же сообщением, каким отказывает команда

### Requirement: Библиотека работает по одним лишь переменным окружения

Функции библиотеки SHALL брать всё, что им нужно, из переменных `STEPCAST_INPUT`, `STEPCAST_OUTPUT` и `STEPCAST_JOB_DIR` и SHALL NOT принимать путей и идентификаторов аргументами.

Отсюда MUST следовать её главное свойство: библиотека работает в любом
процессе, унаследовавшем окружение шага, — не только в самом файле скрипта, но
и в дочернем процессе, запущенном им.

Поведение функций MUST быть таким:

- `input()` читает и разбирает файл входа; файл существует всегда, поэтому
  ветки «входа нет» у вызывающего быть не MUST;
- `output(значение)` записывает файл выхода целиком и атомарно; повторный
  вызов MUST заменять записанное, а не дописывать;
- `publish(ключ, значение)` и `publish(отображение)` дописывают данные работы;
- `log(...)` печатает строку в `stdout`, который остаётся логом шага;
- `exec(команда, аргументы, настройки)` запускает дочерний процесс без
  оболочки, наследуя окружение и рабочую директорию шага, отдаёт код возврата
  и собранные потоки и по умолчанию отказывает при ненулевом коде возврата;
  потоки дочернего процесса MUST по мере поступления идти и в потоки шага,
  попадая в `stdout.log` и `stderr.log`, — иначе лог шага молчал бы всё время
  работы дочернего процесса, а от упавшего в журнале осталась бы одна
  подсказка отказа.

Вызов любой из функций вне шага прогона — переменной нет — MUST давать
названный отказ, объясняющий, что библиотека работает только внутри шага, а не
писать и не читать неизвестно где.

#### Scenario: Вход прочитан

- **WHEN** шаг объявил `input: { slug: bug-42 }`, а скрипт зовёт `input()`
- **THEN** он получает отображение с полем `slug`

#### Scenario: Выход записан

- **WHEN** скрипт зовёт `output({ ok: true })`
- **THEN** файл по пути из `STEPCAST_OUTPUT` содержит этот документ, и движок читает его как структурированный выход шага

#### Scenario: Повторная запись выхода

- **WHEN** скрипт зовёт `output` дважды
- **THEN** в файле остаётся значение последнего вызова

#### Scenario: Работа из дочернего процесса

- **WHEN** скрипт на Python запускает дочерний процесс `node`, а тот импортирует библиотеку
- **THEN** дочерний процесс читает тот же вход и пишет тот же выход

#### Scenario: Дочерний процесс через exec

- **WHEN** скрипт зовёт `exec('git', ['status', '--porcelain'])`
- **THEN** он получает код возврата и собранный `stdout`, а ненулевой код по умолчанию даёт исключение

#### Scenario: Потоки дочернего процесса в логе шага

- **WHEN** запущенный через `exec` процесс печатает в `stdout` и `stderr`
- **THEN** напечатанное попадает в `stdout.log` и `stderr.log` шага, а не только в возвращённый результат

#### Scenario: Вызов вне шага

- **WHEN** файл скрипта запущен вручную, без переменных `STEPCAST_*`
- **THEN** первый же вызов библиотеки отказывает сообщением о том, что она работает только внутри шага прогона

### Requirement: Контракт шага доступен и без библиотеки

Контракт входа и выхода SHALL оставаться пригодным для языка, у которого библиотеки нет: чтения переменных окружения и разбора JSON достаточно, чтобы скрипт получил вход, отдал выход и опубликовал данные работы.

Библиотека MUST оставаться удобством, а не условием: ни одна возможность шага
`script` не MUST требовать её. Документация MUST описывать контракт раньше
библиотеки и показывать его на языке без неё.

#### Scenario: Скрипт на Python без библиотеки

- **WHEN** скрипт на Python читает файл по `STEPCAST_INPUT`, пишет файл по `STEPCAST_OUTPUT` и зовёт `stepcast data set` из каталога `STEPCAST_JOB_DIR`
- **THEN** шаг получает вход, публикует выход и данные работы наравне со скриптом, написанным с библиотекой
