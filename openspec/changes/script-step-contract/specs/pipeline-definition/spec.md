## MODIFIED Requirements

### Requirement: Шаг script объявляет файл, а не команду

Документ пайплайна SHALL признавать шаг с ключом `script`, называющим файл скрипта, с необязательным списком `args`, необязательным именем раннера `runner`, необязательным входом `input` и необязательной схемой выхода `output_schema`.

Ключ `script` MUST различать вид шага при разборе так же, как его различают
ключи `run` и `prompt`: документ, объявивший `script` вместе с `run` или с
`prompt`, MUST отклоняться разбором. Значение `args` MUST быть списком строк;
строковой формы у шага `script` нет — оболочка в его исполнении не участвует.
Значение `input` MUST быть отображением; значения его полей MAY быть любыми
представимыми в JSON. Ключ `output_schema` MUST приниматься и означать
проверку файла выхода шага, а не разбор его `stdout`; путь схемы MUST
разрешаться тем же правилом, что `output_schema` агентского шага, и `stepcast
lint` MUST проверять существование файла схемы тем же правилом, каким проверяет
её у шагов `agent` и `run`. Шаг `script` MUST принимать те же общие ключи, что
и остальные шаги: `id`, `env`, `context`, `timeout`, `budget`, `expect`,
`attempts`, а также `on_fail` тем же составом полей, что у `run`.

Ключ `input` MUST NOT приниматься шагами `run` и `agent`: вход шага `run` —
это его argv, а вход агентского шага — промпт и контекст.

Опубликованная JSON Schema документов (`schema/pipeline.schema.json`,
`schema/job.schema.json` и вывод `stepcast schema`) MUST содержать ветвь шага
`script` со всеми его ключами, чтобы редактор подсказывал их наравне с `run` и
`agent`.

#### Scenario: Шаг объявлен файлом

- **WHEN** работа объявляет `script: cleanup.py` с `args: ['--dry-run']`
- **THEN** раскрытый шаг несёт вид `script`, объявленный путь и список аргументов

#### Scenario: Два вида шага сразу

- **WHEN** шаг объявляет одновременно `script` и `run`
- **THEN** разбор документа отклоняет шаг, называя файл и место объявления

#### Scenario: Аргументы только списком

- **WHEN** шаг объявляет `args: "--dry-run --verbose"`
- **THEN** разбор документа отклоняет значение

#### Scenario: Вход объявляется отображением

- **WHEN** шаг объявляет `input: { slug: bug-42, retries: 3 }`
- **THEN** раскрытый шаг несёт вход этими полями

#### Scenario: Вход не отображением

- **WHEN** шаг объявляет `input: [a, b]` или `input: "slug"`
- **THEN** разбор документа отклоняет значение, называя место объявления

#### Scenario: Схема выхода принимается

- **WHEN** шаг `script` объявляет `output_schema: ./schemas/pick.json`
- **THEN** разбор документа принимает ключ, а путь разрешается относительно файла объявления

#### Scenario: Несуществующая схема выхода

- **WHEN** шаг `script` объявляет `output_schema`, файла по которому нет
- **THEN** `stepcast lint` завершается ошибкой, называя шаг и путь схемы

#### Scenario: Вход у чужого вида шага

- **WHEN** шаг `run` либо агентский шаг объявляет `input`
- **THEN** разбор документа отклоняет ключ

#### Scenario: Ветвь есть в опубликованной схеме

- **WHEN** пакет напечатал JSON Schema документов
- **THEN** описание шага допускает ключи `script`, `args`, `runner`, `input` и `output_schema`

## ADDED Requirements

### Requirement: Вход шага script раскрывается как JSON, а не как строка

Значения внутри `input` SHALL раскрываться подстановками наравне с остальными полями работы, а строка, состоящая ровно из одной подстановки и ничего кроме неё, SHALL давать значение того типа, какой лежит в источнике.

Правило MUST действовать на обоих этапах раскрытия: `${inputs.*}` и
`${params.*}` — при разборе документа, `${jobs.*}`, `${run.*}` и `${env.*}` —
перед исполнением работы. Строка, где подстановка соседствует с любым другим
текстом, MUST раскрываться в строку, как в остальных полях документа.
Подстановка `${jobs.*.output.*}` внутри `input` MUST приниматься: значение
уезжает в файл, а не в командную строку, и запрет, действующий для строковой
формы `run`, здесь не применим.

Правило типизированного значения MUST NOT распространяться за пределы `input`:
в остальных полях документа подстановка, дающая объект или список, остаётся
отказом с прежней причиной.

#### Scenario: Объект уезжает объектом

- **WHEN** шаг объявляет `input: { item: "${jobs.plan.output.item}" }`, а выход работы `plan` содержит объект в поле `item`
- **THEN** вход шага несёт этот объект целиком, а не его строковое представление

#### Scenario: Число остаётся числом

- **WHEN** шаг объявляет `input: { retries: "${params.retries}" }` при `params.retries: 3`
- **THEN** вход шага несёт число `3`

#### Scenario: Подстановка внутри текста даёт строку

- **WHEN** шаг объявляет `input: { title: "чинить ${jobs.plan.output.slug}" }`
- **THEN** вход шага несёт строку с подставленным значением

#### Scenario: Прежнее правило вне input не меняется

- **WHEN** подстановка, дающая объект, объявлена в `args`, в `env` или в тексте промпта
- **THEN** раскрытие отклоняет её с прежней причиной «непредставимое строкой»
