## 9. Правки по ревью

- [x] 9.1 Обёртка различает формат модуля (`src/step/wrapper.ts`): у CommonJS
  точка входа — только `module.exports`-функция, всё прочее `module.exports`
  исполняется как обычный скрипт. До правки любой скрипт на `.cjs` и на `.js`
  без `"type": "module"` отказывал «Default export модуля не функция»: Node
  кладёт в `default` значение `module.exports`, у такого скрипта пустое.
- [x] 9.2 Тесты обёртки на CommonJS: скрипт `.cjs` без экспорта, скрипт `.js`
  без `package.json` рядом, `module.exports` функцией. Первые два падают на
  коде до правки 9.1.
- [x] 9.3 Тесты обёртки, объявленные 1.8, но не написанные: асинхронная точка
  входа и default export не функцией.
- [x] 9.4 Структурированный выход снимается в начале каждой попытки
  (`src/core/run/runner.ts`): успешная попытка, файла не записавшая, не
  выдаёт за свой выход значение прошлой. Тест 1.7 нужной ветви не касался —
  добавлен тест на настоящий случай, падающий на коде до правки.
- [x] 9.5 Промах контракта выхода дописывается к результатам предикатов
  последним, а не отменяет их: упавший скрипт с объявленным `output_schema`
  назван упавшим по `exit_code`. Судьи по промаху контракта не зовутся —
  платить за вызов модели на решённом отказе незачем.
- [x] 9.6 Тесты позднего типизированного раскрытия `input` (`test/late.test.ts`
  и прогон в `test/run.test.ts`): объект из выхода работы выше по графу
  доезжает объектом, число — числом, смешанная строка — строкой, а шаги
  сопоставляются по индексу верно.
- [x] 9.7 `exec` пишет потоки дочернего процесса в потоки шага по мере
  поступления, как и обещала 5.4, — с тестом и записью в спеке `step-sdk`.
- [x] 9.8 Позиция подстановки в типизированном проходе считается `positionAt`,
  а не проставляется константой: соглашение о позиции у двух проходов одно.
