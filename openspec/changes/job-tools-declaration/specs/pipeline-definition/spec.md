## ADDED Requirements

### Requirement: Пространство project содержит имя tools

Пространство подстановки `project` SHALL содержать имя `tools` — действующее объявление инструментов репозитория, списком строк.

Значение SHALL раскрываться при разборе документа наравне с остальными именами
пространства: оно известно до запуска прогона, и раскрытый пайплайн MUST
содержать на его месте объявленные строки, а не подстановку. Доступно оно там
же, где прочие имена пространства, — в документе пайплайна, файлах работ и
файлах промптов.

Документ пайплайна SHALL принимать ключ `tools` внутри верхнего ключа
`project` и перекрывать им конфигурацию — тем же порядком слоёв, каким
перекрывает остальные ключи секции. Требования к значению MUST быть теми же,
что в конфигурации: непустой список непустых строк.

Обращение к необъявленному `${project.tools}` MUST быть отказом разбора, а не
пустым списком; сообщение MUST называть оба места объявления — документ
пайплайна и `.stepcast/config.yml`. Перечень доступных имён пространства,
который движок печатает при обращении к имени вне состава, MUST включать
`tools`.

#### Scenario: Инструменты в списке прав шага

- **WHEN** шаг объявляет право `Bash(${project.tools} *)`, а объявление задаёт `tools: [npm, npx, node]`
- **THEN** шаг уходит в бэкенд с правами `Bash(npm *)`, `Bash(npx *)` и `Bash(node *)`

#### Scenario: Пайплайн перекрывает конфигурацию

- **WHEN** `.stepcast/config.yml` объявляет `project.tools: [npm]`, а пайплайн — `project: { tools: [go] }`
- **THEN** `${project.tools}` во всех документах прогона раскрывается в `go`

#### Scenario: Раскрытое значение попадает в снимок пайплайна

- **WHEN** пайплайн со ссылкой на `${project.tools}` раскрыт
- **THEN** `pipeline.lock.yml` содержит на этом месте объявленные строки, а не подстановку

#### Scenario: Ссылка без объявления

- **WHEN** документ содержит `${project.tools}`, а ключ не объявлен ни пайплайном, ни конфигурацией
- **THEN** `stepcast lint` завершается ошибкой, называющей оба места объявления
- **AND** `stepcast run` не начинает прогон

#### Scenario: Имя вне состава пространства

- **WHEN** документ содержит `${project.toolchain}`
- **THEN** разбор завершается ошибкой с перечнем доступных имён пространства, среди которых назван `tools`

#### Scenario: Документ без ссылки на имя

- **WHEN** ни пайплайн, ни его работы, ни промпты не ссылаются на `${project.tools}`, а ключ не объявлен
- **THEN** пайплайн разбирается и исполняется без ошибки

### Requirement: Списочное значение подстановки раскрывается в элемент списка

Элемент списка, являющийся строкой, в которой ровно одна подстановка даёт список строк, SHALL заменяться на столько элементов, сколько значений в списке: окружающий текст применяется к каждому значению отдельно.

Порядок произведённых элементов MUST повторять порядок значений; место MUST
быть тем же, где стоял исходный элемент, а соседние элементы MUST сохранять
взаимный порядок. Прочие подстановки того же элемента MUST раскрываться как
обычно, по разу на каждый произведённый элемент; отложенная подстановка MUST
оставаться текстом в каждом из них и раскрываться позднее наравне с любой
другой.

Ровно одна списочная подстановка на элемент MUST быть условием: элемент, в
котором списочное значение дают две подстановки и более, MUST отклоняться
разбором с сообщением, называющим поле и выражения, — сколько записей даёт
такое произведение, формат не определяет.

Вне списка списочное значение MUST оставаться непредставимым строкой:
подстановка в скалярном поле отклоняется разбором, а подсказка MUST называть
условие раскрытия — списочное значение раскрывается только в элементе списка.
Подсказка об этом условии MUST выдаваться только там, где условие действует:
значению, которое размножено не будет, она указывала бы на выход, которого у
автора нет.

Список без значений MUST отклоняться разбором, а не удалять элемент: ноль
произведённых элементов означал бы исчезнувшее право или снятую границу
правок — изменение политики, о котором никто не просил и никто не узнал бы.

Правило MUST действовать при разборе документа и MUST NOT действовать при
позднем раскрытии: значения отложенных пространств (`jobs`, `run`, `env`)
приходят из выхода работы — произвольного JSON, не проходившего схемы, — и
списочное значение там MUST оставаться непредставимым строкой, как до
введения правила. Раскрытый пайплайн уже зафиксирован снимком к этому моменту,
и состав списка после фиксации меняться не должен.

Карта подстановок раскрытого документа MUST относить подстановки к путям
произведённых элементов, а не исходного: раскрытый документ содержит именно
их, и статические проверки, работающие по этой карте, MUST применяться к
каждому произведённому значению отдельно.

#### Scenario: Элемент размножается по числу значений

- **WHEN** список объявлен как `[Read, "Bash(${project.tools} *)", "Bash(git log*)"]`, а `tools` — `[npm, npx, node]`
- **THEN** раскрытый список содержит пять элементов: `Read`, три записи `Bash(<имя> *)` в объявленном порядке и `Bash(git log*)` последним

#### Scenario: Список из одного значения

- **WHEN** та же запись раскрывается против `tools: [go]`
- **THEN** на её месте стоит ровно один элемент `Bash(go *)`

#### Scenario: Отложенная подстановка в размножаемом элементе

- **WHEN** элемент списка объявлен как `"${project.tools} ${run.id}"`
- **THEN** каждый произведённый элемент несёт своё значение списка, а `${run.id}` остаётся в каждом из них до позднего раскрытия

#### Scenario: Две списочные подстановки в одном элементе

- **WHEN** элемент списка объявлен как `"${project.tools}-${project.tools}"`
- **THEN** разбор завершается ошибкой, называющей поле и выражения

#### Scenario: Списочное значение в скалярном поле

- **WHEN** скалярное поле объявлено как `${project.tools}`
- **THEN** разбор завершается ошибкой, а подсказка называет, что списочное значение раскрывается только в элементе списка

#### Scenario: Значение, которое размножено не будет

- **WHEN** элемент списка ссылается на подстановку, дающую массив не из строк
- **THEN** разбор завершается ошибкой с перечнем допустимых значений, а не подсказкой о раскрытии в элементе списка

#### Scenario: Список без значений

- **WHEN** подстановка в элементе списка даёт пустой список
- **THEN** разбор завершается ошибкой, называющей поле, а элемент из списка не исчезает

#### Scenario: Список строк в выходе работы

- **WHEN** элемент списка объявлен как `"${jobs.build.output.changed_files}"`, а работа опубликовала списком строк
- **THEN** позднее раскрытие завершается ошибкой «непредставимое строкой», а элемент не размножается и не исчезает

#### Scenario: Проверка путей идёт по произведённым элементам

- **WHEN** список путей контекста объявлен одним элементом со списочной подстановкой, и один из произведённых путей в дереве отсутствует
- **THEN** `stepcast lint` сообщает об ошибке, называя именно этот путь
