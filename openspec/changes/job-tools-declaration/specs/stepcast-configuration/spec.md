## ADDED Requirements

### Requirement: Инструменты репозитория объявляются в конфигурации

Конфигурация SHALL принимать в секции `project` ключ `tools` — список имён команд, которыми в этом репозитории собирают, проверяют и запускают код.

Значение — список строк; каждая строка называет команду, а не право на неё:
форму права собирает файл работы, потому что синтаксис политики доступа
принадлежит бэкенду, а не репозиторию. Пробел внутри значения MUST
допускаться: `./gradlew` — имя с разделителем пути, `npm run` — осмысленное
сужение права.

Каждый элемент MUST быть непустым по тому же правилу, что `project.check` и
`project.spec.tool`: пустая строка и строка из пробельных символов
отклоняются разбором конфигурации. Пустой список MUST отклоняться там же:
репозиторий, которому нечего объявлять, ключ не заводит вовсе, а объявление,
не объявляющее ничего, — забытая правка, а не осмысленное значение.

Требование непустоты — и строки, и списка — MUST быть выражено в публикуемой
JSON Schema, а не только в модели: обрезку пробелов схема не переносит, и без
образца редактор принимал бы значения, которые движок отвергает.

Встроенного умолчания у ключа MUST NOT быть — набор инструментов,
подставленный за автора, был бы верен ровно для того репозитория, из которого
его списали. Ключ MUST оставаться необязательным: его отсутствие — не ошибка,
пока на него никто не сослался.

Ключ MUST быть допустим только в `.stepcast/config.yml` и отклоняться в
`~/.stepcast/config.yml` тем же правилом, что остальные ключи секции
`project`: инструментарий принадлежит репозиторию, а не машине.

Между слоями конфигурации значение MUST заменяться целиком, а не
объединяться: список инструментов — описание репозитория, и слой, назвавший
свои, называет их вместо, а не вдобавок. Слияние секции `project` по листьям
MUST сохраняться: объявить `tools` в одном слое, а `check` в другом можно, и
одно другого не затирает.

#### Scenario: Ключ объявлен в проектном конфиге

- **WHEN** `.stepcast/config.yml` содержит `project: { tools: ["npm", "npx", "node"] }`
- **THEN** действующее значение `project.tools` равно объявленному списку в объявленном порядке
- **AND** отчёт `stepcast config` называет источником этот файл

#### Scenario: Ключ не объявлен

- **WHEN** ни один слой конфигурации не задаёт `project.tools`
- **THEN** конфигурация разрешается без ошибки, а значение отсутствует

#### Scenario: Пустой список

- **WHEN** конфигурация содержит `project: { tools: [] }`
- **THEN** чтение конфигурации завершается ошибкой, называющей файл и ключ

#### Scenario: Пустое имя инструмента

- **WHEN** конфигурация содержит `project: { tools: ["npm", "   "] }`
- **THEN** чтение конфигурации завершается ошибкой, называющей файл и ключ

#### Scenario: Имя с пробелом принимается

- **WHEN** конфигурация содержит `project: { tools: ["./gradlew", "npm run"] }`
- **THEN** конфигурация разрешается без ошибки, а значения сохраняются как объявлены

#### Scenario: Ключ в глобальном конфиге

- **WHEN** `~/.stepcast/config.yml` содержит `project: { tools: ["npm"] }`
- **THEN** чтение конфигурации завершается ошибкой, называющей файл и предлагающей `.stepcast/config.yml`

#### Scenario: Верхний слой заменяет список целиком

- **WHEN** конфигурация объявляет `project.tools: ["npm", "node"]`, а документ пайплайна — `project: { tools: ["go"] }`
- **THEN** действующее значение — `["go"]`, без элементов нижнего слоя

#### Scenario: Соседний ключ секции не затирается

- **WHEN** `.stepcast/config.yml` объявляет `project.check`, а документ пайплайна — только `project.tools`
- **THEN** действуют оба значения: `check` из конфигурации, `tools` из пайплайна

#### Scenario: Публикуемая схема повторяет требование

- **WHEN** `schema/config.schema.json` описывает `project.tools`
- **THEN** описание требует массив с непустым числом элементов, а каждый элемент — строку с образцом непробельного символа
