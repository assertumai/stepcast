## 2. Хранилище

- [x] 2.1 `src/core/journal/schema.ts`: схема записи хранилища —
  проект (ключ и путь), пайплайн (имя и файл), прогон, времена, исход, итог
  (виды токенов, `billable_tokens`, `wallclock_ms`, необязательный `cost_usd`),
  `unreported`, число попыток без цены, разрез по моделям и по работам с
  шагами, версия формата. Схема сохраняет незнакомые поля (design.md,
  Решение 7) — в отличие от прочих схем журнала, и это объяснено комментарием.
- [x] 2.2 `src/core/journal/usageStore.ts`: путь хранилища от корня прогонов,
  права `0600`; `appendUsageRecord` — дозапись одной строкой; `readUsageStore`
  — построчное чтение с пропуском неразбираемых строк, счётом пропущенных и
  правилом «побеждает последняя запись прогона» (Решения 1, 4, 6).
- [x] 2.3 `usageRecord(manifest, status, report)` — единственная точка сборки
  записи, общая для движка и переноса (Решение 2); приведение долей моделей к
  итогу прогона тем же правилом `spread`, что в `src/ui/usage.ts`
  (Решение 13), — правило выносится в общее место, а не копируется.
- [x] 2.4 `backfillUsageStore(runsRoot)`: перечисление прогонов корня
  каталогами, чтение `usage.json` только у тех, кого в хранилище нет, дозапись
  их записей; выполняется один раз на процесс при открытии хранилища
  (Решение 9).
- [x] 2.5 `selectUsageRecords` и `removeUsageRecords`: отбор по возрасту,
  исходу и проекту; снятие переписыванием во временный файл с догоном хвоста и
  заменой через `rename` (Решения 8, 14).

## 3. Движок

- [x] 3.1 `src/core/run/runner.ts`: дозапись записи хранилища из

  «сохранить»; сохранение дописывает запись из каталога, если её ещё нет, до
  снятия файлов; снятие — после успешного снятия файлов (Решение 10). Исход
  каждого адреса называет, что стало с файлами и что — с записью.
