## ADDED Requirements

### Requirement: Сводка расхода прогона хранится вне его каталога

Движок SHALL хранить сводку расхода каждого прогона в общем хранилище корня прогонов, отдельном от каталога прогона.
Запись хранилища MUST переживать удаление каталога прогона, удаление каталога
его проекта и снятие записи проекта из `projects.json`. Отсутствие файла
хранилища MUST читаться как пустое хранилище, а не как ошибка.

#### Scenario: Запись переживает удаление каталога прогона

- **WHEN** каталог прогона удалён целиком, а снятия его статистики не просили
- **THEN** сводка расхода этого прогона по-прежнему читается из хранилища

#### Scenario: Запись переживает удаление проекта

- **WHEN** удалён последний прогон проекта и вместе с ним каталог проекта и его запись в `projects.json`
- **THEN** сводки расхода прогонов этого проекта по-прежнему читаются из хранилища и называют путь проекта

#### Scenario: Пустое хранилище

- **WHEN** файла хранилища ещё нет
- **THEN** чтение отдаёт пустой набор записей и не завершается ошибкой

### Requirement: Хранилище дописывается по завершении прогона

Движок SHALL дописывать запись прогона в хранилище по его завершении, одной новой записью, не переписывая накопленного.
Дозапись MUST делаться тем же местом, которое подводит сводку расхода прогона,
и MUST NOT делаться для прогона, который ещё идёт. Повторная запись по тому же
прогону MUST быть разрешена, а при чтении MUST побеждать последняя из них.

#### Scenario: Завершённый прогон попадает в хранилище

- **WHEN** прогон завершился любым исходом
- **THEN** в хранилище появляется его запись, а накопленные ранее записи остались без изменений

#### Scenario: Идущий прогон в хранилище не попадает

- **WHEN** прогон ещё исполняется
- **THEN** записи о нём в хранилище нет

#### Scenario: Повторная запись вытесняет прежнюю

- **WHEN** по одному и тому же прогону в хранилище дописаны две записи
- **THEN** чтение отдаёт одну запись этого прогона — последнюю дописанную

### Requirement: Обрыв записи портит не больше одной записи

Хранилище SHALL переживать обрыв процесса на записи, теряя не больше одной записи и оставаясь читаемым.
Читатель MUST пропускать запись, которую не удалось разобрать, MUST возвращать
их число вместе с прочитанными записями и MUST NOT отказывать в чтении
хранилища целиком из-за одной испорченной записи. Число испорченных записей
MUST называться там, где хранилище показывается человеку.

#### Scenario: Оборванный хвост

- **WHEN** процесс прерван посреди дозаписи и последняя запись хранилища не дописана до конца
- **THEN** остальные записи читаются как прежде, а незавершённая пропускается

#### Scenario: Число испорченных записей названо

- **WHEN** хранилище содержит запись, которую не удалось разобрать
- **THEN** чтение сообщает число таких записей, а не молчит о них

#### Scenario: Испорченная запись чинится переносом

- **WHEN** запись прогона в хранилище испорчена, а каталог прогона цел
- **THEN** перенос накопленного дописывает запись этого прогона заново

### Requirement: Запись несёт разрез, из которого строится расход

Запись хранилища SHALL нести всё, из чего строится разрез расхода: проект, пайплайн, прогон, времена, исход и сам расход.
Запись MUST называть ключ проекта, путь проекта, имя и файл пайплайна,
идентификатор прогона, время начала, время завершения и исход прогона. Расход
MUST быть назван итогом прогона деньгами и токенами и разрезом по работам,
шагам и моделям. Несообщённая цена MUST оставаться отсутствующей, а не нулевой,
и число попыток с несообщённой ценой MUST быть названо. Сумма долей моделей
MUST сходиться с итогом прогона в каждой мере. Запись MUST нести версию своего
формата, а читатель MUST сохранять незнакомые поля записи, а не отвергать её
из-за них.

#### Scenario: Разрез читается без каталога прогона

- **WHEN** файлы прогона удалены, а запись сохранена
- **THEN** по записи читаются итог прогона, его расход по работам, шагам и моделям

#### Scenario: Несообщённая цена не превращается в ноль

- **WHEN** ни одна попытка прогона не сообщила цены
- **THEN** запись не называет денежного итога и называет число попыток с несообщённой ценой

#### Scenario: Доли моделей сходятся с итогом

- **WHEN** сумма попыток прогона больше его итога — расход перенесённой попытки лежит в сводке шага, но в итог прогона не входит
- **THEN** доли моделей в записи ужаты до итога прогона

#### Scenario: Запись более новой версии формата

- **WHEN** хранилище содержит запись, чья версия формата новее версии читателя
- **THEN** запись читается по известным полям, а расхождение версий названо

### Requirement: Накопленное переносится в хранилище

Движок SHALL переносить в хранилище сводки прогонов, которые есть на диске, но которых в хранилище ещё нет.
Перенос MUST выполняться при открытии хранилища, до первого чтения, и не чаще
одного раза за время жизни процесса. Перенос MUST читать сводку расхода из
каталога прогона и MUST записывать исход, записанный в состоянии прогона, —
включая прогоны, которые остались незавершёнными. Маршрут витрины, отдающий
разрез расхода, MUST оставаться чтением и MUST NOT дописывать хранилище сам.

#### Scenario: Прогоны прошлых заходов попадают в хранилище

- **WHEN** хранилище открывается впервые, а на диске лежат прогоны, завершившиеся до его появления
- **THEN** в хранилище появляются записи этих прогонов с их расходом

#### Scenario: Перенос не повторяется

- **WHEN** хранилище уже содержит запись прогона
- **THEN** перенос эту запись не переписывает и второй строки не добавляет

#### Scenario: Оборванный прогон переносится со своим исходом

- **WHEN** переносится прогон, чьё состояние осталось `running`
- **THEN** его запись появляется в хранилище с этим исходом, а не пропускается

### Requirement: Записи снимаются отдельной операцией по признакам

Хранилище SHALL позволять снять записи отбором по возрасту, исходу и проекту — операцией, которая не трогает файлов прогонов.
Отбор без единого признака MUST NOT снимать ничего. Снятие записей MUST
сохранять записи, не попавшие в отбор, включая записи, дописанные во время
самого снятия. Дозапись новой записи MUST NOT требовать переписывания
хранилища.

#### Scenario: Снятие по возрасту

- **WHEN** запрошено снятие записей старше указанного срока
- **THEN** записи старше срока сняты, остальные остались, а каталоги прогонов не тронуты

#### Scenario: Снятие по исходу и проекту

- **WHEN** запрошено снятие записей отказавших прогонов одного проекта
- **THEN** сняты только записи этого проекта с исходом отказа

#### Scenario: Отбор без признаков

- **WHEN** снятие запрошено без единого признака отбора
- **THEN** не снята ни одна запись

#### Scenario: Прогон, завершившийся во время снятия

- **WHEN** прогон дописал свою запись, пока шло снятие записей по другому признаку
- **THEN** его запись остаётся в хранилище после снятия
