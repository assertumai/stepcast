## Пока нет: снято

- **Сведение и коммит по каждому затронутому репозиторию**
- **Сведение дорожек при очереди внутри вложенного репозитория**
- **Несколько репозиториев у одного пункта**

## Пока нет

- **Несколько репозиториев у одного пункта**: `stepcast project repos` отказывает, если пункт называет больше одного репозитория, — одна дорожка ведёт ровно один репозиторий. Межрепозиторный пункт заводится форматом (поле `repos` — перечень), но до конца не доводится: нужны границы правок по репозиторию (см. выше). Сведение по каждому затронутому репозиторию уже работает и на объявление пункта не опирается — оно считает затронутых по диффу.

## Известные ограничения: снято

- **`stepcast apply` и `merge-lanes` недоступны составному прогону.**

## Работает

- **`stepcast apply` накладывает составной результат по репозиториям**: один помощник наложения (`applyLane`, прогон целиком, `--job`) делает для составного якоря по вызову на корень и на каждую часть, чьи oid до и после различаются, — каждый `git apply --3way` в собственном каталоге репозитория, без приставки пути. Отказ на любом репозитории (конфликт наложения, движение записи gitlink объявленного каталога) откатывает все затронутые к состоянию до наложения; состояние, снятое на другом составе вложенных репозиториев, отказывает названным расхождением, а не наложением чужой части в сегодняшнюю. Однорепозиторный прогон накладывается прежним единственным диффом. Итог `stepcast run` для составного прогона снова предлагает `stepcast apply` наравне с однорепозиторным.
- **`stepcast merge-lanes` сводит и коммитит по каждому затронутому репозиторию**: вклад дорожки накладывается во все репозитории, которые она затронула (по её состояниям, не по объявлению пункта `repos`), затем в каждом исполняется его команда проверки — корневая ключом `--check`, вложенная из объявления `project.nested_repos` — в каталоге этого репозитория, в детерминированном порядке, останавливаясь на первой красной; коммит идёт только после того, как зелены все. Затронутая дорожкой сводится в столько коммитов, сколько репозиториев она затронула, с одним сообщением `<слаг>: <заголовок>`. Коммиты идут снизу вверх по гитлинкам: вложенный репозиторий коммитится раньше корня, который ведёт его записью gitlink, и корень коммитится всегда — иначе сдвинутая коммитом части запись осталась бы незакоммиченной и дерево запуска нечистым. Репозиторий, в чьём рабочем дереве лежит файл очереди, коммитится последним из тех, кого корень гитлинком не ведёт, и несёт отметку `done` — даже если дорожка его дифом не задела; коммит на пустом индексе (файл очереди этим репозиторием не отслеживается) пропускается без отказа, и такой репозиторий не называется среди репозиториев сведённой дорожки. Красная проверка любого затронутого репозитория откатывает все затронутые к их коммитам до наложения; незатронутый объявленный репозиторий откатом не задет. Затронутый репозиторий без объявленной команды проверки — отказ кодом `2` до первого наложения, называющий репозиторий и дорожку; спрашивается команда только с дорожек, которые до наложения дойдут, — негодная дорожка обхода остальных не роняет. Однорепозиторное сведение (состав не объявлен) не меняется ничем — тот же единственный коммит, те же тексты отказов и коды возврата.
- **Обрыв между коммитами читается по состоянию репозиториев**: до первой правки дерева команда сверяет `HEAD` корня и каждого объявленного вложенного репозитория с слагами пунктов дорожек этого прогона — сообщение `<слаг>: …` у пункта, чей исход в очереди не проставлен, означает, что прошлое сведение оборвалось между коммитами, и команда отказывает кодом `2`, называя репозитории с этим коммитом и те, кому он полагался, но не лёг. Пункт со статусом `done` или `failed` ложного срабатывания не даёт.
- **Файл очереди может лежать внутри объявленного вложенного репозитория**: прежний отказ снят — репозиторий, где он лежит, просто коммитится последним из тех, кого корень не ведёт гитлинком.
