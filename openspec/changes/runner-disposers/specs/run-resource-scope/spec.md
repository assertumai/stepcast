## ADDED Requirements

### Requirement: Захват ресурса регистрирует обратную операцию в области

Раннер SHALL захватывать ресурсы через области: захват регистрирует в области именованную обратную операцию, а выход из области исполняет зарегистрированные операции в порядке, обратном регистрации. Область MUST допускать повторное снятие как пустую операцию и MUST отклонять регистрацию после снятия ошибкой движка. Асинхронная обратная операция MUST быть дождана до исполнения следующей.

#### Scenario: Обратный порядок

- **WHEN** в области зарегистрированы операции A, B, C в этом порядке
- **THEN** при снятии исполняются C, B, A

#### Scenario: Регистрация после снятия

- **WHEN** область снята, а затем в неё регистрируют операцию
- **THEN** регистрация завершается ошибкой движка, называющей область

#### Scenario: Повторное снятие

- **WHEN** область снимается второй раз
- **THEN** ни одна операция не исполняется повторно

### Requirement: Отказ обратной операции — учётная операция

Исключение из обратной операции SHALL записываться событием `bookkeeping.failed` с именем операции и областью (работа, шаг, если известны) и MUST NOT прерывать исполнение остальных операций области. Снятие области MUST NOT бросать исключение наружу и MUST NOT подменять причину, по которой область снимается. Область без журнала MUST предназначаться только для операций, не отказывающих по устройству; исключение из такой операции MUST выходить наружу.

#### Scenario: Отказ одной операции не останавливает остальные

- **WHEN** из трёх зарегистрированных операций средняя бросает исключение
- **THEN** остальные две исполняются, а в журнале одно событие `bookkeeping.failed` с именем средней

#### Scenario: Исходная причина сохраняется

- **WHEN** работа отказала на шаге, а снятие индексного файла якоря при выходе из области отказало тоже
- **THEN** статус работы — `failed` с причиной отказа шага, а отказ снятия виден только событием `bookkeeping.failed`

### Requirement: Уровни областей раннера

Раннер SHALL держать область прогона (состояние ожидания, слушатель отмены), область работы (индексный файл якоря, пустой каталог черновиков) и область попытки шага (слушатели отмены попытки); каждая MUST сниматься одним `finally` своей функции при любом исходе — успехе, отказе, отмене, остановке по бюджету. Область прогона MUST сниматься до записи события `run.finished`.

#### Scenario: Якорь снят при отказе

- **WHEN** работа отказала на первом шаге
- **THEN** индексный файл якоря работы отсутствует в каталоге прогона

#### Scenario: Слушатели отмены сняты после попытки

- **WHEN** попытка шага завершилась любым исходом
- **THEN** на сигнале отмены прогона не остаётся слушателей этой попытки

#### Scenario: Отказ снятия при отмене

- **WHEN** прогон отменён, а обратная операция области работы отказала
- **THEN** статус прогона `canceled`, код возврата 130, а отказ записан событием `bookkeeping.failed` до `run.finished`
