## MODIFIED Requirements

### Requirement: Состояние достаточно для продолжения

Файл `status.json` SHALL содержать идентификатор прогона, имя пайплайна, входы, статус каждой работы, для упавшей работы — идентификатор шага, номер попытки, непройденные предикаты, выдержку из вывода и путь к полному журналу, а также израсходованную и предельную величины бюджета. Для прогона, полученного возобновлением, состояние MUST содержать идентификатор исходного прогона. Для каждой работы состояние MUST содержать режим и путь её рабочей директории, а для завершённых шагов — якорь состояния дерева. Для работы, унаследовавшей рабочее дерево, состояние MUST содержать идентификатор работы-источника и признак того, продолжена ли чужая рабочая директория или заведена собственная; работа без наследования этих сведений MUST NOT нести. Команда возобновления в состоянии MUST указывать точку, с которой имеет смысл продолжать.

#### Scenario: Отказ описан полностью

- **WHEN** работа завершилась отказом
- **THEN** `status.json` позволяет назвать упавший шаг, непройденный предикат и путь к его логу без обращения к другим файлам

#### Scenario: Состояние дописывается при прерывании

- **WHEN** прогон прерван
- **THEN** `status.json` содержит статусы всех работ на момент прерывания

#### Scenario: Происхождение возобновлённого прогона

- **WHEN** прогон создан возобновлением
- **THEN** `status.json` содержит идентификатор исходного прогона

#### Scenario: Рабочая директория работы описана

- **WHEN** работа исполнялась в изолированном режиме
- **THEN** `status.json` содержит режим и путь её рабочей директории

#### Scenario: Источник унаследованного дерева описан

- **WHEN** работа унаследовала рабочее дерево предшественника
- **THEN** `status.json` называет идентификатор работы-источника и отличает продолженную директорию от собственной

#### Scenario: Работа без наследования

- **WHEN** работа не имеет зависимостей
- **THEN** её запись в `status.json` сведений об источнике не содержит

### Requirement: Поток событий

Система SHALL вести журнал событий построчно, по одной записи на событие, в формате, допускающем чтение по мере поступления. Записи MUST включать начало и завершение работ и шагов, попытки, непройденные предикаты, исключения по запретам окружения и путей, предупреждения и остановки по бюджету, обнаружение зависшего шага, наследование рабочего дерева работой.

#### Scenario: Чтение на лету

- **WHEN** прогон исполняется
- **THEN** содержимое журнала событий доступно для чтения до его завершения

#### Scenario: Запись об исключении по запрету

- **WHEN** переменная окружения или путь контекста исключены по запрету
- **THEN** в журнале есть запись с именем и сработавшим шаблоном

#### Scenario: Запись о наследовании дерева

- **WHEN** работа начала с состояния, унаследованного от предшественника
- **THEN** в журнале есть запись с именем работы, именем источника и способом получения директории
