## ADDED Requirements

### Requirement: Витрина говорит по-английски

Всё, что показывает браузер — подписи страниц, заголовки экранов в меню,
тексты ошибок и подсказок из ответов демона, — MUST быть на английском языке.

#### Scenario: Заголовки меню

- **WHEN** витрина открыта с составом поставки
- **THEN** пункты меню называются Runs, Pipelines, Backlog, Board, Widgets, Routes, Proposals, Decisions, Usage, Cleanup, Agents, Settings

### Requirement: Меню сгруппировано по `nav.group`

Маршрут MAY объявить `nav.group`; пункты одной группы MUST стоять вместе под
её заголовком, группы поставки — в порядке `work`, `extend`, `system`, пункты
без группы — после групп.

#### Scenario: Пункт перенесён в другую группу домашним слоем

- **WHEN** `~/.stepcast/routes.yml` объявляет `nav: { group: work }` для `screen-cleanup`
- **THEN** пункт Cleanup показан в группе Work, остальные поля маршрута не меняются

### Requirement: Каталог виджетов поставки

Экран Widgets MUST показывать образцы из `src/builtin/widgets/` с описанием,
живым превью и действием «Add to project»; установка MUST копировать файл в
`<проект>/.stepcast/widgets/<id>.tsx` и MUST NOT перезаписывать существующий.

#### Scenario: Добавление образца

- **WHEN** пользователь выбирает проект и нажимает «Add to project» у `clock`
- **THEN** демон создаёт `.stepcast/widgets/clock.tsx`, и виджет появляется в разделе Installed событием потока

#### Scenario: Файл уже есть

- **WHEN** в проекте уже есть `.stepcast/widgets/clock.tsx`
- **THEN** ответ 409, файл не тронут, отказ показан на карточке

### Requirement: Поле модели агента — список с поиском и свободным вводом

Поле модели на экране Agents MUST предлагать имена, перечисленные CLI
агента, и имена, уже сохранённые в конфигурации, с фильтрацией по набранному;
набранное имя вне списка MUST сохраняться как есть и MUST быть отмечено как
custom.

#### Scenario: Имя вне списка

- **WHEN** пользователь набирает `my-fine-tune`, которого нет в списке
- **THEN** поле показывает бейдж custom, сохранение записывает `my-fine-tune`

### Requirement: Экран Proposals объясняет себя

Экран MUST объяснять в шапке, что такое предложение и как оно попадает в
очередь; MUST показывать только проекты с записями, подписывая их последним
сегментом пути; открытые и решённые записи MUST быть разделены.

#### Scenario: Нет ни одной записи

- **WHEN** ни у одного проекта нет записей
- **THEN** экран показывает одно пустое состояние с объяснением, без перечня проектов

## REMOVED Requirements

### Requirement: Экран «Шаги»

**Reason**: каталог `uses:`-шагов без единого действия; сведения о шаге
показывает экран Pipelines при раскрытии `uses:`.
**Migration**: маршрут `/steps` и `GET /api/steps` сняты; патч, отключавший
`screen-steps`, становится безадресным и ни на что не влияет.
