## ADDED Requirements

### Requirement: Команда проверки чистоты дерева

`stepcast assert-clean [--allow <пути через запятую>]` SHALL отвечать, чисты ли рабочее дерево, в котором она запущена, и объявленные вложенные репозитории, не изменяя ни одного из них.

Команда MUST быть частью бинаря и не зависеть от файлов конкретного проекта:
её вход — корень рабочего дерева git, найденный от каталога запуска,
объявление `project.nested_repos` из конфигурации проекта и необязательный
перечень путей, правки которых чистоту не нарушают. Проверять буквальный
каталог запуска команда MUST NOT: и проектный конфиг, и пути состава
объявлены от корня дерева, поэтому из подкаталога она не прочла бы состав
вовсе и ответила бы «чисто» на грязный вложенный репозиторий — тишина здесь
неотличима от чистоты. Команда MUST NOT править, коммитить и удалять
что-либо: она только отвечает. Позиционных аргументов у команды нет.

#### Scenario: Чистое дерево

- **WHEN** в рабочем дереве нет незакоммиченных и неотслеживаемых изменений
- **THEN** команда завершается кодом `0`, ничего не изменив

#### Scenario: Грязное дерево

- **WHEN** в рабочем дереве есть изменённый отслеживаемый либо неотслеживаемый и не игнорируемый файл
- **THEN** команда завершается кодом `2` и называет репозиторий, который нечист

#### Scenario: Вызов из подкаталога дерева

- **WHEN** команда запущена в подкаталоге дерева, где объявлен состав, а нечист объявленный вложенный репозиторий
- **THEN** ответ тот же, что и при запуске из корня: код `2` с именем этого репозитория

#### Scenario: Проверка ничего не правит

- **WHEN** команда вызвана на грязном дереве
- **THEN** незакоммиченные и неотслеживаемые файлы остаются на месте, а `HEAD` не двигается

### Requirement: Проверка обходит корень и каждый объявленный вложенный репозиторий

Команда SHALL снимать состояние отдельно по корню дерева и по каждому каталогу, объявленному в `project.nested_repos`, и признавать дерево чистым только когда чисты все.

Причина в том, что `git status` корня во вложенный репозиторий не заглядывает:
игнорируемый корнем не виден вовсе, отслеживаемый виден одной записью gitlink,
которую правка рабочего дерева не двигает. Обход MUST идти по корню, а затем
по объявленным каталогам в каноническом порядке конфигурации. Отказ MUST
называть **все** репозитории, оказавшиеся нечистыми, — корень отдельным словом
«корень», вложенный — своим объявленным каталогом, — а не только сообщать
факт и не останавливаться на первом нечистом. Запись корня о самом объявленном
каталоге (неотслеживаемый каталог либо сдвинутый gitlink) MUST оставаться
нарушением чистоты корня: её снимает откат корня. Дерево, у которого состав не
объявлен, MUST отвечать прежним сообщением об одном дереве: слово «корень»
объясняло бы там состав, которого нет.

#### Scenario: Грязный вложенный при чистом корне

- **WHEN** корень чист, а в объявленном вложенном репозитории лежит незакоммиченная правка, и корень этот каталог игнорирует
- **THEN** команда завершается кодом `2`, называя этот вложенный репозиторий

#### Scenario: Нечисты сразу несколько репозиториев

- **WHEN** незакоммиченные изменения есть и в корне, и в двух объявленных вложенных репозиториях
- **THEN** сообщение называет все три, а не первый попавшийся

#### Scenario: Корень нечист сам собой при объявленном составе

- **WHEN** объявленный вложенный репозиторий чист, а корень несёт неотслеживаемый каталог этой части либо сдвинутую на неё ссылку gitlink
- **THEN** команда завершается кодом `2`, называя нечистым корень

#### Scenario: Состав не объявлен

- **WHEN** `project.nested_repos` в конфигурации нет
- **THEN** проверяется одно дерево, и ответ — включая текст сообщения об отказе — тот же, каким был бы без объявления состава

### Requirement: Названные пути не нарушают чистоты того дерева, где лежат

Перечисленные ключом `--allow` пути SHALL исключаться из проверки того репозитория, в чьём рабочем дереве они лежат, и только его.

Путь MAY быть абсолютным либо относительным каталогу запуска. Принадлежность
дереву MUST решаться по самому длинному совпавшему объявленному префиксу — тем
же правилом, каким составной якорь маршрутизирует пути в свои части, — и путь
MUST сверяться со `status` этого репозитория относительно **его** корня. Путь,
не попавший ни в одно из проверяемых деревьев, MUST просто ни с чем не
совпасть. Умолчания у ключа нет: не названный явно файл чистоту нарушает.

#### Scenario: Названный файл в корне

- **WHEN** в корне изменён файл, названный в `--allow`, и больше ничего
- **THEN** команда завершается кодом `0`

#### Scenario: Названный файл во вложенном репозитории

- **WHEN** названный в `--allow` путь лежит внутри объявленного вложенного репозитория и изменён там
- **THEN** команда завершается кодом `0`: исключение сверено со `status` того репозитория, а не корня

#### Scenario: Исключение не расползается на соседние деревья

- **WHEN** в `--allow` назван файл корня, а одноимённый файл изменён внутри объявленного вложенного репозитория
- **THEN** команда завершается кодом `2`, называя этот вложенный репозиторий

### Requirement: Репозиторий, который нечем проверить, — отказ

Команда SHALL отказывать, если каталог запуска не является репозиторием git либо если объявленный вложенный каталог отсутствует или не является рабочим деревом git.

Отказ MUST называть каталог, о котором речь, и MUST отличать корень от
объявленной части, а отсутствующий каталог — от каталога без git: это разные
починки (опечатка в составе против несклонированной части). Пропустить
непроверяемую часть молча команда MUST NOT: тишина здесь неотличима от
чистоты — ровно та ошибка, ради которой проверка и обходит части. Отказ
самого git на снятии состояния объявленной части MUST оставаться названным
отказом команды, а не выходить наружу необъяснённым.

#### Scenario: Корень вне репозитория git

- **WHEN** каталог запуска не является репозиторием git
- **THEN** команда завершается кодом `2`, называя причину

#### Scenario: Объявленный каталог не является рабочим деревом git

- **WHEN** каталог, названный в `project.nested_repos`, существует, но не является рабочим деревом собственного репозитория
- **THEN** команда завершается кодом `2`, называя этот каталог

#### Scenario: Объявленного каталога нет вовсе

- **WHEN** каталога, названного в `project.nested_repos`, в дереве нет
- **THEN** команда завершается кодом `2`, называя этот каталог отсутствующим, а не «не рабочим деревом git»

### Requirement: Коды возврата команды проверки чистоты

Команда SHALL завершаться кодом `0`, когда чисты все проверенные репозитории, и кодом `2` в любом ином случае — грязное дерево, непроверяемый репозиторий, ошибка ключей.

Отдельного кода у грязного дерева нет намеренно: вызывающий — шаг пайплайна с
предикатом `exit_code: 0`, и различать причины отказа он не станет, а
сообщение их называет и так.

#### Scenario: Отказ в шаге пайплайна

- **WHEN** команда вызвана шагом с предикатом `exit_code: 0` на грязном дереве
- **THEN** шаг отказывает, а его лог несёт сообщение с именами нечистых репозиториев
