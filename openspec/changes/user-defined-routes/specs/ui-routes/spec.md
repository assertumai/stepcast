## ADDED Requirements

### Requirement: Маршрут витрины объявляется файлом, а не кодом экрана

Маршрут SHALL быть отдельной строкой файла маршрутов и объявлять `id`, путь с параметрами, цель, необязательные параметры цели, необязательный закрытый перечень значений параметров пути, необязательное место в навигации и признак включённости. Путь MUST допускать обязательный параметр сегментом `:имя` и необязательный последним сегментом `:имя?`. Формат файла MUST проверяться схемой, и неизвестный ключ строки MUST быть отказом с указанием файла и места, а не молча пропущенным полем. Схема формата MUST публиковаться тем же генератором, каким публикуются схемы конфигурации и пайплайна, и MUST проверяться на свежесть той же проверкой.

#### Scenario: Маршрут с параметром пути

- **WHEN** файл маршрутов объявляет путь с сегментом-параметром, и открыт адрес, подходящий под этот шаблон
- **THEN** открывается цель маршрута, а значение сегмента достаётся ей параметром под объявленным именем

#### Scenario: Необязательный параметр последним сегментом

- **WHEN** маршрут объявляет последний сегмент необязательным параметром, и открыт адрес без него
- **THEN** маршрут подходит, и параметр доезжает до цели незаполненным

#### Scenario: Неизвестный ключ строки маршрута

- **WHEN** строка маршрута несёт ключ, которого формат не объявляет
- **THEN** сборка таблицы отказывает, называя файл, место и неизвестный ключ

#### Scenario: Схема формата опубликована

- **WHEN** печатаются публикуемые схемы пакета
- **THEN** среди них есть схема файла маршрутов, и её содержимое совпадает с моделью формата

### Requirement: Маршруты складываются тремя слоями и сливаются по `id`

Таблица маршрутов SHALL собираться тремя слоями снизу вверх: встроенный файл поставки, домашний файл `~/.stepcast/routes.yml` и проектный файл `.stepcast/routes.yml` каталога, в котором поднят демон. Строка верхнего слоя с уже известным `id` MUST сливаться с одноимённой по объявленным полям, оставаясь на её месте в порядке, а строка с новым `id` MUST дополнять таблицу. Поле `enabled: false` MUST убирать маршрут из действующей таблицы целиком — из навигации, из разбора адреса и из сборки ссылок. Отсутствие файла слоя MUST быть обычным состоянием, а не отказом. Источник MUST сохраняться по каждому полю строки, а не только по строке, чтобы перечень маршрутов мог назвать, какой файл дал путь, а какой — название пункта.

#### Scenario: Пользователь переносит встроенный маршрут на другой путь

- **WHEN** проектный файл объявляет строку с `id` встроенного маршрута и другим путём
- **THEN** встроенный экран открывается по новому пути, по прежнему не открывается, а прочие поля маршрута — цель и место в навигации — остаются прежними

#### Scenario: Пользователь переименовывает пункт меню

- **WHEN** домашний файл объявляет строку с `id` встроенного маршрута и одним лишь названием пункта
- **THEN** пункт меню называется по-новому, а путь и цель маршрута остаются встроенными

#### Scenario: Пользователь отключает встроенный маршрут

- **WHEN** файл слоя объявляет строку встроенного маршрута отключённой
- **THEN** его адрес перестаёт открывать цель, пункт исчезает из навигации, и ссылка на эту цель не собирается

#### Scenario: Свой маршрут пользователя

- **WHEN** проектный файл объявляет строку с `id`, которого нет ни в одном слое ниже
- **THEN** маршрут добавляется к таблице, не задевая остальных

#### Scenario: Проектный слой — каталог демона

- **WHEN** демон поднят в каталоге проекта, у которого есть файл маршрутов
- **THEN** этот файл — проектный слой таблицы, а файлы маршрутов прочих проектов, видимых демону, в неё не входят

#### Scenario: Файла слоя нет

- **WHEN** ни домашнего, ни проектного файла маршрутов не существует
- **THEN** действует встроенная таблица, и отказа нет

### Requirement: Путь принадлежит одному маршруту

Каждый адрес SHALL принадлежать не более чем одному действующему маршруту: два маршрута с одинаковым шаблоном пути MUST быть названным отказом сборки таблицы с указанием обоих `id` и обоих файлов, и второй MUST NOT подменять первый молча. Шаблоны, отличающиеся только именами параметров, MUST считаться одинаковыми: имя параметра — дело маршрута, адрес от него не зависит. Путь под адресами, которые разбирает сам демон — `/api`, `/widgets/`, `/plugins/`, `/shared/`, — MUST отклоняться названным отказом: страница по таким адресам не открывается никогда. Отказ сборки таблицы MUST NOT менять действующую таблицу и MUST NOT гасить витрину: действует последняя собранная, а причина показывается пользователем вместе с ней.

#### Scenario: Два маршрута на один путь

- **WHEN** проектный файл объявляет маршрут с новым `id` на путь, уже занятый другим действующим маршрутом
- **THEN** сборка таблицы отказывает, называя путь, оба `id` и оба файла

#### Scenario: Шаблоны различаются только именами параметров

- **WHEN** два маршрута объявляют шаблоны, совпадающие посегментно и различающиеся именами параметров
- **THEN** это тот же конфликт пути, а не два разных адреса

#### Scenario: Путь под адресом демона

- **WHEN** файл маршрутов объявляет путь, начинающийся с адреса, который разбирает демон
- **THEN** сборка таблицы отказывает, называя путь и причину, а прежняя таблица продолжает действовать

#### Scenario: Отказ таблицы не гасит витрину

- **WHEN** файл маршрутов испорчен или содержит конфликт при работающем демоне
- **THEN** прежние маршруты продолжают открываться, а причина отказа названа на странице с указанием файла

### Requirement: Встроенные экраны открываются маршрутами встроенного файла

Все встроенные экраны витрины SHALL открываться маршрутами, объявленными во встроенном файле поставки тем же форматом и теми же слоями, что и пользовательские, и их прежние адреса MUST сохраняться содержимым этого файла. Ни разбор адреса, ни сборка ссылки, ни каркас витрины, ни компонент экрана MUST NOT содержать зашитого пути экрана. Встроенный файл MUST быть перекрываем и дополняем пользовательскими слоями наравне с любым другим и MUST NOT иметь привилегии — ни отдельного вида записи, ни правила, недоступного пользователю. Отсутствие или неразбираемость встроенного файла MUST быть названным отказом подъёма витрины, а не молчаливым возвратом к зашитым адресам.

#### Scenario: Прежние адреса сохранены

- **WHEN** витрина поднята без единого пользовательского файла маршрутов
- **THEN** каждый встроенный экран открывается по тому же адресу, по какому открывался до появления маршрутов

#### Scenario: Зашитых путей не осталось

- **WHEN** во встроенном файле маршрутов изменён путь встроенного экрана
- **THEN** экран открывается по новому пути, и ни одного места, продолжающего вести на прежний, не остаётся

#### Scenario: Встроенный файл сломан

- **WHEN** встроенный файл маршрутов отсутствует или не разбирается
- **THEN** подъём витрины отказывает с названием файла и причиной, а зашитые адреса не подставляются

### Requirement: Цель маршрута — экран или виджет, и вид цели пополняем вкладом

Маршрут SHALL называть цель видом и идентификатором: экран по его `id` либо виджет по проекту и `id`. Вид цели MUST быть пополняемым вкладом состава, а не перечислением в маршрутизаторе: строка, приносящая новый вид цели, MUST становиться доступной маршрутам, не меняя ни разбора адреса, ни каркаса. Параметры пути MUST доезжать до цели по своим именам без объявления, а ключ параметров цели MUST добавлять литералы и подстановки вида `${params.<имя>}`; подстановка на имя, которого нет в шаблоне пути, MUST быть названным отказом сборки таблицы, а не пустым значением. Маршрут на цель, которой нет в действующем составе, и маршрут на неизвестный вид цели MUST показываться названной причиной на месте цели и в перечне маршрутов, а не пустым экраном.

#### Scenario: Маршрут на экран

- **WHEN** маршрут называет целью экран действующего состава, и открыт его адрес
- **THEN** открывается этот экран, и параметры пути доезжают до него по своим именам

#### Scenario: Маршрут на виджет

- **WHEN** маршрут называет целью виджет проекта, и открыт его адрес
- **THEN** виджет открывается на месте экрана тем же хостом, каким он показывается на экране виджетов

#### Scenario: Параметры цели с подстановкой

- **WHEN** маршрут объявляет параметр цели со значением-подстановкой параметра пути
- **THEN** цель получает подставленное значение, а объявленные литералы — как есть

#### Scenario: Подстановка на несуществующий параметр

- **WHEN** параметр цели ссылается на имя, которого нет в шаблоне пути маршрута
- **THEN** сборка таблицы отказывает, называя маршрут, файл и имя

#### Scenario: Цели нет в составе

- **WHEN** маршрут называет экран, которого нет в действующем составе
- **THEN** на его месте показана названная причина, и тот же маршрут помечен ею в перечне маршрутов

#### Scenario: Неизвестный вид цели

- **WHEN** маршрут называет вид цели, которого действующий состав не знает
- **THEN** показана причина с названием вида, а не пустой экран

### Requirement: Навигация и стартовая страница собираются из маршрутов

Навигация витрины SHALL собираться из маршрутов с объявленным местом в навигации, в объявленном пользователем порядке и с объявленными им названиями; маршрут без такого объявления MUST NOT давать пункта меню, оставаясь открываемым по своему адресу. Название пункта MUST браться из маршрута, а при его отсутствии — из заголовка цели. Маршрут MUST быть вправе назвать другие маршруты, на которых его пункт остаётся подсвеченным, — страница прогона своего пункта не имеет и подсвечивает пункт прогонов, и это правило MUST быть свойством маршрута, а не зашитой связью двух экранов. Ни каркас витрины, ни маршрутизатор MUST NOT содержать перечня целей: и меню, и разбор адреса собираются из действующей таблицы маршрутов. Стартовая страница SHALL задаваться маршрутом с путём `/`, а не кодом; правила «экран по умолчанию» — выбора цели по порядку пунктов навигации или по любому иному свойству цели — MUST NOT оставаться в коде витрины.

#### Scenario: Порядок и названия пунктов заданы пользователем

- **WHEN** файл слоя задаёт встроенным маршрутам другие названия и другой порядок
- **THEN** меню показывает их в заданном порядке под заданными названиями

#### Scenario: Пункт подсвечен на дочернем маршруте

- **WHEN** открыт адрес маршрута, названного другим маршрутом в перечне подсветки
- **THEN** подсвечен пункт назвавшего маршрута, хотя своего пункта у открытого нет

#### Scenario: Маршрут без места в навигации

- **WHEN** маршрут объявлен без места в навигации
- **THEN** его пункта в меню нет, а адрес открывается

#### Scenario: Стартовая страница задана маршрутом

- **WHEN** пользователь объявляет путь `/` маршрутом на другую цель
- **THEN** корневой адрес открывает эту цель, и никакое иное правило выбора цели на него не влияет

### Requirement: Адрес без маршрута показывает перечень объявленных маршрутов

Адрес, не разобранный ни одним действующим маршрутом, SHALL показывать перечень объявленных маршрутов — путь, цель и источник каждого — и MUST NOT показывать пустой экран и MUST NOT молча подменяться другой целью. Тот же перечень MUST показываться на корневом адресе, если стартовый маршрут не объявлен, с названием этой причины. Перечень MUST оставаться доступным и тогда, когда действующих маршрутов нет вовсе, и MUST называть файл слоя, в который пишутся маршруты.

#### Scenario: Неизвестный адрес

- **WHEN** открыт адрес, которого не объявил ни один действующий маршрут
- **THEN** показан перечень объявленных маршрутов с их целями и источниками

#### Scenario: Стартовая страница не объявлена

- **WHEN** открыт корневой адрес, и маршрута с путём `/` нет
- **THEN** показан тот же перечень и названа причина: стартовая страница не объявлена

#### Scenario: Таблица пуста

- **WHEN** все маршруты отключены слоями пользователя
- **THEN** страница называет это состояние и путь к файлу слоя, а не остаётся пустой

### Requirement: Правка файла маршрутов применяется в открытой витрине

Правка файла маршрутов SHALL применяться в уже открытой витрине без перезагрузки страницы: новая таблица MUST приходить потоком событий демона, а навигация, разобранный адрес и собранные ссылки MUST пересчитываться по ней. Демон MUST замечать правку наблюдением за файлами слоёв своей частью отпечатка и MUST NOT перечитывать ради неё очередь, виджеты и прогоны. Отправка таблицы MUST идти только при отличии от отправленной прежде. Адрес, открытый до правки и оставшийся объявленным, MUST продолжать показывать ту же цель, а переставший быть объявленным MUST показать перечень маршрутов.

#### Scenario: Маршрут добавлен при открытой витрине

- **WHEN** в файл маршрутов добавлена строка при открытой странице
- **THEN** пункт появляется в меню, а его адрес открывается без перезагрузки вкладки

#### Scenario: Маршрут отключён при открытой витрине

- **WHEN** маршрут открытой страницы отключён правкой файла
- **THEN** страница показывает перечень маршрутов, не дожидаясь перезагрузки

#### Scenario: Неизменные файлы не пересылаются

- **WHEN** такт наблюдения прошёл без правки файлов маршрутов
- **THEN** событие таблицы не отправляется, и очередь с виджетами не перечитываются

### Requirement: Витрина показывает маршруты с источником и правит файл слоя

Витрина SHALL показывать действующие маршруты — путь, цель, место в навигации, источник каждого поля и диагностику — и SHALL давать добавить маршрут и править существующий, сохраняя строку в названный файл слоя. Сохранение MUST называть файл до записи и MUST сохранять комментарии, порядок прочих строк и форматирование файла пользователя. Встроенный файл поставки MUST NOT переписываться ни при каком действии витрины: правка встроенного маршрута MUST записываться строкой с его `id` в файл пользовательского слоя. Файл, который не разобрался, MUST NOT переписываться: отказ MUST называть место разбора. Запись MUST происходить только по явному действию пользователя через объявленный маршрут API.

#### Scenario: Перечень с источниками

- **WHEN** открыт экран маршрутов
- **THEN** по каждому маршруту показаны путь, цель, место в навигации и файл, из которого пришло каждое поле

#### Scenario: Отключённый маршрут включается обратно из витрины

- **WHEN** открыт экран маршрутов, и один из маршрутов отключён файлом слоя
- **THEN** он показан отдельной строкой с файлом, который его выключил, и включается обратно записью строки в тот же слой

#### Scenario: Правка встроенного маршрута из витрины

- **WHEN** пользователь меняет в витрине путь встроенного маршрута и сохраняет
- **THEN** строка с его `id` появляется в файле пользовательского слоя, встроенный файл не изменяется, и новый путь действует

#### Scenario: Комментарии пользователя переживают запись

- **WHEN** витрина сохраняет маршрут в файл слоя, где есть комментарии и другие строки
- **THEN** комментарии и прочие строки остаются на месте

#### Scenario: Файл слоя сломан

- **WHEN** витрина сохраняет маршрут в файл, который не разбирается
- **THEN** запись отказывает с названием места разбора, и файл остаётся нетронутым

### Requirement: Разбор маршрутов общий у демона и браузера

Сопоставление адреса с шаблоном, выбор маршрута, сборка ссылки по цели и подстановка параметров SHALL быть одним модулем, общим демону и браузеру, и MUST NOT зависеть ни от диска, ни от окружения браузера. Чтение файлов слоёв, проверка схемой и слияние MUST оставаться на стороне демона: страница MUST получать уже собранную таблицу с источниками и диагностикой и MUST NOT разбирать файлы сама. Выбор маршрута MUST идти по конкретности шаблона — статический сегмент побеждает параметр на той же позиции, — а не по порядку строк в файлах. Ссылка на цель, которую не опубликовал ни один действующий маршрут, MUST быть отсутствием ссылки с названной причиной, а не адресом какой-либо другой цели. Правила формата, слоёв, целей, подстановок и конфликтов MUST быть описаны в документации.

#### Scenario: Статический сегмент побеждает параметр

- **WHEN** объявлены маршруты со статическим сегментом и с параметром на той же позиции, и открыт адрес, подходящий обоим
- **THEN** открывается маршрут со статическим сегментом, независимо от порядка строк в файлах

#### Scenario: Ссылка на цель без маршрута

- **WHEN** место витрины собирает ссылку на цель, маршрут которой отключён
- **THEN** ссылки нет, причина названа на месте, и адрес другой цели не подставляется

#### Scenario: Разбор один на две стороны

- **WHEN** демон и страница разбирают один и тот же адрес по одной и той же таблице
- **THEN** они выбирают один и тот же маршрут и одни и те же значения параметров

#### Scenario: Формат описан

- **WHEN** пользователь ищет, как объявить маршрут
- **THEN** документация описывает формат файла, слои, виды целей, подстановки параметров и правила конфликта путей
