## ADDED Requirements

### Requirement: Поток событий несёт действующие маршруты и состав экранов

Поток событий демона SHALL нести действующую таблицу маршрутов отдельным событием — по каждому маршруту путь, цель, параметры, место в навигации и источник, — и SHALL нести действующий состав экранов тем же потоком. Оба события MUST отправляться первым же обменом при подключении и дальше только при отличии от отправленного прежде — тем же правилом, каким отправляются виджеты и плагины. Состав и таблица MUST собираться на каждом такте по действующему ядру демона, а не сниматься один раз на соединение: страница, открытая до правки, MUST видеть то же, чем живёт демон. Ограничение «новый состав экранов виден только после перезагрузки вкладки» MUST быть снято и MUST NOT оставаться в документации.

#### Scenario: Таблица пришла при подключении

- **WHEN** страница подключилась к потоку событий
- **THEN** она получает действующую таблицу маршрутов и состав экранов первым же обменом

#### Scenario: Правка файла маршрутов отражается в потоке

- **WHEN** файл маршрутов изменён при открытой странице
- **THEN** событие приносит новую таблицу, а состав экранов и виджеты не пересылаются

#### Scenario: Состав экранов изменён без перезагрузки

- **WHEN** патч состава отключил экран при открытой странице
- **THEN** новый состав приходит потоком, и маршрут на отключённый экран показывает названную причину без перезагрузки вкладки

#### Scenario: Неизменное не пересылается

- **WHEN** такт наблюдения прошёл без правки файлов маршрутов и без смены состава
- **THEN** ни события таблицы, ни события состава не отправляется

## MODIFIED Requirements

### Requirement: Наблюдение не изменяет журнал

Демон SHALL только читать файлы, за которыми наблюдает: он MUST NOT изменять, создавать или удалять файлы прогонов. Кроме корня прогонов демон читает файлы проектов, названных указателем `projects.json`, — очередь улучшений, каталог переиспользуемых шагов и каталог виджетов, — файлы маршрутов своих слоёв и каталоги плагинов своих слоёв, и это чтение MUST оставаться чтением: ни компиляция виджета, ни сборка браузерной половины плагина, ни кеш их результатов, ни наблюдение за файлом маршрутов MUST NOT записывать ничего ни в каталог проекта, ни в каталог плагина. Единственная запись демона в каталог проекта или в домашний каталог SHALL быть записью файла маршрутов слоя по явному действию пользователя через объявленный маршрут API; никакой другой файл проекта демон изменять MUST NOT, и встроенный файл маршрутов поставки MUST NOT изменяться никогда. Собственное состояние демона (pid-файл и лог) MUST лежать вне каталогов прогонов, вне каталогов проектов и вне каталогов плагинов.

#### Scenario: Наблюдение оставляет файлы нетронутыми

- **WHEN** демон наблюдает за корнем прогонов, каталогами проектов и файлами маршрутов
- **THEN** ни один наблюдаемый файл не создаётся, не изменяется и не удаляется наблюдением

#### Scenario: Запись файла маршрутов по действию пользователя

- **WHEN** пользователь сохраняет маршрут через объявленный маршрут API витрины
- **THEN** демон пишет только файл маршрутов названного слоя, а прочие файлы проекта остаются нетронутыми

#### Scenario: Состояние демона вне наблюдаемых каталогов

- **WHEN** демон поднят
- **THEN** его pid-файл и лог лежат вне корня прогонов, вне каталогов проектов и вне каталогов плагинов
