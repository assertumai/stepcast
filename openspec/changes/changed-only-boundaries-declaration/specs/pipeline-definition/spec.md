## ADDED Requirements

### Requirement: Пространство project содержит имя edit_paths

Пространство подстановки `project` SHALL содержать имя `edit_paths` — действующее объявление границ правок репозитория, списком строк.

Значение SHALL раскрываться при разборе документа наравне с остальными именами
пространства: оно известно до запуска прогона, и раскрытый пайплайн MUST
содержать на его месте объявленные пути, а не подстановку. Доступно оно там же,
где прочие имена пространства, — в документе пайплайна, файлах работ и файлах
промптов.

Раскрытие в элемент списка MUST подчиняться уже действующему правилу списочного
значения: элемент `- ${project.edit_paths}` заменяется на столько записей,
сколько объявлено путей, в объявленном порядке, а соседние записи списка
сохраняют своё место. Отдельного правила для границ правок MUST NOT
заводиться — это второе списочное имя пространства, а не второй способ
раскрытия.

Документ пайплайна SHALL принимать ключ `edit_paths` внутри верхнего ключа
`project` и перекрывать им конфигурацию — тем же порядком слоёв, каким
перекрывает остальные ключи секции. Требования к значению MUST быть теми же,
что в конфигурации: непустой список относительных путей от корня репозитория.

Обращение к необъявленному `${project.edit_paths}` MUST быть отказом разбора, а
не пустым списком; сообщение MUST называть оба места объявления — документ
пайплайна и `.stepcast/config.yml`. Перечень доступных имён пространства,
который движок печатает при обращении к имени вне состава, MUST включать
`edit_paths`.

#### Scenario: Границы в предикате шага

- **WHEN** шаг объявляет `changed_only: ["${project.edit_paths}", "docs/changes/**"]`, а объявление задаёт `edit_paths: [src/**, test/**]`
- **THEN** предикат шага несёт шаблоны `src/**`, `test/**` и `docs/changes/**` — в этом порядке

#### Scenario: Пайплайн перекрывает конфигурацию

- **WHEN** `.stepcast/config.yml` объявляет `project.edit_paths: [src/**]`, а пайплайн — `project: { edit_paths: [cmd/**] }`
- **THEN** `${project.edit_paths}` во всех документах прогона раскрывается в `cmd/**`

#### Scenario: Раскрытое значение попадает в снимок пайплайна

- **WHEN** пайплайн со ссылкой на `${project.edit_paths}` раскрыт
- **THEN** `pipeline.lock.yml` содержит на этом месте объявленные пути, а не подстановку

#### Scenario: Ссылка без объявления

- **WHEN** документ содержит `${project.edit_paths}`, а ключ не объявлен ни пайплайном, ни конфигурацией
- **THEN** `stepcast lint` завершается ошибкой, называющей оба места объявления
- **AND** `stepcast run` не начинает прогон

#### Scenario: Имя вне состава пространства

- **WHEN** документ содержит `${project.edit_path}`
- **THEN** разбор завершается ошибкой с перечнем доступных имён пространства, среди которых назван `edit_paths`

#### Scenario: Списочное значение в скалярном поле

- **WHEN** скалярное поле объявлено как `check: ${project.edit_paths}`
- **THEN** разбор завершается ошибкой о значении, непредставимом строкой, с подсказкой о раскрытии только в элементе списка

#### Scenario: Документ без ссылки на имя

- **WHEN** ни пайплайн, ни его работы, ни промпты не ссылаются на `${project.edit_paths}`, а ключ не объявлен
- **THEN** пайплайн разбирается и исполняется без ошибки
