## ADDED Requirements

### Requirement: Границы правок объявляются в конфигурации

Конфигурация SHALL принимать в секции `project` ключ `edit_paths` — список путей и шаблонов от корня репозитория, правка которых в этом репозитории и есть работа над ним.

Значение — список путей, а не готовый предикат: форму предиката собирает файл
работы, потому что работа добавляет к объявленному свои записи, а список между
слоями заменяется целиком и дописать к нему было бы нечем.

Каждый элемент MUST проверяться тем же правилом, что `project.spec.dir`:
пустая строка, строка из пробельных символов, абсолютный путь и путь с
сегментом `..` отклоняются разбором конфигурации. Правило MUST быть тем же
самым, а не повторённым: пути в предикат границ приходят относительно корня
рабочего дерева, и запись, которой ни один из них не может соответствовать, —
не расширенная граница, а тихо бесполезное объявление. Шаблоны глоба
(`src/**`, `*.md`) MUST приниматься: граница правок из них и состоит.

Пустой список MUST отклоняться там же и по той же причине, что `project.tools`:
объявление, не называющее ни одного пути, — забытая правка, а не «править
нечего».

Требование непустоты — и строки, и списка — MUST быть выражено в публикуемой
JSON Schema, а не только в модели: обрезку пробелов схема не переносит.

Встроенного умолчания у ключа MUST NOT быть: раскладка, подставленная за
автора, была бы верна ровно для того репозитория, из которого её списали. Ключ
MUST оставаться необязательным — его отсутствие не ошибка, пока на него никто
не сослался.

Ключ MUST быть допустим только в `.stepcast/config.yml` и отклоняться в
`~/.stepcast/config.yml` тем же правилом, что остальные ключи секции `project`:
раскладка принадлежит репозиторию, а не машине.

Между слоями конфигурации значение MUST заменяться целиком, а не
объединяться, — как `project.tools`. Слияние секции `project` по листьям MUST
сохраняться: объявить `edit_paths` в одном слое, а `check` в другом можно, и
одно другого не затирает.

#### Scenario: Ключ объявлен в проектном конфиге

- **WHEN** `.stepcast/config.yml` содержит `project: { edit_paths: ["src/**", "package.json"] }`
- **THEN** действующее значение `project.edit_paths` равно объявленному списку в объявленном порядке
- **AND** отчёт `stepcast config` называет источником этот файл

#### Scenario: Ключ не объявлен

- **WHEN** ни один слой конфигурации не задаёт `project.edit_paths`
- **THEN** конфигурация разрешается без ошибки, а значение отсутствует

#### Scenario: Пустой список

- **WHEN** конфигурация содержит `project: { edit_paths: [] }`
- **THEN** чтение конфигурации завершается ошибкой, называющей файл и ключ

#### Scenario: Пустой путь в списке

- **WHEN** конфигурация содержит `project: { edit_paths: ["src/**", "   "] }`
- **THEN** чтение конфигурации завершается ошибкой, называющей файл и ключ

#### Scenario: Абсолютный путь

- **WHEN** конфигурация содержит `project: { edit_paths: ["/etc/**"] }`
- **THEN** чтение конфигурации завершается ошибкой, сообщающей, что ожидается относительный путь от корня репозитория

#### Scenario: Путь с сегментом `..`

- **WHEN** конфигурация содержит `project: { edit_paths: ["../other-repo/**"] }`
- **THEN** чтение конфигурации завершается ошибкой, сообщающей, что путь не может выходить за корень репозитория

#### Scenario: Шаблон глоба принимается

- **WHEN** конфигурация содержит `project: { edit_paths: ["cmd/**", "internal/**", "go.mod", "go.sum"] }`
- **THEN** конфигурация разрешается без ошибки, а значения сохраняются как объявлены

#### Scenario: Ключ в глобальном конфиге

- **WHEN** `~/.stepcast/config.yml` содержит `project: { edit_paths: ["src/**"] }`
- **THEN** чтение конфигурации завершается ошибкой, называющей файл и предлагающей `.stepcast/config.yml`

#### Scenario: Верхний слой заменяет список целиком

- **WHEN** конфигурация объявляет `project.edit_paths: ["src/**", "test/**"]`, а документ пайплайна — `project: { edit_paths: ["cmd/**"] }`
- **THEN** действующее значение — `["cmd/**"]`, без элементов нижнего слоя

#### Scenario: Соседний ключ секции не затирается

- **WHEN** `.stepcast/config.yml` объявляет `project.check`, а документ пайплайна — только `project.edit_paths`
- **THEN** действуют оба значения: `check` из конфигурации, `edit_paths` из пайплайна

#### Scenario: Публикуемая схема повторяет требование

- **WHEN** `schema/config.schema.json` описывает `project.edit_paths`
- **THEN** описание требует массив с непустым числом элементов, а каждый элемент — строку с образцом непробельного символа
