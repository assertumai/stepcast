## ADDED Requirements

### Requirement: Запись данных работы ограничена её объявлением

Движок SHALL отклонять запись данных по ключу, которого определение текущей работы не объявляет, и MUST NOT менять при этом файл данных.

Отказ MUST называть работу и ключ, а MUST также перечислять объявленный работой
состав: сообщение адресовано автору пайплайна и агенту внутри шага, и ответ
«какой ключ здесь законен» обязан быть в самом отказе.

Проверка MUST стоять на общем пути публикации, а не в одной лишь команде
`stepcast data`: тем же путём публикуют данные и другие команды движка,
исполняемые внутри шага. Низкоуровневый писатель файла, которым движок
переносит уже отобранный состав, MUST называть обход объявления своим именем,
чтобы новый писатель не взял его по невнимательности; запись, прошедшая мимо
объявления этой дорогой, всё равно MUST быть отклонена на приёме.

Объявление MUST читаться из раскрытого определения работы, лежащего в каталоге
работы рядом с файлом данных: подпроцессу шага доступно только окружение, а
каталог работы он получает переменной `STEPCAST_JOB_DIR`.

Отсутствующее либо нечитаемое определение MUST считаться пустым объявлением, то
есть приводить к отказу записи, а не к её разрешению. Отказ по ненайденному
определению MUST объясняться иначе, чем отказ по пустому объявлению, и MUST
называть ожидавшийся путь: работа, честно не объявившая ключей, и каталог
прогона без раскрытого определения — разные поломки, и совет править пайплайн
уместен только в первой.

Чтение (`stepcast data get`) объявлением MUST NOT ограничиваться: оно ничего не
меняет, а необъявленный ключ и так не будет найден.

#### Scenario: Необъявленный ключ

- **WHEN** шаг работы, объявившей `title`, выполняет `stepcast data set slug значение`
- **THEN** команда отказывает, называя работу, ключ и объявленный состав, и файл данных остаётся прежним

#### Scenario: Объявленный ключ

- **WHEN** тот же шаг публикует объявленный ключ `title`
- **THEN** значение публикуется как прежде

#### Scenario: Работа без объявления

- **WHEN** шаг работы, не объявившей ни одного ключа, публикует любой ключ
- **THEN** запись отказывает, называя пустой объявленный состав

#### Scenario: Определение работы недоступно

- **WHEN** раскрытого определения работы в каталоге работы нет
- **THEN** запись отказывает, а не считается разрешённой, и отказ называет ожидавшийся путь, а не советует править объявление

### Requirement: В состояние прогона попадают только объявленные данные работы

Движок SHALL класть в запись работы `status.json` только те ключи файла данных, которые объявлены определением этой работы.

Запись мимо команды — прямо в файл данных — MUST NOT расширять состав видимых
данных: файловая система шагу доступна, и проверка одной лишь команды была бы
вежливостью, а не свойством устройства. Именно эта граница и защищает
`${jobs.<работа>.data.<ключ>}`, выражения `if` и витрину: все трое читают запись
работы, а не файл.

Обнаружив в файле данных необъявленный ключ, движок MUST провалить работу,
назвав в причине работу и ключ. Повторных попыток и эскалации шага это
MUST NOT вызывать: файл остался на месте, и повтор упёрся бы в то же самое,
переоплатив агентский шаг.

Сверка данных MUST NOT подменять собой исход самого шага: шаг, упавший по
`expect`, таймауту или бюджету, MUST сохранить свою причину и свою причину
остановки (`cause`), а нарушение объявления MUST дописываться к причине, а не
замещать её. Иначе статус работы разошёлся бы с фактом — тот же класс лжи,
который закрывало изменение `budget-stop-status-lies`.

Файл данных MUST оставаться на диске как есть: отказ отменяет действие записи,
а не её след. Объявленные ключи, опубликованные той же работой, MUST
сохраняться в её записи.

Сверяться движок MUST с определением работы, которым исполняет её сам, а не с
файлом определения в каталоге работы: иначе правка этого файла шагом расширяла
бы объявление.

#### Scenario: Запись в файл в обход команды

- **WHEN** шаг пишет в файл данных работы ключ, которого её определение не объявляет
- **THEN** работа отказывает с причиной, называющей работу и ключ, а шаг не повторяется

#### Scenario: Упавший шаг оставил необъявленный ключ

- **WHEN** шаг не прошёл `expect` и записал в файл данных необъявленный ключ
- **THEN** работа отказывает с причиной и `cause` самого шага, а нарушение объявления дописано к причине

#### Scenario: Перенос при возобновлении подчиняется новому объявлению

- **WHEN** исходный прогон опубликовал ключ, которого определение нового прогона больше не объявляет
- **THEN** перенос данных переиспользованной работы этот ключ отбрасывает

#### Scenario: Объявленное соседство сохраняется

- **WHEN** в том же файле рядом с необъявленным ключом лежит объявленный
- **THEN** объявленный присутствует в записи работы, а необъявленный — нет

#### Scenario: Подстановка не получает необъявленного значения

- **WHEN** работа ниже по графу подставляет ключ, который работа выше по графу записала в файл, но не объявляла
- **THEN** работа-производитель отказывает раньше, чем читатель дойдёт до подстановки, и необъявленное значение не попадает в область видимости ни при каком ходе прогона
