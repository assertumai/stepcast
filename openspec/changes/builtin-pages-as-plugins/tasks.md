## 8. Правки по итогам ревью

- [x] 8.1 Причина отказа сборки показывается пользователем, а не только
  лежит в сервисе: полоса над экраном в каркасе плюс браузерные проверки на
  оба сценария требования «Отказ сборки состава не гасит витрину».
- [x] 8.2 Состав без строки каркаса (`ui-shell` отключён патчем) разбирается
  как отказ сборки, а не роняет демон обращением к несуществующему сервису;
  отказ обработчика под `/api/` отвечает 500, а не необработанным отклонением
  промиса. Тест: демон отвечает встроенным составом и называет причину.
- [x] 8.3 `GET /api/screens` несёт признак происхождения строки (`builtin`);
  страница применяет встроенную половину только к строке поставки, а
  заменённый экран показывает причиной. Тесты с обеих сторон.
- [x] 8.4 Настройки и агенты отказывают с названной причиной, пока ни одна
  сборка не удалась, вместо того чтобы выдавать встроенные умолчания за
  конфигурацию пользователя (`src/ui/settings.ts`).
- [x] 8.5 Из каркаса и маршрутизатора ушли последние имена экранов:
  отслеживаемый прогон берётся из параметров адреса, `runHref` переехал к
  экрану прогона (`ui/src/screens/run.tsx`).
- [x] 8.6 Ключ, которого нет в слоте экранов, ведёт на экран по умолчанию
  действующего состава (`useDefaultScreenId` вызван), а не на заглушку.
- [x] 8.7 `ScreensService.register` отказывает на повторе `id`, называя обе
  строки, и снимает при разборе только свою запись.
- [x] 8.8 Сценарий «Владелец маршрута отключён» покрыт тестом на паре
  `screen-cleanup` → `screen-runs`.
- [x] 8.9 Перечень значений параметра объявляет сам экран (`paramValues`):
  `/usage/вчера` снова ведёт на экран по умолчанию, как вёл до перевода.
