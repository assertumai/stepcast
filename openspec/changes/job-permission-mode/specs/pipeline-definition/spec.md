## ADDED Requirements

### Requirement: Режим применения прав принимается и проверяется статически

Файл работы и шаг SHALL принимать в блоке `permissions` поле `enforce` со значениями `inherit` и `strict`; отсутствие поля равнозначно `inherit`.
Иное значение MUST отклоняться разбором как структурная ошибка. Объявление
ближайшего уровня MUST побеждать: шаг сильнее работы, работа сильнее
конфигурации бэкенда.

`stepcast lint` MUST отклонять ошибкой сочетание `enforce: strict` с режимом
бэкенда, разрешающим неназванное по умолчанию, и `enforce: strict` на бэкенде,
не объявившем поддержку жёсткого режима. Диагностика MUST называть место
объявления — файл и точечный путь поля.

Режим MUST переноситься в раскрытый пайплайн и в `pipeline.lock.yml` наравне с
остальной политикой доступа: иначе по фиксации прогона нельзя восстановить,
действовала ли граница.

#### Scenario: Значение принято

- **WHEN** шаг объявляет `permissions.enforce: strict`
- **THEN** пайплайн разбирается, а раскрытый пайплайн и `pipeline.lock.yml` несут это значение

#### Scenario: Неизвестное значение отклоняется

- **WHEN** шаг объявляет `permissions.enforce` со значением вне перечня
- **THEN** разбор завершается ошибкой, называющей поле и допустимые значения

#### Scenario: Шаг сужает режим работы

- **WHEN** работа объявляет `enforce: inherit`, а её шаг — `enforce: strict`
- **THEN** шаг исполняется в жёстком режиме

#### Scenario: Противоречивое сочетание с разрешающим режимом

- **WHEN** объявление несёт `enforce: strict` и режим бэкенда, разрешающий неназванное по умолчанию
- **THEN** `stepcast lint` завершается ошибкой, называя оба поля и место объявления

#### Scenario: Жёсткий режим на бэкенде без поддержки

- **WHEN** работа объявляет `enforce: strict`, а её бэкенд не объявляет поддержку жёсткого режима
- **THEN** `stepcast lint` завершается ошибкой до начала прогона
