## ADDED Requirements

### Requirement: Витрина показывает каталог доступных шагов

Витрина SHALL показывать отдельным экраном каталог переиспользуемых шагов, доступных проекту: имя, описание, слой, объявленные параметры и наличие схемы выхода.

Каждый параметр MUST показываться именем, типом, обязательностью, умолчанием и
описанием — теми же сведениями, которыми манифест их объявил. Шаг без
параметров MUST быть показан шагом без параметров, а не шагом без данных.

Каталог MUST собираться теми же тремя слоями, какими имя разрешает раскрытие, и
MUST называть слой каждого шага. Шаг нижнего слоя, перекрытый одноимённым шагом
верхнего, MUST быть отмечен перекрытым, а не пропущен молча: перекрытие —
самая дорогая неожиданность трёхслойного разрешения.

Каталог MUST оставаться читаемым при отсутствии каталогов шагов у проекта и в
домашнем каталоге: встроенные шаги пакета доступны всегда.

Шаг с дефектным манифестом MUST быть показан с причиной, по которой он не
разрешается, а не выпадать из каталога: иначе автор ищет пропавший шаг вслепую.

#### Scenario: Каталог перечисляет шаги трёх слоёв

- **WHEN** проект объявляет свой шаг, а пакет поставляет встроенный
- **THEN** экран показывает оба, называя слой каждого

#### Scenario: Параметры видны с типами и умолчаниями

- **WHEN** манифест объявляет параметр с типом, описанием и умолчанием
- **THEN** карточка шага показывает имя параметра, тип, обязательность, умолчание и описание

#### Scenario: Перекрытый шаг отмечен

- **WHEN** одноимённый шаг есть и в проекте, и в домашнем каталоге
- **THEN** экран показывает шаг проекта действующим, а домашний — перекрытым

#### Scenario: Чистый проект

- **WHEN** у проекта нет каталога `.stepcast/steps/`
- **THEN** экран показывает встроенные шаги пакета, а не пустой список

#### Scenario: Дефектный манифест

- **WHEN** манифест шага не читается либо не проходит схему
- **THEN** шаг показан с причиной отказа и файлом манифеста

### Requirement: Карточка переиспользуемого шага называет имя, слой и параметры

Карточка шага `uses` — и на экране пайплайнов, и на странице прогона — SHALL называть имя шага, слой, из которого он разрешён, и переданные ему параметры.

Имя MUST показываться вместо абсолютного пути файла: путь в чужой
`node_modules` не говорит читателю ничего, а имя — говорит. Путь и раннер MUST
оставаться доступными, но не занимать место имени.

Параметры MUST показываться так, как они попали в файл фиксации, — с
применёнными умолчаниями; значение, оставшееся отложенной подстановкой, MUST
показываться выражением, а окончательные значения прогона MUST быть доступны
через файл входа шага, который витрина уже умеет раскрывать.

#### Scenario: Шаг назван именем

- **WHEN** прогон исполнил шаг `uses: changed-files` из встроенного слоя
- **THEN** карточка шага называет имя и слой, а не только абсолютный путь файла

#### Scenario: Переданные параметры видны

- **WHEN** шаг объявлен с `with: { ref: HEAD }`
- **THEN** карточка показывает параметр и его значение

#### Scenario: Отложенное значение параметра

- **WHEN** параметр объявлен как `"${jobs.plan.output.item}"`
- **THEN** карточка показывает выражение, а окончательное значение доступно раскрытием файла входа шага
