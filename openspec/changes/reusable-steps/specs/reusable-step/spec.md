## ADDED Requirements

### Requirement: Переиспользуемый шаг — каталог с манифестом

Переиспользуемый шаг SHALL быть каталогом `<имя>/` с манифестом `step.yml` внутри, и весь код и все схемы шага SHALL лежать внутри этого каталога.

Манифест MUST быть документом с `version: 1` и `kind: step` — тем же образцом,
каким объявлены документы пайплайна и работы. Он MUST объявлять `name`
(имя шага), `description` (одна-две фразы о том, зачем шаг нужен) и `file`
(файл со своим кодом). Он MAY объявлять `params` (схему параметров),
`output_schema` (схему выхода) и `runner` (имя записи таблицы раннеров).
Незнакомое поле MUST отклоняться разбором с указанием файла.

Значение `name` MUST совпадать с именем каталога; расхождение MUST быть
ошибкой, называющей и имя каталога, и имя в манифесте.

Каталог без `step.yml` MUST считаться не каталогом шага, а посторонним
каталогом: слой просматривается дальше, как и при отсутствующем каталоге.

#### Scenario: Каталог с манифестом — шаг

- **WHEN** в `.stepcast/steps/changed-files/` лежит `step.yml` с `name: changed-files`, `description`, `file: ./main.mjs`
- **THEN** шаг `changed-files` доступен пайплайнам проекта

#### Scenario: Имя не совпадает с каталогом

- **WHEN** в каталоге `.stepcast/steps/changed-files/` манифест объявляет `name: list-changes`
- **THEN** `stepcast lint` завершается ошибкой, называя оба имени и файл манифеста

#### Scenario: Каталог без манифеста

- **WHEN** в `.stepcast/steps/` проекта есть каталог `notes/` без `step.yml`, а в домашнем слое есть `notes/step.yml`
- **THEN** имя `notes` разрешается шагом домашнего слоя

#### Scenario: Незнакомое поле манифеста

- **WHEN** манифест объявляет поле, не описанное форматом
- **THEN** разбор отклоняет манифест, называя файл и поле

### Requirement: Имя шага разрешается тремя слоями

Имя переиспользуемого шага SHALL разрешаться тремя слоями в порядке убывания приоритета: `<корень проекта>/.stepcast/steps/`, `~/.stepcast/steps/`, встроенный каталог шагов пакета stepcast.

Первый слой, где лежит каталог с манифестом, MUST побеждать; слои ниже MUST
просматриваться только пока шаг не найден. Встроенный слой MUST находиться от
расположения самого движка, а не от каталога запуска, — чтобы имя разрешалось
одинаково из исходников, из `dist/`, из `node_modules` целевого проекта и из
глобальной установки.

Имя MUST быть одним сегментом из строчных латинских букв, цифр и дефисов.
Значение с разделителем пути (`/`) MUST отклоняться отдельным сообщением,
называющим форму `автор/имя` неподдерживаемой, а не просто недопустимым
символом. Значение с явным префиксом `./`, `../` либо абсолютное MUST
отклоняться с подсказкой, что файл по пути объявляется шагом `script`.

Ненайденное имя MUST давать отказ, перечисляющий просмотренные каталоги.

#### Scenario: Проектный слой перекрывает домашний

- **WHEN** шаг `changed-files` есть и в `.stepcast/steps/` проекта, и в `~/.stepcast/steps/`
- **THEN** исполняется шаг проекта

#### Scenario: Встроенный слой доступен без каталогов проекта

- **WHEN** проект не имеет каталога `.stepcast/steps/`, а пайплайн объявляет `uses: changed-files`
- **THEN** разрешается встроенный шаг пакета

#### Scenario: Имя не найдено

- **WHEN** пайплайн объявляет `uses: no-such-step`
- **THEN** `stepcast lint` завершается ошибкой, называя имя шага и перечень просмотренных каталогов

#### Scenario: Имя с пространством автора

- **WHEN** пайплайн объявляет `uses: alice/lint-fix`
- **THEN** разбор отклоняет значение, называя форму `автор/имя` пока неподдерживаемой

#### Scenario: Путь вместо имени

- **WHEN** пайплайн объявляет `uses: ./tools/cleanup/step.yml`
- **THEN** разбор отклоняет значение с подсказкой объявить файл шагом `script`

### Requirement: Схема параметров описывает объект with целиком

Ключ `params` манифеста SHALL быть JSON Schema, описывающей объект `with` целиком, и MUST быть объектной схемой — `type: object` с `properties`.

Описание каждого параметра MUST допускать `description`, `default` и любой тип,
представимый в JSON, включая объект и список. Обязательность параметра MUST
объявляться списком `required` той же схемы. Схема, не являющаяся объектной,
MUST отклоняться с указанием файла манифеста: без `properties` ни назвать
неизвестный параметр по имени, ни показать перечень параметров нечем.

Дефектная схема MUST быть названа при чтении манифеста — ошибкой с именем шага
и файлом, а не исключением первого прогона.

Манифест без `params` MUST означать шаг без параметров: любое непустое `with`
на месте вызова у такого шага MUST быть ошибкой.

#### Scenario: Параметр объявлен с описанием и умолчанием

- **WHEN** манифест объявляет `params` с `properties.ref: { type: string, default: HEAD, description: ... }`
- **THEN** шаг принимает параметр `ref`, а его умолчание и описание доступны линту и витрине

#### Scenario: Параметр-объект

- **WHEN** манифест объявляет `properties.item: { type: object }`
- **THEN** значение `with.item` принимается объектом и уезжает в `input.json` объектом

#### Scenario: Схема параметров не объектная

- **WHEN** манифест объявляет `params: { type: array }`
- **THEN** чтение манифеста отклоняет схему, называя файл

#### Scenario: Дефектная схема параметров

- **WHEN** `params` не компилируется как JSON Schema
- **THEN** `stepcast lint` завершается ошибкой, называя шаг и файл манифеста

#### Scenario: Шаг без параметров

- **WHEN** манифест не объявляет `params`, а место вызова передаёт `with: { slug: bug-42 }`
- **THEN** `stepcast lint` завершается ошибкой, называя параметр необъявленным

### Requirement: Параметры вызова сводятся со схемой параметров

Переданные `with` значения SHALL сводиться со схемой параметров манифеста: неизвестное имя и непереданный обязательный параметр — отказ, недостающее значение с объявленным `default` — подстановка умолчания.

Неизвестный параметр MUST называться отдельным сообщением с перечнем
объявленных, а не замечанием валидатора схемы; непереданный обязательный —
сообщением, называющим параметр. Оба MUST называть имя шага и файл манифеста.

Умолчания MUST применяться при раскрытии пайплайна, до записи файла фиксации,
чтобы в записи шага лежал полный набор параметров.

Сведённый набор параметров MUST становиться входом контракта шага —
`input.json` — целиком и без изменений.

#### Scenario: Неизвестный параметр

- **WHEN** место вызова передаёт `with: { slag: bug-42 }` при объявленном `slug`
- **THEN** `stepcast lint` завершается ошибкой «параметр не объявлен» с перечнем объявленных, именем шага и файлом манифеста

#### Scenario: Непереданный обязательный параметр

- **WHEN** манифест объявляет `required: [slug]`, а `with` его не содержит
- **THEN** `stepcast lint` завершается ошибкой, называющей параметр

#### Scenario: Умолчание подставляется

- **WHEN** параметр `ref` объявлен с `default: HEAD` и не передан
- **THEN** шаг получает `ref: HEAD` во входе, и то же значение видно в файле фиксации

#### Scenario: Значение не по схеме

- **WHEN** параметр объявлен `{ type: int }`, а передана строка `"позже"`
- **THEN** проверка завершается ошибкой с замечанием валидатора, именем шага и параметра

### Requirement: Пути внутри манифеста разрешаются от каталога шага

Значения `file` и `output_schema` манифеста SHALL разрешаться относительно каталога шага и MUST NOT выходить за его пределы.

Слои разрешения внутри манифеста MUST NOT применяться: голое имя в `file` — это
файл в каталоге шага, а не имя, которое ищут слоями. Значение, уводящее за
пределы каталога (`../`, абсолютный путь), MUST отклоняться с указанием файла
манифеста. Форма `stepcast:<имя>` у `output_schema` MUST сохранять прежнее
значение — схему, поставляемую пакетом.

Отсутствующий файл `file` MUST быть ошибкой, называющей шаг и ожидаемый путь.

Раннер MUST выбираться теми же тремя правилами, что и у шага `script`: явный
`runner` манифеста, расширение файла, имя из shebang.

Промах, объявленный манифестом — неизвестное имя раннера, раннер, не
определимый ни расширением, ни shebang, отсутствующий файл схемы выхода, — MUST
называть местом объявления сам манифест, а не документ пайплайна: ключей
`runner`, `script` и `output_schema` у шага `uses` в документе нет вовсе.

#### Scenario: Файл рядом с манифестом

- **WHEN** манифест объявляет `file: ./main.mjs`
- **THEN** исполняется `main.mjs` из каталога шага

#### Scenario: Файл за пределами каталога

- **WHEN** манифест объявляет `file: ../../tools/cleanup.py`
- **THEN** чтение манифеста отклоняет значение, называя файл манифеста

#### Scenario: Схема выхода рядом с манифестом

- **WHEN** манифест объявляет `output_schema: ./output.schema.json`
- **THEN** выход шага проверяется этой схемой

#### Scenario: Раннер по расширению

- **WHEN** манифест объявляет `file: ./main.py` и не объявляет `runner`
- **THEN** раннер выбирается расширением по таблице раннеров

#### Scenario: Неизвестный раннер манифеста

- **WHEN** манифест объявляет `runner: nosuch`
- **THEN** `stepcast lint` завершается ошибкой, называющей работу, шаг и файл манифеста, а не ключ `runner` документа пайплайна

#### Scenario: Схема выхода манифеста не найдена

- **WHEN** манифест объявляет `output_schema: ./output.schema.json`, а файла рядом нет
- **THEN** `stepcast lint` завершается ошибкой, называющей файл манифеста, а не ключ `output_schema` документа пайплайна

### Requirement: Встроенный переиспользуемый шаг поставляется пакетом

Пакет stepcast SHALL поставлять хотя бы один переиспользуемый шаг образцом, и этот шаг MUST работать без каталогов `.stepcast/steps/` в проекте и в домашнем каталоге.

Образец MUST опираться только на контракт файлов — переменные окружения и
разбор JSON — и MUST NOT зависеть ни от библиотеки шага `stepcast/step`, ни от
обёртки раннера: он обязан исполняться одинаково из глобальной установки, из
`node_modules` целевого проекта и из исходников, включая проект,
переопределивший раннер `node`.

Образец MUST объявлять и схему параметров, и схему выхода — иначе он не
показывает того, ради чего манифест заведён.

#### Scenario: Встроенный шаг доступен из чистого проекта

- **WHEN** пайплайн проекта без каталога `.stepcast/steps/` объявляет `uses: changed-files`
- **THEN** шаг разрешается встроенным слоем и исполняется

#### Scenario: Встроенный шаг не зависит от обёртки

- **WHEN** проект переопределил раннер `node` со снятой обёрткой (`wrapper: none`)
- **THEN** встроенный шаг исполняется и отдаёт выход по своей схеме

#### Scenario: Выход образца проверяется схемой

- **WHEN** встроенный шаг завершился успешно
- **THEN** его выход соответствует объявленной схеме и доступен как выход шага

### Requirement: Формат манифеста публикуется JSON Schema

Пакет SHALL публиковать JSON Schema манифеста переиспользуемого шага рядом со схемами пайплайна, работы и конфигурации.

Схема MUST печататься из той же модели, которой манифест проверяется при
чтении, и MUST проверяться на свежесть тем же способом, что и остальные
публикуемые схемы.

#### Scenario: Схема манифеста опубликована

- **WHEN** пакет напечатал JSON Schema документов
- **THEN** среди них есть схема манифеста шага с полями `name`, `description`, `file`, `params`, `output_schema`, `runner`

#### Scenario: Схема манифеста свежа

- **WHEN** модель манифеста изменена без перегенерации схем
- **THEN** проверка свежести опубликованных схем падает
