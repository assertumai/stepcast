## ADDED Requirements

### Requirement: Витрина показывает расход

Обзор SHALL показывать по каждому прогону его расход — величину токенов, идущую в бюджет, и затраченное время. При раскрытии прогона дашборд SHALL показывать расход каждой работы и каждого её шага, включая число попыток шага. Измерения, не сообщённые бэкендом, MUST помечаться как несообщённые и MUST NOT показываться нулём. Расход MUST браться из состояния прогона и сводки расхода, а новых точек HTTP-API для этого MUST NOT заводиться.

#### Scenario: Расход прогона в обзоре

- **WHEN** пользователь открывает обзор
- **THEN** каждый прогон показан со своим расходом токенов и затраченным временем

#### Scenario: Расход работы и шага

- **WHEN** пользователь раскрывает прогон
- **THEN** у каждой работы и каждого её шага показан расход, а у шага — ещё и число попыток

#### Scenario: Несообщённое измерение в витрине

- **WHEN** бэкенд не сообщил одно из измерений расхода
- **THEN** витрина показывает на его месте признак «не сообщено», а не ноль

#### Scenario: Прогон без записанной сводки

- **WHEN** прогон ещё идёт и `usage.json` не записан
- **THEN** витрина показывает расход по уже записанным попыткам и не показывает прогон сломанным

#### Scenario: Расход убранного прогона

- **WHEN** пользователь раскрывает прогон, убранный `stepcast gc`
- **THEN** его расход по работам и шагам по-прежнему показан, наряду с объяснением, что остальные подробности убраны
