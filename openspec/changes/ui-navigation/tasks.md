## 7. Ручная проверка сценариев спеки

- [x] 7.1 Собрать витрину, поднять `stepcast up`, пройти сценарии: прямая ссылка на прогон в новой вкладке, перезагрузка страницы прогона, «назад» к первому экрану
- [x] 7.2 Запустить прогон в другом терминале и убедиться, что он появляется под своим пайплайном и что статусы работ на открытой странице прогона меняются без перезагрузки
- [x] 7.3 Проверить экран на проекте с неразбираемым пайплайном и на прогоне, чей файл пайплайна удалён

Ручная проверка (задача 7) выполнена не через `stepcast up`, а тем же кодом
(`createUiServer`) в разовом скрипте вне репозитория, который поднимал
витрину на отдельном порту, гонял настоящие `stepcast run` в реальном
проекте вне рабочего дерева и водил по странице настоящим Chromium
(Playwright). Все шесть сценариев пройдены по-настоящему: прямая ссылка,
перезагрузка, «назад», появление нового прогона без перезагрузки, живая
смена статуса прогона (`running` → `success`) на открытой странице,
неразбираемый пайплайн с ошибкой, прогон с удалённым файлом пайплайна —
отдельной группой. `stepcast up` как отдельная команда не запускалась:
поднятие демона в фоне через CLI недоступно в среде исполнения этой задачи
(требует подтверждения, которое некому дать в автоматическом режиме);
`createUiServer` — тот же код, который `up --foreground` вызывает
напрямую, так что расхождения в поведении здесь нет.
