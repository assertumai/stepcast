## Why

Витрина, которую видит пользователь на 7717, собрана из кода, которого в
рабочей ветке нет. Серверная половина уже здесь и работает: `src/ui/graph.ts`,
`src/ui/pipelines.ts`, `src/ui/settings.ts`, маршрут `GET /api/pipelines`,
отдача страницы на любой не-API адрес и поток `GET /api/events?run=<адрес>`
со снимком одного прогона. А клиентская половина заперта на ветке
`draft/ui-vite-dashboard`, чей коммит подписан «не проверялась и не
ревьюилась» и который отстал от рабочей ветки на тринадцать коммитов.

Из этого следуют три вещи. Единственная существующая витрина держится на
`dist/ui-web/index.html` — файле в `.gitignore`, который в рабочей ветке
пересобрать нечем: vite-скриптов в её `package.json` нет. Несобранная витрина
отвечает `503` и называет команду `npm run build:ui`, которой не существует —
`src/ui/server.ts:383` отсылает пользователя к несуществующему скрипту. И
любая правка фронта сегодня начинается с ветки, чей код не проходил ни
ревью, ни `npm run check`.

## What Changes

- **Исходники витрины и её сборка переезжают в рабочую ветку.** `ui/` с
  исходниками на React и TypeScript, `ui/tsconfig.json`, `vite.config.ts`;
  `vite-plugin-singlefile` собирает один самодостаточный
  `dist/ui-web/index.html`, и демон по-прежнему отдаёт одну страницу, не
  становясь файловым сервером с разбором MIME и защитой от обхода путей.
- **`npm run check` проверяет и витрину.** Типизация `ui/` своим
  `tsconfig`, линт по `ui`, и сборка фронта в составе `npm run build` — иначе
  «собирается одной командой» проверялось бы только тем, что кто-то однажды
  собрал её руками у себя.
- **Первый экран — пайплайны с их прогонами.** Запускают пайплайн, а не
  прогон, и первым вопросом к витрине стоит «что у меня есть и чем это
  кончилось». Пайплайны приходят из `GET /api/pipelines`, прогоны — из
  обзора, склейка идёт по проекту и имени пайплайна. Прогон, чьего файла
  пайплайна больше нет, остаётся видимым отдельной группой, а не исчезает.
- **Прогон открывается собственной страницей по собственному адресу.**
  `/runs/<проект>/<прогон>` переживает перезагрузку, годится для ссылки и
  открытия в новой вкладке, «назад» работает браузерными средствами.
  Маршрутизация — History API, разбор адреса — общий с сервером модуль
  `src/ui/routes.ts`: адрес страницы прогона это контракт между тем, кто
  отдаёт страницу на этот путь, и тем, кто её на этом пути разбирает.
- **Живое обновление действует на обоих экранах.** Страница прогона
  подписывается на `GET /api/events?run=<адрес>` и получает свой снимок тем
  же потоком, что и обзор, — а не перезапрашивает `GET /api/run` на каждое
  изменение обзора, как это делает заготовка на ветке.
- **Несобранная витрина называет команду, которая существует.** Отказ `503`
  и `npm run build:ui` сходятся в одной точке: скрипт заводится этим же
  изменением, и тест держит их вместе.
- **Не входит:** экран настроек, корзинка и групповое удаление в интерфейсе
  (серверная часть описана изменением `ui-run-deletion`), разрез токенов по
  видам в таблице. Заготовка на ветке их содержит; сюда они не переносятся —
  каждая из них требует своих требований и своего ревью, а этот пункт про
  две страницы, названные в его заголовке.

## Capabilities

### New Capabilities
- `ui-build`: исходники витрины в репозитории, сборка одной командой в один
  самодостаточный артефакт и охват этих исходников проверкой проекта.

### Modified Capabilities
- `ui-dashboard`: первый экран показывает пайплайны с их прогонами; прогон
  открывается собственной страницей по собственному адресу; живое обновление
  распространяется на страницу прогона и идёт одним потоком.
- `ui-daemon`: витрина отдаётся на любой не-API адрес, а отсутствие маршрута
  под `/api/` называется ошибкой; несобранная витрина отвечает отказом,
  называющим действующую команду сборки, не задевая API.

## Impact

- Новое: `ui/` (исходники витрины), `ui/tsconfig.json`, `vite.config.ts`,
  `src/ui/routes.ts` (разбор адресов, общий с сервером).
- `package.json`: `build:node`, `build:ui`, `build`, `dev:ui`,
  `typecheck:ui`; `lint` и `check` расширяются на `ui`. Зависимости сборки —
  `vite`, `@vitejs/plugin-react`, `vite-plugin-singlefile`, `react`,
  `react-dom` и их типы, все в `devDependencies`: в пакет уезжает `dist`, а
  не исходники.
- `eslint.config.js`: `ui` под линтом, с `.tsx` и браузерным окружением.
- `src/ui/server.ts`: отдача страницы и отказ несобранной витрины — через
  общий разбор адресов; сама маршрутизация уже написана.
- `docs/status.md`: строка о витрине и снятие ограничения «Страница витрины
  из репозитория не собирается» — фрагментом `openspec/changes/ui-navigation/status.md`.
- `README.md`: шаг сборки витрины рядом с `stepcast up`.
- Движок исполнения не затрагивается: изменение показывает уже записанное.
