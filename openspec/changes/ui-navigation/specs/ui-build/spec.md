## ADDED Requirements

### Requirement: Витрина собирается из исходников репозитория одной командой

Исходники витрины SHALL лежать в репозитории, и сборка витрины SHALL выполняться одной командой `npm` без ручных шагов. Собранная витрина MUST быть единственным самодостаточным файлом `dist/ui-web/index.html` со встроенными скриптами, стилями и прочими ресурсами: демон отдаёт одну страницу и MUST NOT становиться файловым сервером. Полная сборка проекта (`npm run build`) MUST собирать и витрину, а не только код на Node. Собранная витрина MUST NOT попадать в git — она пересобирается из исходников.

#### Scenario: Сборка в свежем клоне

- **WHEN** в свежем клоне репозитория после установки зависимостей выполнена команда сборки витрины
- **THEN** появляется `dist/ui-web/index.html`, и `stepcast up` отдаёт эту страницу

#### Scenario: Единственный файл

- **WHEN** витрина собрана
- **THEN** страница работает без обращения к другим файлам сборки, а демон не отдаёт ничего, кроме неё и ответов `/api/`

#### Scenario: Полная сборка включает витрину

- **WHEN** выполнена полная сборка проекта
- **THEN** собран и код на Node, и витрина

### Requirement: Проверка проекта охватывает исходники витрины

Команда `npm run check` SHALL проверять исходники витрины наравне с исходниками движка: типизацией по конфигурации витрины, линтом и сборкой витрины. Ошибка типизации, ошибка линта или несобираемая витрина MUST делать `npm run check` красным. Проверка MUST NOT зависеть от того, собирал ли кто-то витрину на этой машине раньше.

#### Scenario: Ошибка в исходниках витрины красит проверку

- **WHEN** в исходниках витрины появилась ошибка типизации или линта
- **THEN** `npm run check` завершается неуспешно и называет файл

#### Scenario: Проверка на чистом дереве

- **WHEN** `npm run check` выполняется там, где витрина ни разу не собиралась
- **THEN** проверка собирает витрину сама и проходит, не требуя ручных шагов
