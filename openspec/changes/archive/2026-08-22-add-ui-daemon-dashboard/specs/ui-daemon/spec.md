## ADDED Requirements

### Requirement: Команда поднимает фоновый наблюдатель

Команда `stepcast up` SHALL запускать фоновый локальный HTTP-сервер,
наблюдающий за корнем прогонов целиком, печатать URL дашборда и возвращать
управление, не занимая терминал. Сервер MUST слушать только `127.0.0.1`.

#### Scenario: Демон поднят и напечатан адрес

- **WHEN** `stepcast up` вызвана, а демон ещё не запущен
- **THEN** поднимается фоновый сервер на порту из `ui.port`, печатается его URL, команда завершается кодом 0

#### Scenario: Терминал не занят

- **WHEN** `stepcast up` завершилась успешно
- **THEN** сервер продолжает работать, а вызвавший терминал свободен для следующей команды

#### Scenario: Доступ только с локальной машины

- **WHEN** демон поднят
- **THEN** он принимает соединения на `127.0.0.1` и не слушает внешние сетевые интерфейсы

#### Scenario: Наблюдение начинается без единого прогона

- **WHEN** `stepcast up` вызвана на машине, где прогонов ещё не было
- **THEN** демон поднимается и показывает пустой обзор, а не завершается ошибкой

### Requirement: Повторный запуск не поднимает второго демона

Команда `stepcast up` SHALL определять уже поднятый демон по pid-файлу и в этом
случае печатать его состояние — URL, идентификатор процесса и время старта, —
завершаясь кодом 0, вместо запуска второго сервера. Осиротевший pid-файл, чей
процесс не существует, MUST NOT мешать запуску: он перезаписывается. Если порт
занят посторонним процессом, команда SHALL завершиться внятной ошибкой,
называющей порт и настройку `ui.port`, и MUST NOT молча выбирать другой порт.

#### Scenario: Демон уже поднят

- **WHEN** `stepcast up` вызвана повторно, а прошлый демон жив
- **THEN** печатается URL, идентификатор процесса и время старта работающего демона, второй сервер не поднимается, код возврата 0

#### Scenario: Осиротевший pid-файл

- **WHEN** pid-файл остался от процесса, которого больше нет
- **THEN** файл перезаписывается и демон поднимается как обычно

#### Scenario: Порт занят посторонним процессом

- **WHEN** порт из `ui.port` занят процессом, не являющимся демоном stepcast
- **THEN** команда завершается ошибкой, называющей порт и настройку, не поднимая сервер на другом порту

### Requirement: Демон останавливается отдельной командой

Команда `stepcast down` SHALL останавливать поднятый демон и удалять его
pid-файл. Вызов при отсутствии работающего демона SHALL сообщать об этом и
завершаться кодом 0, а не ошибкой.

#### Scenario: Остановка работающего демона

- **WHEN** `stepcast down` вызвана при поднятом демоне
- **THEN** процесс демона завершается, порт освобождается, pid-файл удаляется

#### Scenario: Останавливать нечего

- **WHEN** `stepcast down` вызвана, когда демон не запущен
- **THEN** команда сообщает, что демон не работает, и завершается кодом 0

### Requirement: Наблюдатель работает и в текущем терминале

Команда `stepcast up --foreground` SHALL запускать тот же сервер в текущем
процессе, не отсоединяя его и не записывая pid-файл фонового демона, — чтобы
поведение при отладке совпадало с поведением в фоне.

#### Scenario: Запуск без отсоединения

- **WHEN** `stepcast up --foreground` вызвана
- **THEN** сервер работает в текущем терминале и завершается вместе с ним по сигналу прерывания

### Requirement: Состояние прогона и состояние демона не смешиваются

Команда `stepcast status` MUST сохранить своё нынешнее значение — состояние
прогона — и MUST NOT начать отвечать о демоне: ни при вызове без флагов, ни
новым флагом. Сведения о демоне SHALL сообщаться повторным вызовом
`stepcast up`.

#### Scenario: Поведение status не изменилось

- **WHEN** `stepcast status` вызвана без флагов при поднятом демоне
- **THEN** она показывает состояние последнего прогона проекта, как и до появления демона

#### Scenario: Сведения о демоне доступны через up

- **WHEN** пользователю нужно узнать, работает ли демон и на каком порту
- **THEN** эти сведения печатает повторный вызов `stepcast up`

### Requirement: Наблюдение не изменяет журнал

Демон MUST только читать файлы под корнем прогонов: он MUST NOT изменять,
создавать или удалять файлы прогонов. Собственное состояние демона
(pid-файл и лог) MUST лежать вне каталогов прогонов.

#### Scenario: Файлы прогона не тронуты

- **WHEN** демон наблюдал за прогоном и был остановлен
- **THEN** файлы этого прогона остались теми же, какими их записал движок
