## ADDED Requirements

### Requirement: Разрешение конфигурации из двух файлов

Система SHALL собирать действующую конфигурацию из встроенных умолчаний,
глобального файла `~/.stepcast/config.yml`, проектного файла `.stepcast/config.yml` и
флагов командной строки. Каждый следующий источник MUST перекрывать
предыдущий. Отсутствие любого из файлов MUST NOT быть ошибкой.

#### Scenario: Проектный конфиг перекрывает глобальный

- **WHEN** в глобальном конфиге `defaults.model: sonnet`, а в проектном `defaults.model: opus`
- **THEN** действующее значение `defaults.model` равно `opus`

#### Scenario: Флаг перекрывает оба файла

- **WHEN** оба конфига задают `defaults.model`, а запуск выполнен с `--model haiku`
- **THEN** действующее значение `defaults.model` равно `haiku`

#### Scenario: Конфигов нет

- **WHEN** ни `~/.stepcast/config.yml`, ни `.stepcast/config.yml` не существуют
- **THEN** система работает на встроенных умолчаниях без ошибки

### Requirement: Запреты складываются и не отменяются снизу

Списки `env_deny` и `context.deny` SHALL объединяться со всех уровней —
глобального конфига, проектного конфига и пайплайна. Нижний уровень MUST NOT
иметь возможности удалить шаблон, объявленный выше.

#### Scenario: Пайплайн добавляет запрет

- **WHEN** глобальный конфиг задаёт `env_deny: ["AWS_*"]`, а пайплайн `env_deny: ["FOO_*"]`
- **THEN** действуют оба шаблона

#### Scenario: Пайплайн не может снять запрет

- **WHEN** глобальный конфиг задаёт `env_deny: ["AWS_*"]`, а пайплайн задаёт пустой `env_deny: []`
- **THEN** шаблон `AWS_*` остаётся действующим

### Requirement: Потолки limits ограничивают пайплайн

Значения `limits` из конфигурации SHALL задавать верхнюю границу для
соответствующих значений пайплайна. Пайплайн, превышающий потолок, MUST
отклоняться с ошибкой, а не урезаться молча.

#### Scenario: Бюджет пайплайна выше потолка

- **WHEN** конфиг задаёт `limits.tokens: 5M`, а пайплайн `budget.tokens: 8M`
- **THEN** `stepcast lint` завершается ошибкой с указанием обоих значений
- **AND** `stepcast run` не начинает прогон

#### Scenario: Число попыток выше потолка

- **WHEN** конфиг задаёт `limits.attempts: 5`, а шаг `attempts.max: 9`
- **THEN** `stepcast lint` завершается ошибкой

### Requirement: Проектный конфиг не содержит машинно-зависимых значений

Ключи `runs.root` и `backends.*.command` SHALL приниматься только в глобальном
конфиге. Их присутствие в проектном конфиге MUST быть ошибкой.

#### Scenario: Путь к бэкенду в проектном конфиге

- **WHEN** `.stepcast/config.yml` содержит `backends.claude.command`
- **THEN** система завершается с ошибкой конфигурации и называет запрещённый ключ

### Requirement: Происхождение значений наблюдаемо

Команда `stepcast config` SHALL печатать действующую конфигурацию, указывая для
каждого значения источник, из которого оно получено. Для складывающихся списков
вывод MUST показывать вклад каждого источника.

#### Scenario: Отчёт о конфигурации

- **WHEN** пользователь выполняет `stepcast config`
- **THEN** для каждого ключа выводится значение и источник — встроенное умолчание, путь к файлу конфигурации или имя флага
- **AND** для `env_deny` выводится число шаблонов из каждого источника
