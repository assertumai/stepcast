## ADDED Requirements

### Requirement: Проверка результата шага предикатами

Шаг SHALL объявлять список предикатов `expect`. Все объявленные предикаты MUST
вычисляться, даже если один из них уже не прошёл. Попытка MUST считаться
непройденной, если не прошёл хотя бы один предикат.

#### Scenario: Все предикаты вычисляются

- **WHEN** шаг объявляет три предиката и первый не прошёл
- **THEN** остальные два всё равно вычисляются, а их результаты сохраняются

#### Scenario: Шаг без предикатов

- **WHEN** шаг не объявляет `expect`
- **THEN** попытка считается пройденной при нулевом коде возврата процесса

### Requirement: Предикат кода возврата

Предикат `exit_code` SHALL сравнивать код завершения процесса шага с
объявленным значением.

#### Scenario: Ожидаемый код

- **WHEN** объявлено `exit_code: 0`, а процесс завершился кодом 0
- **THEN** предикат пройден

#### Scenario: Неожиданный код

- **WHEN** объявлено `exit_code: 0`, а процесс завершился кодом 2
- **THEN** предикат не пройден, а в результате записаны ожидаемое и фактическое значения

### Requirement: Предикат наличия файла

Предикат `file_exists` SHALL проверять существование файла по пути,
разрешённому от корня рабочей директории работы.

#### Scenario: Файл создан шагом

- **WHEN** объявлено `file_exists: reports/plan.json`, и шаг создал этот файл
- **THEN** предикат пройден

#### Scenario: Файл отсутствует

- **WHEN** объявленный файл не существует после завершения шага
- **THEN** предикат не пройден, а в результате указан проверявшийся путь

### Requirement: Предикат соответствия схеме

Предикат `schema` SHALL проверять структурированный вывод шага на соответствие
JSON Schema из указанного файла. Отсутствие структурированного вывода MUST
считаться непрохождением.

#### Scenario: Вывод соответствует схеме

- **WHEN** структурированный вывод шага удовлетворяет схеме
- **THEN** предикат пройден

#### Scenario: Вывод нарушает схему

- **WHEN** структурированный вывод не удовлетворяет схеме
- **THEN** предикат не пройден, а в результате перечислены нарушения с путями к полям

#### Scenario: Структурированного вывода нет

- **WHEN** шаг не произвёл структурированного вывода, а предикат `schema` объявлен
- **THEN** предикат не пройден

### Requirement: Предикаты соответствия тексту

Предикаты `matches` и `not_matches` SHALL применять регулярное выражение к
текстовому результату шага. Для агентского шага текстовым результатом MUST
считаться итоговый текст ответа, для шага командной строки — его stdout.

#### Scenario: Ожидаемая подстрока в выводе команды

- **WHEN** шаг командной строки объявляет `matches` и его stdout содержит совпадение
- **THEN** предикат пройден

#### Scenario: Запрещённая подстрока в ответе агента

- **WHEN** агентский шаг объявляет `not_matches`, а итоговый текст ответа содержит совпадение
- **THEN** предикат не пройден

### Requirement: Предикат внешней команды

Предикат `cmd` SHALL исполнять указанную команду в рабочей директории работы и
считаться пройденным при нулевом коде возврата. Вывод команды MUST сохраняться
в результате проверок.

#### Scenario: Проверка сборкой

- **WHEN** предикат объявлен как `cmd: npx tsc --noEmit`, и команда завершилась кодом 0
- **THEN** предикат пройден

#### Scenario: Вывод неуспешной проверки сохранён

- **WHEN** команда предиката завершилась ненулевым кодом
- **THEN** предикат не пройден, а её вывод сохранён и доступен для эскалации следующей попытки

### Requirement: Результаты проверок фиксируются

Для каждой попытки система SHALL записывать в `expect.json` результат каждого
предиката: его вид, объявленные параметры, признак прохождения и подробности
непрохождения.

#### Scenario: Запись результатов

- **WHEN** попытка завершилась
- **THEN** `expect.json` содержит запись по каждому объявленному предикату, включая пройденные

### Requirement: Работа публикует один структурированный выход

Работа SHALL публиковать не более одного структурированного выхода. Ключ
`output.from` указывает шаг, чей структурированный вывод становится выходом
работы; схема необязательна. При отсутствии `from` выходом MUST считаться
структурированный вывод последнего агентского шага работы. Файл выхода MUST
записывать движок.

#### Scenario: Явно указанный шаг

- **WHEN** работа объявляет `output.from: review-self`
- **THEN** структурированный вывод этого шага публикуется как выход работы

#### Scenario: Умолчание по последнему агентскому шагу

- **WHEN** работа объявляет `output` без `from`
- **THEN** выходом становится структурированный вывод последнего исполненного агентского шага

#### Scenario: Работа без агентских шагов и без from

- **WHEN** работа объявляет `output` без `from` и не содержит агентских шагов
- **THEN** система завершается ошибкой валидации до начала прогона

### Requirement: Выход работы публикуется в артефактах

Опубликованный выход работы SHALL записываться в `artifacts/<job>.json`
директории прогона и MUST быть доступен последующим работам через выражение
`${jobs.<id>.output.*}` и через автоматический блок контекста.

#### Scenario: Публикация и чтение

- **WHEN** работа `plan` завершилась успехом и объявляла выход
- **THEN** файл `artifacts/plan.json` существует
- **AND** выражение `${jobs.plan.output.tasks}` разрешается в последующих работах

#### Scenario: Работа завершилась отказом

- **WHEN** работа завершилась отказом
- **THEN** её выход не публикуется, а обращение к `${jobs.<id>.output.*}` в условии считается неопределённым и делает условие ложным
