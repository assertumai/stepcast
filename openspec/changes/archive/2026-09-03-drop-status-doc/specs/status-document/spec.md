## REMOVED Requirements

### Requirement: Состояние реализации собирается из базы и фрагментов

**Reason**: Собранный документ был третьим учётом при двух существующих. Таблица «Работает» пересказывала статус `done` очереди, таблица «Пока нет» — пункты `pending`, а первичный ответ на вопрос «работает ли это» даёт сам движок: правило проекта запрещает тихую деградацию, и `stepcast lint`/`stepcast run` отклоняют нереализованное, называя причину. Гейт сверял собранное с записанным, а не записанное с кодом, — то есть расхождение пересказа с истиной ловить было нечем.

**Migration**: `docs/status.md` и `docs/status.base.md` удалены. Что сделано, а что нет, читается из очереди (`stepcast backlog list`) и из отказа движка. Раздел «Известные ограничения» и раздел «Примечания» перенесены в документы, описывающие оговариваемое поведение: `docs/pipeline-format.md`, `docs/run-layout.md`, `docs/config.md`, `docs/backlog.md`, `README.md`.

### Requirement: Фрагмент лежит в каталоге изменения

**Reason**: Знание о том, что изменения живут в `openspec/changes/<slug>/` и архивируются с датным префиксом `ГГГГ-ММ-ДД-`, было вшито в скрипт репозитория. Это последняя жёсткая привязка петли к устройству каталогов конкретного инструмента спецификаций: чужой репозиторий, ведущий изменения иначе, не получал от неё ничего.

**Migration**: Четырнадцать фрагментов `openspec/changes/*/status.md` удалены вместе со скриптом сборки. Изменение больше не кладёт рядом с собой файл состояния; его вклад в документацию — правка самих документов.

### Requirement: Разметка фрагмента

**Reason**: Собственная разметка — фиксированный перечень разделов, жирные лиды ключей, разделы «снято» — существовала только ради сборки. Без сборки разбирать нечего.

**Migration**: Оговорка о реализованном поведении пишется абзацем с жирным лидом прямо в разделе документа, описывающего это поведение. Ни ключей, ни разделов «снято» больше нет: снятие ограничения — удаление абзаца.

### Requirement: Порядок сборки не зависит от места фрагмента

**Reason**: Требование о детерминированности склейки относилось к сборке, которой больше нет.

**Migration**: Порядок абзацев в документе задаёт автор правки; воспроизводимость обеспечивается тем, что файл ведётся руками и лежит в git как есть.

### Requirement: Строка «Работает» складывается из клауз по ключу

**Reason**: Строка «Работает» была вторичным пересказом сделанного, и склейка клауз по ключу — механикой её накопления. Пересказ удалён целиком.

**Migration**: Сделанное отмечено в очереди статусом `done`; поведение описано в документах формата, а объявленное, но нереализованное движок отклоняет с причиной.

### Requirement: Строку «Пока нет» заводит ровно один источник

**Reason**: Таблица «Пока нет» дублировала очередь: несделанное лежит в ней пунктом с `why` и `done_when`. Четыре её строки указывали на текст, где то же сказано подробнее.

**Migration**: Секреты — раздел «Отложено» `docs/config.md`; `lint --budget` и `lint --resolve` — `docs/pipeline-format.md` и `docs/run-layout.md`; триггеры расписания — `docs/pipeline-format.md` и пункт очереди `schedule-trigger`; неизвестный бэкенд — отказ `stepcast lint`.

### Requirement: Снятие строк и блоков

**Reason**: Механика снятия чужой строки по ключу и чужого блока по лиду нужна была потому, что содержимое жило в разных файлах и сводилось сборкой. Содержимое живёт там, где описано поведение, и снимается обычной правкой.

**Migration**: Изменение, снявшее ограничение, удаляет абзац из документа, где он стоит.

### Requirement: Блок ограничения называет изменение

**Reason**: Строка `*Заведено изменением `<slug>`.*` проставлялась сборкой из имени каталога фрагмента. Авторство абзаца несёт `git log` — точнее и без ручной атрибуции в тексте.

**Migration**: При переносе блоков в документы строки атрибуции сняты.

### Requirement: Расхождение собранного с записанным ловится гейтом

**Reason**: Гейт стерёг согласованность генератора с его выходом — задача, исчезающая вместе с генератором. Согласованности документации с кодом он не проверял никогда.

**Migration**: `npm run status:check` и `npm run status:build` удалены из `package.json`, `status:check` убран из состава `npm run check`. Возврат механизма стережёт тест, падающий на упоминании удалённого документа в отслеживаемых файлах.

### Requirement: Собранный документ сводится объединением, а не конфликтом

**Reason**: Объявление `docs/status.md merge=union` существовало потому, что дорожки правили один сгенерированный файл. Файла нет — конфликтовать нечему; сами оговорки разъехались по четырём документам и разным их разделам, что снижает и вероятность встречной правки.

**Migration**: Строка `docs/status.md merge=union` и объясняющий её комментарий удалены из `.gitattributes`.
