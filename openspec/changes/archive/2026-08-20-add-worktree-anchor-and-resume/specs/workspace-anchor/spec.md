## ADDED Requirements

### Requirement: Состояние рабочего дерева фиксируется после каждого шага

После завершения каждого шага система SHALL фиксировать состояние рабочей
директории работы как единый идентификатор дерева и записывать его в `step.json`
полем `tree_id`. Фиксация MUST выполняться независимо от исхода шага, включая
отказ, отмену и превышение бюджета. Фиксация MUST NOT создавать записей в
истории проекта и MUST NOT изменять рабочую директорию.

#### Scenario: Якорь записан у успешного шага

- **WHEN** шаг завершился успехом
- **THEN** его `step.json` содержит непустой `tree_id`

#### Scenario: Якорь записан у упавшего шага

- **WHEN** шаг завершился отказом после исчерпания попыток
- **THEN** его `step.json` содержит `tree_id` состояния дерева на момент отказа

#### Scenario: История проекта не затронута

- **WHEN** прогон завершился в репозитории git
- **THEN** множество коммитов, ветки и текущая позиция `HEAD` не изменились
- **AND** индекс репозитория остаётся в том состоянии, в каком был до прогона

#### Scenario: Одинаковые деревья дают одинаковый якорь

- **WHEN** два шага завершились с посодержимо одинаковым рабочим деревом
- **THEN** их `tree_id` совпадают

### Requirement: Отказ фиксации якоря не останавливает прогон

Неудача при снятии якоря, вычислении диффа или чтении якоря SHALL записываться
в журнал и MUST NOT изменять статус шага, работы или прогона. Шаг, для которого
якорь снять не удалось, MUST получать пометку об отсутствии якоря с причиной и
MUST считаться непригодным для переиспользования при последующих
возобновлениях. Исполнение следующих шагов MUST продолжаться.

#### Scenario: Фиксация не удалась

- **WHEN** снятие якоря после успешного шага завершилось ошибкой
- **THEN** шаг сохраняет статус `success`, а его запись содержит пометку об отсутствии якоря с причиной
- **AND** следующий шаг работы исполняется

#### Scenario: Событие об отказе бухгалтерии

- **WHEN** якорь снять не удалось
- **THEN** в потоке событий есть запись с причиной и указанием шага

#### Scenario: Последствие ограничено возобновлением

- **WHEN** прогон содержит шаг без якоря и позже возобновляется
- **THEN** этот шаг и всё ниже по графу признаются невалидными и переисполняются
- **AND** причиной названо отсутствие якоря

#### Scenario: Дифф не вычислился

- **WHEN** вычислить `diff.patch` не удалось
- **THEN** файл не записывается, причина попадает в журнал, а статус шага не меняется

### Requirement: Способ фиксации зависит от наличия git

В репозитории git состояние дерева SHALL фиксироваться средствами git как
объект дерева, без коммита и без изменения ветки. Вне репозитория git состояние
SHALL фиксироваться хеш-манифестом дерева: устойчивым хешем от отсортированного
перечня путей, их режимов и хешей содержимого. Способ фиксации MUST
записываться рядом с якорем, чтобы значения двух способов не сравнивались между
собой.

#### Scenario: Дерево вне git

- **WHEN** прогон выполняется в директории, не принадлежащей репозиторию git
- **THEN** `tree_id` вычисляется хеш-манифестом, а способ фиксации помечен в записи шага

#### Scenario: Способы не смешиваются

- **WHEN** сравниваются два якоря, снятые разными способами
- **THEN** они считаются несравнимыми, а не различающимися

### Requirement: Исключения при фиксации совпадают с видимостью git

Фиксация состояния SHALL пропускать пути, невидимые для git: игнорируемые по
правилам репозитория и служебный каталог самого git. Вне репозитория git
исключения MUST браться из тех же правил игнорирования, если они присутствуют в
дереве.

#### Scenario: Игнорируемые пути не влияют на якорь

- **WHEN** шаг создал файл, подпадающий под правила игнорирования
- **THEN** `tree_id` до и после его создания совпадают

#### Scenario: Неотслеживаемый, но не игнорируемый файл учитывается

- **WHEN** шаг создал новый файл, не подпадающий под правила игнорирования
- **THEN** `tree_id` отличается от предыдущего

### Requirement: Дерево восстанавливается по якорю

Система SHALL уметь привести рабочую директорию к состоянию, зафиксированному
указанным `tree_id`. Восстановление MUST быть отказано, если якорь снят другим
способом фиксации или соответствующие объекты недоступны, — с указанием причины
и без частично применённого результата.

#### Scenario: Восстановление состояния

- **WHEN** система восстанавливает рабочую директорию по `tree_id` шага
- **THEN** содержимое отслеживаемых путей совпадает с зафиксированным на момент снятия якоря

#### Scenario: Объекты недоступны

- **WHEN** якорь ссылается на объекты, отсутствующие в репозитории
- **THEN** восстановление завершается ошибкой с указанием якоря и причины
- **AND** рабочая директория остаётся в том состоянии, в каком была до попытки

### Requirement: Отпечаток входов шага по умолчанию — всё дерево

Отпечатком входов шага SHALL по умолчанию считаться `tree_id` на начало этого
шага. Объявление входов MUST NOT требоваться от автора пайплайна. Отпечаток
MUST записываться в `step.json` и входить в вычисление ключа шага.

#### Scenario: Отпечаток без объявлений

- **WHEN** шаг исполнен и ничего про свои входы не объявлял
- **THEN** его запись содержит отпечаток входов, равный якорю дерева на начало шага

#### Scenario: Изменение дерева меняет отпечаток

- **WHEN** предшествующий шаг изменил файл рабочего дерева
- **THEN** отпечаток входов следующего шага отличается от снятого в прошлом прогоне

### Requirement: Наблюдённые входы сужают инвалидацию

Если бэкенд сообщает фактически прочитанные шагом файлы, система SHALL
сохранять их перечень в `step.json` и на последующих прогонах вычислять
отпечаток входов только по ним. Сужение MUST применяться только при наличии
сохранённого перечня от предыдущего успешного исполнения того же шага. При
отсутствии перечня система MUST возвращаться к отпечатку по всему дереву, а не
считать входы пустыми.

#### Scenario: Первый прогон широкий, второй узкий

- **WHEN** шаг исполнен впервые и бэкенд сообщил прочитанные файлы
- **THEN** отпечаток первого прогона взят по всему дереву, а перечень прочитанных файлов сохранён
- **AND** на следующем прогоне отпечаток вычисляется только по сохранённому перечню

#### Scenario: Изменение вне наблюдённых входов не инвалидирует

- **WHEN** между прогонами изменён файл, отсутствующий в сохранённом перечне прочитанных
- **THEN** отпечаток входов шага не изменился

#### Scenario: Бэкенд не сообщает прочитанное

- **WHEN** бэкенд не отдаёт сведений о прочитанных файлах
- **THEN** отпечаток входов остаётся отпечатком всего дерева

### Requirement: Объявленные входы работы сужают отпечаток явно

Система SHALL принимать у работы необязательный перечень входов. При его
наличии отпечаток входов её шагов SHALL вычисляться только по объявленным
путям, а наблюдённые входы MUST NOT
расширять его. Отклонение от умолчания MUST быть видно в объяснении
инвалидации.

#### Scenario: Явное объявление уже умолчания

- **WHEN** работа объявляет входами один каталог, а изменён файл вне него
- **THEN** отпечаток входов её шагов не изменился

#### Scenario: Происхождение отпечатка наблюдаемо

- **WHEN** работа объявила входы
- **THEN** объяснение инвалидации указывает, что отпечаток вычислен по объявленным путям

### Requirement: Диффы шага выводятся из пары якорей

Изменение, внесённое шагом в рабочее дерево, SHALL вычисляться сравнением
якорей на начало и на конец шага и сохраняться в каталоге шага файлом
`diff.patch`. Файл MUST NOT записываться, если якоря совпали.

#### Scenario: Шаг изменил дерево

- **WHEN** шаг изменил файлы рабочего дерева
- **THEN** его каталог содержит `diff.patch` с изменениями между якорями начала и конца шага

#### Scenario: Шаг ничего не изменил

- **WHEN** якоря на начало и конец шага совпали
- **THEN** `diff.patch` в каталоге шага отсутствует
