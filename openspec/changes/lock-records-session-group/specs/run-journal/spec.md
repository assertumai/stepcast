## MODIFIED Requirements

### Requirement: Ключ шага вычисляется, записывается и определяет переиспользование

Для каждого шага система SHALL вычислять ключ от нормализованного определения шага и работы, развёрнутых промпта и контекста, идентификатора и версии бэкенда, модели, выходов работ выше по графу и отпечатка входов шага, и записывать его в `step.json`.

Объявленная на месте подключения работы группа сессий (`session_group`) MUST
входить в ключ наравне с прочим, что записано в определении работы:
результат шага работы, продолжающей чужой диалог, зависит от того, что
агент видел выше по сессии, и ключ, слепой к раскладке диалогов, признавал бы
действительным результат, полученный при другом её устройстве. Появление,
снятие и переименование группы MUST менять ключи шагов затронутой работы, а
работ, группы не объявивших, MUST NOT затрагивать. Отпечаток прогона в
манифесте (`lock_hash`) MUST различать два прогона, отличающиеся только
раскладкой сессий.

Вычисленный ключ SHALL быть единственным основанием для решения о
переиспользовании результата шага из другого прогона. Отпечаток входов и его
происхождение MUST записываться рядом с ключом, чтобы решение о валидности
можно было объяснить без повторного вычисления.

#### Scenario: Одинаковые условия дают одинаковый ключ

- **WHEN** шаг исполняется дважды на неизменном рабочем дереве с теми же входами
- **THEN** вычисленные ключи совпадают

#### Scenario: Изменение промпта меняет ключ

- **WHEN** изменён файл промпта шага
- **THEN** вычисленный ключ отличается от предыдущего

#### Scenario: Изменение рабочего дерева меняет ключ

- **WHEN** между прогонами изменён файл, входящий в отпечаток входов шага
- **THEN** вычисленный ключ отличается от записанного в прошлом прогоне

#### Scenario: Совпадение ключа — основание для переиспользования

- **WHEN** ключ шага совпал с ключом успешного шага исходного прогона
- **THEN** шаг признан валидным и его результат берётся из исходного прогона

#### Scenario: Решение объяснимо по записи

- **WHEN** шаг признан невалидным
- **THEN** его запись содержит отпечаток входов и его происхождение, достаточные, чтобы назвать причину

#### Scenario: Объявление группы сессий меняет ключ

- **WHEN** два пайплайна различаются только тем, что в одном работа объявляет `session_group`, а в другом нет
- **THEN** ключи шагов этой работы различаются

#### Scenario: Переименование группы меняет ключ

- **WHEN** объявленная группа переименована, а всё остальное в пайплайне не менялось
- **THEN** ключи шагов работ этой группы отличаются от записанных в прошлом прогоне

#### Scenario: Работы вне группы не затронуты

- **WHEN** в пайплайне нет ни одной объявленной группы сессий
- **THEN** ключи шагов его работ совпадают с записанными до появления учёта раскладки

#### Scenario: Отпечаток прогона различает раскладку

- **WHEN** два прогона отличаются только раскладкой работ по группам сессий
- **THEN** `lock_hash` в их манифестах различается
