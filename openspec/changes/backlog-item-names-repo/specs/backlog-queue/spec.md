## ADDED Requirements

### Requirement: Пункт очереди называет затрагиваемые репозитории

Пункт очереди SHALL иметь необязательное поле `repos` — перечень каталогов через запятую, называющий репозитории, которых пункт касается, где `.` называет корень рабочего дерева.

Поле MUST разбираться схемой пункта наравне с остальными: каждое имя —
относительный путь без сегмента `..`, без символов шаблона глоба и без
абсолютной формы; пустое значение, пустой элемент перечня и повтор имени MUST
быть отказом разбора, называющим слаг пункта. Разбор MUST NOT проверять, что
названный каталог объявлен: очередь не знает устройства проекта, и это
проверяется тем, кто читает конфигурацию. Отсутствие поля MUST означать
корень дерева. Публикуемая запись пункта (`list`, `pick`, файл дорожки) MUST
нести названные репозитории перечнем строк — пустым, когда поля нет.

#### Scenario: Пункт называет вложенный репозиторий

- **WHEN** у пункта `repos: backend`
- **THEN** разбор проходит, а публикуемая запись несёт перечень из одного имени `backend`

#### Scenario: Пункт называет несколько репозиториев

- **WHEN** у пункта `repos: ., backend`
- **THEN** разбор проходит, а публикуемая запись несёт оба имени в объявленном порядке

#### Scenario: Пункт репозиториев не называет

- **WHEN** поля `repos` у пункта нет
- **THEN** разбор проходит, а публикуемая запись несёт пустой перечень

#### Scenario: Недопустимое имя

- **WHEN** имя в перечне абсолютно, содержит сегмент `..` либо символ шаблона глоба
- **THEN** разбор отказывает, называя слаг пункта и это имя

#### Scenario: Пустое значение поля

- **WHEN** у пункта `repos:` без значения либо перечень с пустым элементом
- **THEN** разбор отказывает, называя слаг пункта

#### Scenario: Повтор имени

- **WHEN** одно и то же имя названо в перечне дважды
- **THEN** разбор отказывает, называя слаг пункта и повторённое имя

### Requirement: Ответ pick --lanes несёт объявления репозитория дорожки

Схема ответа `stepcast backlog pick --lanes` SHALL допускать у заполненной дорожки необязательный блок объявлений её репозитория: каталог, команду проверки и практику спецификации.

Сама подкоманда `pick` этот блок MUST NOT заполнять — она конфигурации не
читает, — а поставляемая пакетом JSON Schema `stepcast:backlog-slots` MUST
принимать документ и с блоком, и без него: одна схема проверяет и ответ
`pick`, и ответ команды, которая его дополнила. Схема MUST порождаться той же
моделью движка, что и проверка разбора.

#### Scenario: Ответ pick принимается схемой

- **WHEN** ответ `pick --lanes` проверяется поставляемой схемой
- **THEN** проверка проходит, хотя блока объявлений в нём нет

#### Scenario: Дополненный ответ принимается схемой

- **WHEN** той же схемой проверяется ответ, у которого заполненная дорожка несёт блок объявлений
- **THEN** проверка проходит

#### Scenario: Посторонний ключ дорожки

- **WHEN** у дорожки объявлен ключ, не входящий ни в прежние поля, ни в блок объявлений
- **THEN** проверка схемой отказывает
