```yaml
# Работа: слить единицы знания с пересекающейся областью и освободить место в
# оглавлении.
#
# Идёт на дереве проекта после сведения дорожек, а не внутри дорожки, и это
# не удобство. Слияние — решение о дереве целиком: дорожка видит свою копию и
# не знает единицы, заведённой в этом же заходе соседней. Вторая причина
# техническая: две дорожки, слившие одновременно, правят одни и те же файлы, и
# наложение второй дало бы конфликт, стоивший заходу её работы целиком.
#
# Разделение шагов — то же, что в remember.yml: агент не правит файлы памяти,
# он кладёт описание, а пишет движок. Ревизию якоря подставляет движок, и
# якорь, записанный агентом напрямую, не проверялся бы на устаревание вовсе.
#
# Коммит стоит до последнего гейта сознательно. Записанное уже прошло
# knowledge_valid, то есть память цела; последний вопрос — хватило ли места.
# Отказ на нём при обратном порядке оставил бы дерево грязным и остановил
# следующий заход на assert-clean.

version: 1
kind: job
name: consolidate
description: Слить единицы знания и освободить место в оглавлении памяти

params:
  knowledge_rules: { type: string, required: true }
  knowledge_dir: { type: string, required: true }

context:
  - path: ${params.knowledge_rules}

steps:
  - id: pick
    agent: claude
    prompt: file:../prompts/consolidate.md
    timeout: 15m
    permissions:
      enforce: strict
      allow:
        - Read
        - Grep
        - Glob
        - Write
        - Bash(stepcast knowledge index*)
        - Bash(stepcast knowledge select*)
        - Bash(stepcast knowledge check*)
    expect:
      - changed_only: []

  # Описания нет — сливать нечего, и это законный исход шага: работа всё равно
  # упрётся в гейт достаточности ниже, и провалит её именно он, назвав
  # причину.
  - id: apply
    run: >
      sh -c 'f="$STEPCAST_SCRATCH/merge.json";
      [ -f "$f" ] || { echo "сливать нечего"; exit 0; };
      "$STEPCAST_BIN" knowledge write --file "$f"'
    timeout: 5m
    expect:
      - exit_code: 0
      - knowledge_valid: true

  - id: commit
    run:
      [
        sh,
        -c,
        'git add -- "${params.knowledge_dir}" && { git diff --cached --quiet || git commit -q -m "knowledge: слияние единиц знания"; }',
      ]
    timeout: 3m
    expect: [{ exit_code: 0 }]

  # Гейт достаточности. exit_code стережёт целость памяти, not_matches —
  # освобождённое место: переполнение стало жёлтым и кода возврата не меняет.
  - id: check
    run: '"$STEPCAST_BIN" knowledge check'
    timeout: 5m
    expect:
      - exit_code: 0
      - not_matches: index-overflow
```

**Файлы памяти не правь.** Твоя работа — описание, а записывает движок:

## Что сделать

1. `stepcast knowledge check` — он называет размер записей единиц знания и
   предел, в который они обязаны уложиться. Разница и есть то, что нужно
   освободить.
2. `stepcast knowledge index --json` — у каждой записи есть область.
   Кандидаты на слияние — единицы с пересекающейся областью: сравниваются
   дословные приставки шаблонов (`src/judge/**` даёт `src/judge`), и шаблоны
   пересекаются, когда одна приставка является началом другой по границе
   сегмента.
3. Прочитай тела кандидатов целиком: `stepcast knowledge select --id a,b,c`.
   Сливать, не прочитав, нельзя — решение о том, что чему подчинено, и есть
   вся эта работа.
4. Положи описание в `${run.scratch}/merge.json` — объект либо список
   объектов, по объекту на слитую группу:

   ```json
   {
     "id": "process-kill-and-session-costs",
     "title": "Одна строка утверждения, не темы",
     "scope": ["src/core/exec/**"],
     "anchors": ["src/core/exec/process.ts"],
     "supersedes": ["process-kill-is-posix-only", "session-group-costs-more"],
     "body": "Текст слитого утверждения и его причина.",
     "status": "active"
   }
   ```

`supersedes` — идентификаторы поглощённых единиц. Движок пометит их
отменёнными сам, не трогая тел: перепечатывать их не нужно и не следует.
`anchors` — только пути, без ревизий: ревизию подставит движок.

## Правила слияния

1. **Сливается то, что об одном.** Пересечение областей — признак кандидата, а
   не основание. Пять единиц об одном предмете сливаются в одну; пять о разном
   не сливаются, как бы их области ни пересекались.
2. **Ни одно верное утверждение не пропадает.** Тело слитой единицы несёт
   каждое утверждение поглощённых, которое всё ещё верно, и каждый их якорь.
   Утверждение, ставшее неверным, не переносится, — и это единственная
   законная потеря.
3. **Тело укладывается в предел тела единицы.** Не укладывается — значит слито
   слишком многое: сливай меньше.
4. **Сливай столько групп, сколько нужно**, чтобы оглавление уложилось в
   предел. Одной группы обычно хватает; если нет — добавь вторую объектом в
   список.
5. **Сливать нечего — файла не создавай.** Это законный исход: память полна
   несводимым, и решать это человеку — поднятием предела или выносом знания.
   Работа упрётся в гейт и честно провалится; выдумывать слияние, чтобы
   показать работу, нельзя.
```
