## ADDED Requirements

### Requirement: Неустранимый отказ бэкенда распознаётся по конверту результата

Адаптер SHALL классифицировать неустранимый отказ бэкенда по конверту финальной записи результата и сообщать движку класс отказа, сообщение бэкенда и код состояния, если бэкенд его назвал.
Распознаваемых классов ровно два: исчерпание окна лимита подписки и отказ
аутентификации. Кандидатом на классификацию MUST считаться только запись,
объявляющая себя ошибкой и несущая признак ошибки бэкенда — код состояния
ответа или соответствующую пометку о причине завершения. Класс MUST
определяться сначала по коду состояния, и лишь при его отсутствии — по телу
ответа из закрытого перечня узнаваемых формулировок.

Отказ, не совпавший ни с одним классом, MUST оставаться обычным отказом шага, и
классификация по догадке MUST NOT выполняться. Текст успешного ответа модели
MUST NOT участвовать в классификации.

#### Scenario: Упор в лимит подписки

- **WHEN** бэкенд вернул запись результата с признаком ошибки и кодом состояния 429
- **THEN** адаптер сообщает движку класс «исчерпано окно лимита подписки» и текст сообщения бэкенда

#### Scenario: Отказ аутентификации без кода состояния

- **WHEN** бэкенд вернул запись результата с признаком ошибки, без кода состояния, а тело ответа сообщает о неудачной аутентификации
- **THEN** адаптер сообщает движку класс «отказ аутентификации» и текст сообщения бэкенда

#### Scenario: Нераспознанный отказ не классифицируется

- **WHEN** бэкенд вернул запись результата с признаком ошибки, не совпадающую ни с одним известным классом
- **THEN** адаптер не сообщает класса отказа, а попытка обрабатывается как обычный отказ шага

#### Scenario: Слова про лимит в успешном ответе

- **WHEN** шаг завершился успешно, а текст его ответа содержит формулировку об исчерпанном лимите
- **THEN** класс отказа не сообщается

### Requirement: Момент сброса окна лимита извлекается из ответа об отказе

Адаптер SHALL извлекать момент сброса окна лимита из ответа об отказе по лимиту и приводить его к моменту времени, когда сообщённая бэкендом форма распознана.
Распознаваемых форм ограниченный набор: настенное время с указанием часового
пояса и метка времени с явным смещением. Настенное время MUST разрешаться в
ближайшее будущее его наступление в названном поясе.

Нераспознанная форма, неизвестный часовой пояс и отсутствие упоминания сброса
MUST давать отказ без момента сброса. Момент сброса MUST NOT угадываться.

#### Scenario: Время сброса словами

- **WHEN** ответ об отказе по лимиту называет время сброса настенным временем с часовым поясом
- **THEN** адаптер сообщает движку соответствующий ему ближайший будущий момент времени

#### Scenario: Форма времени не распознана

- **WHEN** ответ об отказе по лимиту называет время сброса в форме, которой нет в распознаваемом наборе
- **THEN** адаптер сообщает класс отказа без момента сброса

#### Scenario: Часовой пояс неизвестен

- **WHEN** ответ об отказе по лимиту называет часовой пояс, который система не знает
- **THEN** адаптер сообщает класс отказа без момента сброса

### Requirement: Неустранимый отказ на вызове судьи не становится вердиктом

Вызов судьи SHALL классифицироваться на неустранимый отказ бэкенда теми же правилами, что и агентский шаг, и такой отказ MUST NOT давать вердикта.
Судья, упёршийся в лимит подписки или в отказ аутентификации, MUST давать тот
же неустранимый отказ бэкенда, что и шаг, и MUST NOT приводить к
переисполнению оцениваемого шага ради повторного упора.

#### Scenario: Судья упёрся в лимит

- **WHEN** вызов судьи вернул отказ класса «исчерпано окно лимита подписки»
- **THEN** предикат не получает отрицательного вердикта, а движок обрабатывает неустранимый отказ бэкенда

#### Scenario: Судья упёрся в аутентификацию

- **WHEN** вызов судьи вернул отказ класса «отказ аутентификации»
- **THEN** оцениваемый шаг не переисполняется, а движок обрабатывает неустранимый отказ бэкенда
