## MODIFIED Requirements

### Requirement: Прогон останавливается только по объявленным причинам

Исполняющийся прогон SHALL прекращаться досрочно только по одной из причин:
непройденный предикат `expect` при исчерпанных попытках, исчерпание итераций
цикла, превышение объявленного бюджета, упор в окно лимита подписки бэкенда,
отказ аутентификации бэкенда, отмена пользователем, невозможность запустить
процесс шага. Неудача внутреннего учёта — снятие или чтение якоря состояния
дерева, вычисление диффа, запись производных файлов журнала, чтение данных
прошлого прогона — MUST NOT изменять статус шага, работы или прогона. Такая
неудача MUST записываться в журнал с причиной, а последствие MUST
ограничиваться утратой зависящей от неё возможности.

Условия, делающие прогон заведомо неисполнимым, MUST проверяться до запуска
первой работы и MUST давать ошибку конфигурации, а не отказ работы посреди
прогона.

Ошибка, возникшая при исполнении работы и не выявленная заранее, MUST
ограничиваться отказом этой работы. Прогон MUST продолжаться по объявленным
правилам, MUST дописывать своё состояние до конечного статуса и MUST сохранять
статусы работ, успевших завершиться.

Неустранимый отказ бэкенда — упор в окно лимита подписки, когда ожидание не
объявлено или невозможно, и отказ аутентификации — MUST прекращать прогон
независимо от `fail_fast`, потому что следующая работа упёрлась бы в то же
самое. Незапущенные работы MUST получать статус `skipped`, состояние прогона
MUST дописываться обычным путём, а причина MUST называть отказ бэкенда,
сообщение бэкенда и, для отказа аутентификации, способ починки.

#### Scenario: Учёт не удался, прогон продолжается

- **WHEN** во время прогона не удалось снять якорь состояния рабочего дерева
- **THEN** шаг сохраняет статус, определённый его предикатами, а прогон продолжает исполнение
- **AND** причина неудачи записана в поток событий

#### Scenario: Остановка по объявленному условию

- **WHEN** работа прогона автотестов объявляет предикат нулевого кода возврата, а тесты упали на всех попытках
- **THEN** работа получает статус отказа, а прогон останавливается по правилам `fail_fast`

#### Scenario: Неисполнимость выявляется заранее

- **WHEN** окружение не позволяет исполнить прогон в объявленной конфигурации
- **THEN** прогон завершается ошибкой конфигурации до запуска первой работы

#### Scenario: Причина остановки называется пользователю

- **WHEN** прогон остановился досрочно
- **THEN** состояние прогона называет причину из перечня объявленных и указывает работу и шаг, на которых она наступила

#### Scenario: Нечитаемый файл посреди прогона

- **WHEN** шаг работы объявляет путь, который не удалось прочитать, и заранее
  этот путь не проверялся
- **THEN** работа завершается отказом с причиной, называющей файл
- **AND** прогон получает конечный статус, а не остаётся в состоянии исполнения

#### Scenario: Завершающая работа отрабатывает после такой ошибки

- **WHEN** работа завершилась отказом из-за нечитаемого файла, а пайплайн
  объявляет работу с `needs: all`
- **THEN** эта работа исполняется и получает исход упавшей работы

#### Scenario: Отказ аутентификации не даёт следующим работам стартовать

- **WHEN** шаг работы упёрся в отказ аутентификации бэкенда, а пайплайн объявляет `fail_fast: false`
- **THEN** следующие работы получают статус `skipped`, а прогон прекращается с причиной, называющей отказ аутентификации

#### Scenario: Способ починки назван

- **WHEN** прогон прекращён отказом аутентификации бэкенда
- **THEN** состояние прогона и вывод команды называют сообщение бэкенда и действие, которым пользователь восстанавливает доступ

### Requirement: Статусы и код возврата

Работа SHALL завершаться одним из статусов `success`, `failed`, `skipped`,
`canceled`, `budget_exceeded`. Отказ работы MUST сопровождаться причиной;
причина `until_not_met` MUST использоваться, когда предел итераций цикла
исчерпан, а его предикаты не пройдены. Прогон MUST завершаться кодом 0 при
успехе, 1 при отказе работы, 2 при ошибке конфигурации или валидации, 3 при
остановке по бюджету, 4 при неустранимом отказе аутентификации бэкенда, 130
при отмене.

Упор в окно лимита подписки, при котором ожидание не состоялось, MUST давать
области статус `budget_exceeded` и код возврата 3 — так же, как выродившееся
ожидание по потолку `rate_limit_pct`. Отказ аутентификации MUST давать работе
статус `failed` и коду возврата прогона значение 4, отличающее неисполнимость
окружения от отказа самого пайплайна. Значения кодов 0, 1, 2, 3 и 130 MUST
оставаться прежними.

#### Scenario: Отказ работы

- **WHEN** хотя бы одна работа завершилась статусом `failed`
- **THEN** `stepcast run` завершается кодом 1

#### Scenario: Все работы успешны или пропущены

- **WHEN** ни одна работа не завершилась отказом
- **THEN** `stepcast run` завершается кодом 0

#### Scenario: Исчерпание итераций цикла

- **WHEN** работа с циклом исчерпала предел итераций, а её предикаты `check` не пройдены
- **THEN** работа получает статус `failed` с причиной `until_not_met`, а прогон завершается кодом 1

#### Scenario: Упор в лимит без ожидания

- **WHEN** шаг упёрся в окно лимита подписки, а ожидание не объявлено
- **THEN** область получает статус `budget_exceeded`, а прогон завершается кодом 3

#### Scenario: Отказ аутентификации отличим по коду возврата

- **WHEN** шаг упёрся в отказ аутентификации бэкенда
- **THEN** прогон завершается кодом 4, отличным от кода отказа работы
