## 2. Классификация в адаптере

- [ ] 2.1 Тип классификации отказа в `src/core/backend/types.ts`: класс
      (`rate_limit` | `unauthenticated`), сообщение бэкенда, необязательный код
      состояния, необязательный момент сброса; событие `result` получает его
      необязательным полем
- [ ] 2.2 Классификация в `src/core/backend/claude.ts`: кандидат — запись с
      `is_error: true` и (`api_error_status` либо `terminal_reason:
      "api_error"`); класс по коду состояния (429 → лимит, 401/403 →
      аутентификация), при его отсутствии — по телу `result` из закрытого
      перечня формулировок. `subtype` в классификации не участвует: в обоих
      настоящих конвертах он равен `success`
- [ ] 2.3 Тесты классификации на фикстурах из 1.1 плюс отрицательные:
      `is_error: true` без признаков класса, успешный ответ с формулировкой про
      лимит в тексте, запись без `is_error`

## 3. Момент сброса из текста

- [ ] 3.1 Разбор момента сброса в `src/core/backend/claude.ts`: форма
      `resets <час>[:<минуты>]<am|pm> (<зона IANA>)` и метка ISO 8601 со
      смещением или `Z`. Настенное время разрешается через
      `Intl.DateTimeFormat` в ближайшее будущее наступление в названной зоне
- [ ] 3.2 Отказы разбора возвращают отсутствующий момент: неизвестная зона,
      непризнанная форма, отсутствие упоминания сброса
- [ ] 3.3 Тесты разбора с фиксированным «сейчас»: `resets 11pm (Asia/Nicosia)`
      до и после указанного часа, зона с получасовым смещением, неизвестная
      зона, ISO-метка, мусор

## 5. Ожидание и остановка

- [ ] 5.1 Причина ожидания в `src/core/run/runner.ts` обобщается: `waitForReset`
      принимает область, режим `on_exceed`, момент сброса и описание — от
      превышения `rate_limit_pct` либо от отказа бэкенда по лимиту
- [ ] 5.2 Режим для отказа по лимиту берётся у ближайшей объявившей его области
      (шаг → работа → пайплайн), при отсутствии — `stop`. Выдуманные `used` и
      `limit` в учёт расхода не попадают
- [ ] 5.3 Отказ аутентификации прекращает прогон независимо от `fail_fast`:
      незапущенные работы получают `skipped`, состояние дописывается, команда
      возобновления записывается
- [ ] 5.4 Тесты: сон и переисполнение шага при `wait` с разобранным моментом;
      остановка при `stop`; остановка при неразобранном моменте; остановка при
      сбросе дальше `defaults.max_wait`; отмена спящего прогона; отказ
      аутентификации при `fail_fast: false`
