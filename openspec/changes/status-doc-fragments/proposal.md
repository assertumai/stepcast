## Why

`docs/status.md` — граница между тем, что работает, и тем, что отклоняется с
внятной ошибкой; поэтому восемнадцать пунктов очереди из двадцати требуют его
правки. Правят его руками, в одних и тех же таблицах: строка «Бюджет» в
«Работает» переписывалась пятью изменениями подряд, а «Известные ограничения»
разрослись до двадцати с лишним абзацев. Пока дорожка одна, это терпимо. Как
только их станет несколько (`scheduler-concurrency` уже снял последнее
препятствие, `parallel-tracks` стоит в очереди), три работы будут писать в один
файл в одни и те же места, а git плохо сводит правки соседних строк: разрешать
такой конфликт агентом постфактум дороже, чем не создавать его.

Второе, что чинится тем же приёмом, — безадресность. По строке «Известных
ограничений» сейчас не видно, каким изменением она заведена, и снимать её потом
приходится поиском по прозе.

## What Changes

- **Каждое изменение кладёт свой фрагмент рядом с собой** — файл
  `openspec/changes/<slug>/status.md`. В нём только то, что это изменение
  добавляет в состояние реализации: клаузы в строки «Работает», строки в «Пока
  нет», снятие строк из «Пока нет», блоки «Известных ограничений» и снятие чужих
  блоков. Никто, кроме автора изменения, в этот файл не пишет — параллельные
  дорожки трогают разные файлы, и сводить нечего.
- **`docs/status.md` становится собранным документом.** Руками он больше не
  правится: вводная проза, порядок разделов и всё содержимое, накопленное до
  введения фрагментов, переезжают в `docs/status.base.md`, а собранный документ
  получается склейкой базы с фрагментами.
- **Сборка — скрипт `scripts/status.mjs`**, `--write` пишет документ, `--check`
  сверяет записанное с собранным и падает при расхождении, называя расхождение
  и команду `npm run status:build`. `npm run check` завершается этой проверкой,
  так что забытая пересборка ловится тем же гейтом, что и упавший тест. Скрипт
  без сборки — как `scripts/backlog.mjs`: пересобрать документ можно, не трогая
  `dist/`.
- **Порядок сборки не зависит от того, заархивировано изменение или нет.**
  Фрагменты ищутся и в `openspec/changes/<slug>/`, и в
  `openspec/changes/archive/<дата>-<slug>/`; сортируются по слагу, а датный
  префикс архивного каталога отбрасывается. Архивация переносит фрагмент вместе
  с изменением и собранного документа не меняет ни на байт.
- **Строка «Работает» собирается из клауз по ключу.** Ячейка строки «Бюджет» —
  это склейка вкладов всех изменений, её трогавших, в порядке слагов; так эта
  ячейка и росла, только теперь каждый вклад лежит отдельно.
- **Блок «Известных ограничений» называет изменение, которым заведён.**
  Атрибуция берётся из имени каталога фрагмента, а не пишется руками, и
  снимается блок по его жирному лиду — из фрагмента того изменения, которое
  ограничение сняло. Содержимое, переехавшее в базу, атрибуции не получает:
  задним числом её взять неоткуда, и восстанавливать её по двадцати пяти
  архивным изменениям — работа, которой этот пункт не стоит.
- **Расхождение и опечатка отклоняются, а не толкуются наугад.** Неизвестный
  заголовок во фрагменте, снятие несуществующей строки, два фрагмента с одним
  слагом, строка «Пока нет» с ключом, уже занятым базой или другим фрагментом, —
  всё это отказ сборки с указанием файла и причины.
- **`docs/status.md` объявлен собранным и для git.** `.gitattributes` даёт ему
  `merge=union`, чтобы независимые дорожки не встречались на конфликте в
  сгенерированном файле; последствия слияния приводит в порядок пересборка,
  а неприведённое ловит `npm run status:check`.
- **Промпт `implement` перенаправляется на фрагмент.** Вместо «обнови
  `docs/status.md`» — «опиши изменение в своём фрагменте и пересобери документ».

## Impact

- `docs/status.md` — становится собранным файлом; содержимое переезжает в
  `docs/status.base.md` без единой правки текста, чтобы первая же сборка совпала
  с ним побайтно.
- `scripts/status.mjs` — новый скрипт сборки и проверки.
- `package.json` — `status:build`, `status:check`; `check` дополняется
  проверкой.
- `.gitattributes` — новый файл; `docs/status.md merge=union`.
- `.stepcast/prompts/implement.md` — правило про `docs/status.md` заменяется
  правилом про фрагмент.
- `.stepcast/jobs/implement.yml`, `.stepcast/jobs/fix-review.yml` — предикат
  `changed_only` расширяется до `scripts/**`, `package.json`, `.gitattributes` и
  `.stepcast/**`: без этого заход петли не может тронуть ни сборщик, ни гейт, ни
  собственный промпт. Правка нужна до запуска захода — список шаблонов читается
  при старте `stepcast run`.
- `openspec/changes/status-doc-fragments/status.md` — фрагмент самого этого
  изменения, первый по счёту.
- `test/status-doc.test.ts` — новый тест: сборка, порядок, устойчивость к
  архивации, отказы на некорректном фрагменте, поведение `--check`.
- `README.md` — ссылка на состояние реализации остаётся, добавляется оговорка о
  том, что файл собирается.
