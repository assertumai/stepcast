## ADDED Requirements

### Requirement: Команда проверки проекта объявляется в конфигурации

Конфигурация SHALL принимать секцию `project` с ключом `check` — строкой,
несущей команду проверки репозитория. Значение MUST быть непустым: пустая
строка и строка из одних пробельных символов отклоняются разбором
конфигурации, потому что пустая команда даёт нулевой код возврата и превращает
проверку в тихое согласие. Ключ MUST быть необязательным: репозиторий, которому
проверять нечем, конфигурацию с этой секцией не заводит, и отсутствие ключа
само по себе MUST NOT быть ошибкой.

Встроенного умолчания у `project.check` MUST NOT быть: команда, подставленная
за автора, исполнялась бы в чужом репозитории.

#### Scenario: Команда объявлена в проектном конфиге

- **WHEN** `.stepcast/config.yml` содержит `project: { check: "npm run check" }`
- **THEN** действующее значение `project.check` равно `npm run check`
- **AND** отчёт `stepcast config` называет источником этот файл

#### Scenario: Команда не объявлена

- **WHEN** ни один слой конфигурации не задаёт `project.check`
- **THEN** конфигурация разрешается без ошибки, а значение `project.check` отсутствует

#### Scenario: Пустая команда

- **WHEN** конфигурация содержит `project: { check: "   " }`
- **THEN** чтение конфигурации завершается ошибкой, называющей файл и ключ

#### Scenario: Неизвестный ключ секции

- **WHEN** конфигурация содержит `project: { chek: "npm run check" }`
- **THEN** чтение конфигурации завершается ошибкой о неизвестном ключе

### Requirement: Секция project допустима только в проектной конфигурации

Ключи секции `project` SHALL приниматься только из `.stepcast/config.yml` и
MUST отклоняться с ошибкой при чтении `~/.stepcast/config.yml`. Сообщение MUST
называть ключ и предлагать перенести значение в проектный конфиг.

Правило зеркалит запрет машинно-зависимых ключей (`runs.root`,
`backends.*.command`) в проектном конфиге: у каждого вида ключей есть
единственный верный слой, и слой, общий всем репозиториям машины, не может
объявлять команду одного из них.

#### Scenario: Команда проверки в глобальном конфиге

- **WHEN** `~/.stepcast/config.yml` содержит `project: { check: "npm run check" }`
- **THEN** любая команда, читающая конфигурацию, завершается ошибкой с указанием ключа `project.check`
- **AND** подсказка называет `.stepcast/config.yml` как верное место объявления

#### Scenario: Проектный конфиг не ограничен этим правилом

- **WHEN** `.stepcast/config.yml` содержит `project: { check: "./gradlew check" }`, а глобальный конфиг секции `project` не содержит
- **THEN** конфигурация разрешается без ошибки
