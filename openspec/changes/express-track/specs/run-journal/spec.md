## ADDED Requirements

### Requirement: Пропуск работы объявляет своё происхождение

Запись пропущенной работы в состоянии прогона SHALL нести поле `skip` из закрытого перечня: `condition` — пропуск по решению графа (ложное условие `if`, все зависимости пропущены, несовпадение `on:`), `halted` — прогон до работы не дошёл (остановка после отказа при `fail_fast`, неразрешённые зависимости).

Поле MUST появляться только у работ со статусом `skipped`. Оно MUST NOT входить в перечень причин неуспеха (`cause`): пропуск по условию неуспехом не является.

Читающий MUST различать эти два случая по полю, а не по тексту причины: текст объясняет пропуск человеку и не является форматом.

#### Scenario: Пропуск по ложному условию

- **WHEN** работа пропущена, потому что её `if` ложен
- **THEN** её запись несёт `skip: condition`

#### Scenario: Пропуск остановкой после отказа

- **WHEN** работа пропущена, потому что прогон остановлен после отказа соседней
- **THEN** её запись несёт `skip: halted`

#### Scenario: Запись прошлого прогона

- **WHEN** читается состояние прогона, снятое до появления поля
- **THEN** пропуск в нём происхождения не объявляет, и читающий трактует его строго — как непройденную работу
