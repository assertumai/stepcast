## MODIFIED Requirements

### Requirement: Спеки репозитория индексируются наравне с единицами знания

Источник `fs` SHALL включать в индекс документы практики спецификации, объявленной `project.spec.dir`, беря их областью каталог, в котором они лежат, и SHALL разрешать всякий названный индексом идентификатор каталога отбором по имени. Содержимое спек источник не MUST копировать в каталог знания. Отбор по имени такого идентификатора MUST отдавать запись на каждый документ Markdown каталога — ссылкой на его исходный путь, а не копией содержимого, — порядком по пути, и MUST называть каждую запись тем идентификатором, который назван в запросе. Перечень каталогов у индекса и у отбора по имени MUST быть один и тот же: каталог, которого нет в индексе, MUST давать тот же внятный отказ, что и всякий несуществующий идентификатор. Отбор по области записи каталогов практики спецификации MUST NOT возвращать: их число растёт от самой петли и памятью не управляется, а отбор по имени возвращает ровно названное. Оглавление, уезжающее в контекст агентского шага, MUST называть записи каталогов запрашиваемыми только по идентификатору всякий раз, когда показывает хотя бы одну из них: область у такой записи печатается наравне с областью единицы знания и называет место каталога в дереве, а необъявленная разница дала бы шагу на объявленную им область не отказ, а пустой ответ — молчание, неотличимое от «знания по этой области нет». Документ каталога, содержимое которого прочитать не удалось, MUST давать отказ, называющий путь и причину, а не ошибку среды исполнения.

#### Scenario: Спека попадает в оглавление

- **WHEN** репозиторий объявляет практику спецификации и содержит документ спеки
- **THEN** `index` перечисляет его наравне с единицами знания, а `select` отдаёт ссылкой на его исходный путь

#### Scenario: Идентификатор из оглавления разрешается по имени

- **WHEN** `select` вызван по имени с идентификатором каталога, названным ответом `index`
- **THEN** источник отдаёт записи на документы этого каталога, каждая со ссылкой на исходный путь и с запрошенным идентификатором, и отказа не происходит

#### Scenario: Каталог отдаётся всеми своими документами

- **WHEN** каталог практики спецификации содержит несколько документов Markdown, включая вложенные
- **THEN** отбор по его идентификатору отдаёт запись на каждый из них порядком по пути

#### Scenario: Отбор по области каталоги не возвращает

- **WHEN** `select` вызван по области, пересекающейся с каталогом практики спецификации
- **THEN** ответ содержит только единицы знания, и ни одной записи каталога в нём нет

#### Scenario: Оглавление в контексте называет записи каталогов запрашиваемыми по имени

- **WHEN** оглавление, собранное для контекста агентского шага, показывает хотя бы одну запись каталога практики спецификации
- **THEN** его текст говорит, что записи `spec:…` запрашиваются только по идентификатору, а отбор по области их не возвращает

#### Scenario: Нечитаемый документ каталога отказывает названной причиной

- **WHEN** каталог практики спецификации содержит путь с именем на `.md`, содержимое которого прочитать не удаётся
- **THEN** отбор по имени этого каталога отказывает сообщением, называющим путь и причину, а не ошибкой среды исполнения

#### Scenario: Несуществующий идентификатор по-прежнему отказывает

- **WHEN** `select` вызван по имени с идентификатором, которого нет ни среди единиц знания, ни среди каталогов, названных индексом
- **THEN** источник отказывает, называя идентификатор и подсказывая сверить его с оглавлением
