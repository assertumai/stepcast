## Why

Оглавление встроенного источника `fs` перечисляет каталоги практики
спецификации записями `spec:<слаг>` (`specEntries()`, `src/core/knowledge/fs.ts`)
и открывается строкой «Известное по проекту. Тела здесь нет — **запрашивайте по
идентификатору**». Отбор по имени этих идентификаторов не знает: ветка
`selector.kind === 'id'` ищет только среди `units()`, то есть среди файлов
каталога знания, и на всё остальное отвечает отказом «Единица знания не
найдена: spec:<слаг>» (`fs.ts:194-209`). Промах достаётся и человеку
(`stepcast knowledge select --id spec:<слаг>`), и агентскому шагу: запись
контекста `knowledge: { id: … }` ограничения на форму идентификатора не имеет
(`src/core/pipeline/schema.ts`), так что отказ источника роняет шаг посреди
прогона.

Это не крайний случай. В этом репозитории оглавление составляют две единицы
знания и около шестидесяти записей каталогов изменений: агент, поступивший
ровно так, как велело оглавление, промахивается в подавляющем большинстве
попыток.

Записанное требование уже говорит обратное коду. `openspec/specs/knowledge-fs/spec.md`,
требование «Спеки репозитория индексируются наравне с единицами знания»,
сценарий: «`index` перечисляет его наравне с единицами знания, а `select`
отдаёт ссылкой на его исходный путь». Реализация с этим требованием разошлась,
а само требование не говорит, каким селектором отбор происходит и что бывает с
такими записями при отборе по области, — то есть его сегодня нельзя ни
выполнить проверяемо, ни опровергнуть.

## What Changes

- **Отбор по имени разрешает записи каталогов.** `select({ kind: 'id' })`
  встроенного источника, не найдя идентификатор среди единиц знания, ищет его
  среди записей, которые отдаёт `specEntries()` — тем же перечнем, из которого
  собрано оглавление. Согласованность держится построением: единственный
  список каталогов, ни оглавление, ни отбор своей копии не заводят.
- **Каталог разрешается своими документами.** Найденная запись `spec:<слаг>`
  превращается не в одну запись ответа, а в запись на каждый документ каталога
  (файлы `**/*.md` внутри него, порядком по пути). Каждая несёт `path` — тот же
  путь, что лежит в дереве, — а не `text`: путь и заведён затем, чтобы движок
  применил к нему `context.deny`, порог вставки, склейку повторов и понижение
  до ссылки по бюджету.
- **Идентификатор ответа — тот, о котором спросили.** Все записи одного
  каталога несут `id: spec:<слаг>`; документ различается путём и заголовком
  записи. Отчёт о составе контекста (`context.json`) при этом называет каждую
  строку тем идентификатором, который стоял в объявлении.
- **Отбор по области объявляется явно.** Записи каталогов практики
  спецификации отбором по области **не** возвращаются — только по имени, — и
  это становится объявленным поведением с причиной (число каталогов растёт от
  самой петли и памятью не управляется — тем же доводом заведён отдельный
  предел `spec_index_max_tokens`), а не следствием того, как написан цикл.
- **Отказ по несуществующему идентификатору сохраняется** дословно: имя,
  которого нет ни среди единиц, ни среди каталогов, по-прежнему даёт
  `Единица знания не найдена: <id>` с подсказкой про `stepcast knowledge index`.
  Каталог без единого документа в оглавление не попадает и по имени не
  разрешается — тот же перечень, то же поведение.
- **Тест-свойство**, падающий до правки: по фикстуре с каталогом практики
  спецификации каждый идентификатор из `index()` разрешается
  `select({ kind: 'id', id: [<он же>] })` и отдаёт хотя бы одну запись с
  читаемым содержимым.
- **Документация** (`docs/knowledge.md`) называет оба поведения: разрешение
  записи каталога по имени и невозвращение её отбором по области.

Ломающих изменений нет: контракт `KnowledgeEntry` не меняется, а прежде
успешные вызовы отбора отвечают ровно тем же.

### Modified Capabilities

- `knowledge-fs`: требование «Спеки репозитория индексируются наравне с
  единицами знания» уточняется — запись каталога разрешается отбором по имени и
  отдаётся записью на документ со ссылкой на исходный путь, а отбором по
  области не возвращается.
- `knowledge-source`: добавляется требование согласованности оглавления и
  отбора по имени — всякий идентификатор, названный ответом `index` источника,
  разрешается его же `select` по имени. Требование контрактное: оно
  распространяется и на источник `cmd`, где ту же ловушку легко воспроизвести.

## Impact

- `src/core/knowledge/fs.ts` — ветка `selector.kind === 'id'` метода `select()`
  и перечень записей каталогов `specEntries()`.
- `test/knowledge.test.ts` — тест-свойство по оглавлению; при необходимости
  `test/cli-knowledge.test.ts` для `stepcast knowledge select --id spec:<слаг>`.
- `docs/knowledge.md` — разделы «Встроенный источник `fs`» и «Работа вне
  пайплайна».
- Контракт (`src/core/knowledge/types.ts`, схемы ответов) и сборка контекста
  (`src/core/context/assemble.ts`) правок не требуют: записи со ссылкой на путь
  она уже обрабатывает.
