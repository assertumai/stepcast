## MODIFIED Requirements

### Requirement: Общий контекст отправляется один раз на сессию

Унаследованный контекст SHALL включаться в первое сообщение сессии, когда
несколько агентских шагов исполняются в одной сессии. Последующие шаги той же
сессии MUST получать только собственный контекст и собственный промпт.
Унаследованным считается всё, что шаг получает не от себя: блок выходов
предшественников, `context` пайплайна и `context` работы.

Границы отметки об отправленном контексте:

- отметка ведётся по сессии шага, поэтому шаги разных сессий — в том числе все
  шаги работы с `session: per_step` — получают унаследованный контекст каждый;
- отметка ведётся в пределах работы: одноимённая сессия соседней работы MUST
  считаться отдельной и получать унаследованный контекст самостоятельно;
- новая итерация цикла `until` MUST начинать сессии работы заново и получать
  унаследованный контекст снова: сессия предыдущей итерации не продолжается;
- повторная попытка шага MUST NOT получать унаследованный контекст заново —
  это следующее сообщение той же сессии, а не новая сессия.

#### Scenario: Второй шаг общей сессии

- **WHEN** два шага работы отнесены к одной сессии и наследуют один и тот же контекст пайплайна
- **THEN** контекст пайплайна отправляется только в первом сообщении
- **AND** зафиксированный состав контекста второго шага содержит только его собственные записи

#### Scenario: Раздельные сессии получают контекст каждая

- **WHEN** шаги отнесены к разным сессиям
- **THEN** унаследованный контекст отправляется в первом сообщении каждой сессии

#### Scenario: Работа с `session: per_step`

- **WHEN** работа объявляет `session: per_step` и содержит два агентских шага
- **THEN** зафиксированный состав контекста каждого шага содержит записи уровней пайплайна и работы

#### Scenario: Одноимённая сессия соседней работы

- **WHEN** две работы содержат агентские шаги с одним и тем же псевдонимом сессии
- **THEN** первый агентский шаг каждой работы получает унаследованный контекст

#### Scenario: Новая итерация цикла

- **WHEN** работа с `until` не проходит проверку и уходит на следующую итерацию
- **THEN** первый агентский шаг новой итерации снова получает унаследованный контекст

#### Scenario: Повторная попытка шага

- **WHEN** первая попытка агентского шага не проходит предикат и шаг делает вторую
- **THEN** промпт второй попытки унаследованного контекста не содержит

### Requirement: Состав контекста фиксируется и наблюдаем

Для каждого агентского шага система SHALL записывать в `context.json` перечень
вошедших записей с указанием уровня-источника, способа передачи и размера в
токенах. Отправленный текст MUST сохраняться в `prompt.txt`. Запись MUST
отражать состав, фактически ушедший бэкенду на этом шаге: уровень, чьи записи
шаг не получил, в перечне отсутствует. Промпт каждой повторной попытки MUST
сохраняться отдельным файлом `prompt.<номер попытки>.txt`, тогда как
`context.json` у шага один и отражает последнюю сборку промпта.

#### Scenario: Разбор по источникам

- **WHEN** шаг исполнен
- **THEN** `context.json` содержит для каждой записи её источник — блок выходов, пайплайн, работа или шаг — способ передачи и размер

#### Scenario: Шаг без унаследованного контекста

- **WHEN** шаг исполнен вторым в общей сессии и унаследованного контекста не получил
- **THEN** в его `context.json` нет записей с источником «блок выходов», «пайплайн» или «работа»

#### Scenario: Промпты попыток сохраняются раздельно

- **WHEN** шаг исполнен со второй попытки
- **THEN** каталог шага содержит `prompt.txt` первой попытки и `prompt.2.txt` второй
