## MODIFIED Requirements

### Requirement: Прогон останавливается только по объявленным причинам

Исполняющийся прогон SHALL прекращаться досрочно только по одной из причин:
непройденный предикат `expect` при исчерпанных попытках, исчерпание итераций
цикла, превышение объявленного бюджета, отмена пользователем, невозможность
запустить процесс шага. Неудача внутреннего учёта — снятие или чтение якоря
состояния дерева, вычисление диффа, запись производных файлов журнала, чтение
данных прошлого прогона — MUST NOT изменять статус шага, работы или прогона.
Такая неудача MUST записываться в журнал с причиной, а последствие MUST
ограничиваться утратой зависящей от неё возможности.

Условия, делающие прогон заведомо неисполнимым, MUST проверяться до запуска
первой работы и MUST давать ошибку конфигурации, а не отказ работы посреди
прогона.

Ошибка, возникшая при исполнении работы и не выявленная заранее, MUST
ограничиваться отказом этой работы. Прогон MUST продолжаться по объявленным
правилам, MUST дописывать своё состояние до конечного статуса и MUST сохранять
статусы работ, успевших завершиться.

#### Scenario: Учёт не удался, прогон продолжается

- **WHEN** во время прогона не удалось снять якорь состояния рабочего дерева
- **THEN** шаг сохраняет статус, определённый его предикатами, а прогон продолжает исполнение
- **AND** причина неудачи записана в поток событий

#### Scenario: Остановка по объявленному условию

- **WHEN** работа прогона автотестов объявляет предикат нулевого кода возврата, а тесты упали на всех попытках
- **THEN** работа получает статус отказа, а прогон останавливается по правилам `fail_fast`

#### Scenario: Неисполнимость выявляется заранее

- **WHEN** окружение не позволяет исполнить прогон в объявленной конфигурации
- **THEN** прогон завершается ошибкой конфигурации до запуска первой работы

#### Scenario: Причина остановки называется пользователю

- **WHEN** прогон остановился досрочно
- **THEN** состояние прогона называет причину из перечня объявленных и указывает работу и шаг, на которых она наступила

#### Scenario: Нечитаемый файл посреди прогона

- **WHEN** шаг работы объявляет путь, который не удалось прочитать, и заранее
  этот путь не проверялся
- **THEN** работа завершается отказом с причиной, называющей файл
- **AND** прогон получает конечный статус, а не остаётся в состоянии исполнения

#### Scenario: Завершающая работа отрабатывает после такой ошибки

- **WHEN** работа завершилась отказом из-за нечитаемого файла, а пайплайн
  объявляет работу с `needs: all`
- **THEN** эта работа исполняется и получает исход упавшей работы
