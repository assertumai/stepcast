## ADDED Requirements

### Requirement: Слой конфигурации включает файл патча дерева плагинов

Слой конфигурации SHALL состоять из двух документов: `config.yml` и `plugins.patch.yml` того же каталога. Домашний слой MUST читаться из `~/.stepcast/`, проектный — из `.stepcast/` корня проекта. Патч MUST участвовать только в сборке дерева плагинов и MUST NOT сливаться с прочими значениями конфигурации по точечным путям. Отсутствие файла патча MUST быть обычным состоянием, а не отказом. Чтение конфигурации, у которой патч не разбирается или не проходит схему, MUST отказывать так же, как отказывает неразбираемый `config.yml`: с именем файла, местом и подсказкой.

#### Scenario: Патч читается вместе со слоем

- **WHEN** в `.stepcast/` лежат `config.yml` и `plugins.patch.yml`
- **THEN** значения конфигурации берутся из первого, состав плагинов — из обоих

#### Scenario: Патча нет

- **WHEN** файла `plugins.patch.yml` нет ни в одном слое
- **THEN** конфигурация разрешается без ошибок, а дерево плагинов собирается из встроенных строк и ключа `plugins`

#### Scenario: Патч не разбирается

- **WHEN** `plugins.patch.yml` содержит неверный YAML
- **THEN** любая команда, разрешающая конфигурацию, завершается ошибкой, называющей файл и место

## MODIFIED Requirements

### Requirement: Ключ plugins складывается между слоями

Конфигурация SHALL принимать ключ `plugins` — список строк — в глобальном и проектном слоях. Значения слоёв MUST объединяться в порядке «глобальный, затем проектный» с сохранением порядка внутри слоя; повтор строки MUST схлопываться в одно вхождение. Пустой список MUST отклоняться разбором как объявление, не объявляющее ничего. Требование MUST быть выражено в публикуемой JSON Schema конфигурации. Каждая строка ключа MUST быть сокращённой формой строки дерева плагинов (возможность `plugin-tree`), то есть вставкой в конец своего слоя, и MUST быть доступна для замены и отключения патчем вышестоящего слоя.

#### Scenario: Объединение слоёв

- **WHEN** глобальный слой объявляет `plugins: ["a"]`, проектный — `plugins: ["b", "a"]`
- **THEN** действующий список — `["a", "b"]`

#### Scenario: Пустой список

- **WHEN** конфигурация содержит `plugins: []`
- **THEN** чтение конфигурации завершается ошибкой, называющей файл и ключ

#### Scenario: Строка ключа отключается патчем

- **WHEN** глобальный конфиг объявляет `plugins: ["a"]`, а проектный патч объявляет строку `a` с `enabled: false`
- **THEN** модуль `a` не загружается

### Requirement: Отчёт о конфигурации показывает плагины и их умолчания

Отчёт `stepcast config` SHALL показывать вклад каждого слоя в список `plugins` по образцу складывающихся списков и SHALL печатать раздел о загруженных плагинах. Значение, полученное из умолчаний плагина, MUST показываться с источником `plugin:<имя плагина>`. Действующее значение ключа `plugins` в отчёте MUST быть проекцией итогового дерева — модулями действующих строк в порядке дерева, — а не объединением объявленных списков: состав, который отчёт называет действующим, MUST совпадать с составом, который загружается. Строки встроенного слоя в это значение MUST NOT входить: их `use` (`stepcast:<имя>`) модулем не является. Строка, принесённая одним лишь патчем, MUST быть в нём названа, даже если ключ `plugins` не объявлял ни один слой.

#### Scenario: Источник умолчания плагина

- **WHEN** `backends.codex.sessions` получено из умолчаний плагина `codex-adapter`
- **THEN** отчёт показывает значение с источником `plugin:codex-adapter`

#### Scenario: Отключённая патчем строка не числится действующей

- **WHEN** патч отключил строку, объявленную ключом `plugins`
- **THEN** отчёт не показывает её модуль среди действующих, а вклад слоя в ключ `plugins` показывает как объявленный

#### Scenario: Строка, объявленная одним лишь патчем

- **WHEN** ключ `plugins` не объявлен ни одним слоем, а патч вставляет строку с модулем
- **THEN** отчёт называет этот модуль действующим значением ключа `plugins`
