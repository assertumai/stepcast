## Why

Список прогонов — первый экран витрины (`ui/src/pages/Runs.tsx:221-328`) и
единственное место, где заходы видны все сразу. Устроен он одним способом:
секция на проект (`Runs.tsx:243-247`), внутри — таблица с шестью колонками
(`Runs.tsx:249-259`) в порядке, который задаёт сборка обзора и который выбрать
нельзя, — новейшими первыми (`src/ui/overview.ts:336`). Ни отбора, ни
сортировки, ни выбора нескольких строк на экране нет.

На пустом корне прогонов это незаметно. На корне, где месяц работали петлёй,
получается так:

- **Проект не назван в строке.** Он назван заголовком секции
  (`Runs.tsx:245-247`), и пока секция целиком помещается на экран, этого
  довольно. Стоит секции стать длиннее экрана — заголовок уезжает вверх, и
  строка перестаёт отвечать на вопрос, чей это прогон. Требование главной
  спеки «по каждому прогону обзор MUST показывать проект»
  (`openspec/specs/ui-dashboard/spec.md:9-15`) держится на прокрутке.
- **Отобрать нечем.** Ни по проекту, ни по пайплайну, ни по статусу: чтобы
  найти вчерашние отказы одного пайплайна, список листают глазами. При этом
  экран уборки (`ui/src/pages/Cleanup.tsx:93-142`) отбор по проекту и признаку
  уже умеет — но только чтобы удалять, а не чтобы смотреть.
- **Порядок один.** Колонки длительности, стоимости и токенов
  (`Runs.tsx:310-314`) заведены ровно для того, чтобы заходы сравнивать
  («расход стоит рядом с исходом намеренно» — `Runs.tsx:7-17`), а
  отсортировать по ним нельзя: вопрос «какой заход шёл дольше всех» и «какой
  обошёлся дороже всех» решается глазами по всему списку. Секции по проектам
  делают его нерешаемым в принципе: сравнивать пришлось бы пять
  самостоятельных таблиц.
- **Удаление — по одному.** Корзинка живёт в строке (`Runs.tsx:147-219`) и
  снимает один прогон за одно подтверждение. Групповое удаление в витрине
  есть, но только по признакам «оборванный / отказавший / старше срока» на
  экране уборки (`Cleanup.tsx:145-344`). Между «этот один» и «все оборванные»
  нет ничего: разобрать десяток прогонов, отобранных глазом, — десять
  подтверждений подряд.

Демон при этом уже умеет почти всё, что для этого нужно:
`DELETE /api/runs` (`src/ui/server.ts:412-475`) принимает явный список адресов,
не обрывается на первом препятствии и даёт исход по каждому адресу, а
`GET /api/runs` (`src/ui/server.ts:356-410`) меряет объём отбора до удаления.
Не хватает ровно одного: измерить объём **выбранных руками** прогонов, а не
отобранных признаком.

## What Changes

- **Секции по проектам уступают одной таблице с колонкой проекта.** Проект
  называется в каждой строке путём своего корня; проект, которого нет в
  `projects.json`, — ключом с пометкой «путь неизвестен», как и сегодня
  (`Runs.tsx:245-247`). Сортировка через весь список возможна только так:
  порядок внутри пяти секций на вопрос «самые долгие заходы» не отвечает.
- **Фильтры: проект, пайплайн, статус.** Объединяются по «и», незаполненный
  означает «все». Пайплайн различается **файлом**, которым запущен прогон
  (`RunOverview.pipelineFile`), а не именем: два файла проекта могут объявить
  одно имя — то же правило, по которому прогоны находят свой пайплайн в
  `src/ui/grouping.ts:10-17`.
- **Сортировка по времени начала, длительности, стоимости и числу токенов, в
  обе стороны.** Умолчание — прежнее, новейшими первыми. Прогон, у которого
  выбранной величины нет (расход не сообщён, время не прочиталось), уходит в
  конец при обоих направлениях: иначе «самые дорогие» показывали бы первыми
  тех, у кого цены нет вовсе.
- **Групповое удаление флажками.** Флажок получает та же строка, что получает
  сегодня корзинку (`Runs.tsx:158-176`): у идущего живым процессом и у прогона
  без файлов его нет — демон такое удаление отклонит (`409`, `404`). Флажок
  шапки отмечает ровно то, что видно под действующими фильтрами.
  Подтверждение называет число прогонов и суммарный объём, удаление идёт одним
  запросом `DELETE /api/runs`, исход показывается по каждому адресу. Сводка
  расхода сохраняется: её снятие остаётся отдельно вооружаемым действием
  экрана уборки (`Cleanup.tsx:291-304`).
- **`GET /api/runs` учится отбору по явному списку адресов.** Параметр
  `run=<адрес>`, повторяемый; со признаками (`trait`, `older-than`, `project`)
  взаимоисключающий. Отвечает тем же составом, что и отбор по признаку —
  адрес, размер каталога, возраст, число и суммарный объём, — потому что
  подтверждению нужно то же самое. Размер по-прежнему считается только на
  отборе и не считается при сборке обзора: обзор пересобирается на каждое
  событие журнала.
- **Правило отбора и порядка выносится в чистый модуль `src/ui/runsView.ts`.**
  Витрина импортирует его относительным путём из `ui/`, тест — как любой
  модуль `src/`: тем же приёмом, что `src/ui/routes.ts`, `grouping.ts` и
  `format.ts` (`vite.config.ts:44-53`, `ui/tsconfig.json`). Иначе правило
  осталось бы внутри `.tsx`, где в этом репозитории тестов нет вовсе.

Отдельно названо то, чего изменение **не** делает: пункт очереди требует
согласовать `docs/status.md`, но такого документа в репозитории нет —
сводный учёт упразднён изменением `drop-status-doc`, и его возврат стережёт
`test/no-status-doc.test.ts`. Согласовывать нечего; обязанность описать
поведение несёт дельта-спека.

### Modified Capabilities

- `ui-dashboard`: список прогонов получает колонку проекта, фильтры по
  проекту, пайплайну и статусу, выбираемый порядок по четырём величинам и
  групповое удаление выбранными флажками; порядок «новейшими первыми»
  становится умолчанием, а не единственным; демон учится мерить объём прогонов
  по явному списку адресов.

## Impact

- `ui/src/pages/Runs.tsx` — одна таблица вместо секций, колонка проекта,
  полоса фильтров, сортируемая шапка, колонка флажков, полоса выбранного с
  подтверждением; `DeleteCell` остаётся поштучным удалением.
- `src/ui/runsView.ts` (новый) — фильтры, порядок и состав значений фильтров
  над уже полученным обзором; чистый модуль, ни React, ни `window`, ни диска.
- `src/ui/format.ts` — склонение «прогон / прогона / прогонов» переезжает сюда
  из `Runs.tsx:60-67`: его теперь просит и подтверждение группового удаления.
- `src/ui/server.ts` — `handleSelectRuns` принимает `run=<адрес>`;
  взаимоисключение с признаками, предел числа адресов, тот же ответ.
- `src/core/run/cleanup.ts` — отбор по явным адресам рядом с
  `selectCandidates` (`cleanup.ts:180-208`), тем же `candidateOf`, чтобы
  возраст и размер считались одним кодом.
- `ui/src/api.ts` — `selectRuns` учится списку адресов.
- `vite.config.ts`, `ui/tsconfig.json` — новый общий модуль в перечне
  разрешённых браузеру файлов и в перечне включаемых.
- `ui/src/styles.css` — колонки флажка и проекта, полоса фильтров, полоса
  выбранного.
- Тесты: новый `test/ui-runs-view.test.ts` (фильтры и порядок),
  `test/ui-server.test.ts` (отбор по адресам), `test/ui-format.test.ts`
  (склонение), `test/cleanup.test.ts` (отбор по адресам в ядре).
