## 1. Падающие проверки

- [x] 1.1 Тест в `test/ui-usage.test.ts`: два прогона разных дней и разных
  моделей дают агрегат, где итог периода равен сумме прогонов, `models`
  разложены по убыванию денег, а `days` идут подряд по календарю. Проверка
  обязана падать: модуля ещё нет.
- [x] 1.2 Тест: день внутри периода, в который не начался ни один прогон,
  присутствует в `days` пустой записью, а не пропускается.
- [x] 1.3 Тест: прогон без сводки расхода (`skipUsage`) и прогон со сводкой
  прежней формы (пустой перечень попыток) отдают весь свой итог долей без
  модели, `runsWithoutBreakdown` их считает, и сумма долей сходится с итогом
  периода — в обеих мерах.
- [x] 1.4 Тест: попытка без `cost_usd` не входит в денежные суммы (ни в итог,
  ни в долю модели), её токены входят, а `costUnreportedAttempts` называет их
  число на уровнях итога, пайплайна и захода.
- [x] 1.5 Тест: прогоны группируются по паре «проект + файл пайплайна»;
  прогон, чей манифест не читается, попадает в строку без пайплайна; заходы
  внутри пайплайна идут новейшими первыми.
- [x] 1.6 Тест: прогон без читаемого времени старта не попадает ни в один
  день и ни в один итог периода, а считается счётчиком `undated`; прогон
  старее периода в агрегат не входит вовсе.
- [x] 1.7 Тест: убранный прогон (`cleanupRun`, остались `run.json`,
  `status.json`, `usage.json`) входит в агрегат вместе с разрезом по моделям.
- [x] 1.8 Тест в `test/ui-server.test.ts`: `GET /api/usage` без параметра
  отдаёт агрегат за весь период наблюдений, с `days=7` — за неделю; ответ
  проходит те же проверки полей, что и прочие маршруты витрины.
- [x] 1.9 Тест: негодный `days` (не целое, отрицательное, ноль) отвечает
  `400`, а не подменяется умолчанием; метод, отличный от `GET`, отвечает
  `405`.
- [x] 1.10 Тест в `test/ui-routes.test.ts`: `/usage`, `/usage/7d`,
  `/usage/30d`, `/usage/90d` и `/usage/all` разбираются в маршрут расхода со
  своим периодом; голый `/usage` даёт умолчание в 30 дней; неизвестный хвост
  (`/usage/вчера`) уводит на первый экран, как и всякий неизвестный адрес;
  `MENU` несёт пункт расхода, и он подсвечивается на этом экране.

## 2. Агрегат в демоне

- [x] 2.1 `src/ui/usage.ts`: типы ответа — итог периода, `models`, `days`,
  `pipelines` с заходами, `runsWithoutBreakdown`, `undated`, границы периода
  строками `YYYY-MM-DD`.
- [x] 2.2 `buildUsage(runsRoot, overview, { days, now })`: отбор прогонов
  периода по календарному дню старта в часовом поясе демона; итог каждого
  прогона берётся из `RunOverview.usage`, а не считается заново (design.md,
  Решение 1).
- [x] 2.3 Разрез по моделям: чтение `usage.json` только у прогонов периода
  (`readUsageSoft`), сложение попыток по модели; попытка без поля `model`
  идёт в долю без модели.
- [x] 2.4 Остаток без модели: недостача между итогом прогона и суммой его
  попыток по каждой мере отдельно; излишек (сумма попыток больше итога)
  ужимает доли пропорционально; счётчик прогонов, давших остаток целиком
  (design.md, Решение 2).
- [x] 2.5 Счёт попыток с несообщённой ценой на уровнях захода, пайплайна и
  итога; денежные суммы такую попытку не содержат и нуля вместо цены не
  подставляют.
- [x] 2.6 Группировка по пайплайну парой «ключ проекта + `pipelineFile`», с
  именем из манифеста и строкой без пайплайна для прогонов, где файла нет
  (design.md, Решение 6); сортировки — модели и пайплайны по убыванию денег,
  дни по календарю, заходы новейшими первыми.
- [x] 2.7 Маршрут `GET /api/usage` в `src/ui/server.ts`: разбор `days`
  существующим `readNonNegativeInt` с отказом на ноль и на период за
  `MAX_USAGE_DAYS`, агрегат поверх `watcher.current()`, ответ через
  `sendJson`. Маршрут остаётся чтением.

## 7. Правки по ревью

- [x] 7.1 Итог периода берётся из `RunOverview.usage`, а разрез приводится к
  итогу прогона (`spread`): перенесённая попытка продолженного шага больше не
  раздувает столбцы над итогом. Тест на ужатие долей и на схождение суммы
  столбцов с итогом.
- [x] 7.2 Верхний предел `days` (`MAX_USAGE_DAYS`): период за ним отклоняется
  `400`, а не строит ряд дней в миллионы записей и не отвечает пустым
  агрегатом на переполненную дату. Тест на `3651`, `100000000` и `1e400`.
- [x] 7.3 Классы `.usage-series-*` красят и долю столбца (`fill`), и квадратик
  легенды (`background`): на `span` свойство `fill` не действует, и легенда
  выходила прозрачной.
- [x] 7.4 Перезапрос по `overview` пересоздаётся при смене периода и
  отменяется по номеру запроса: отложенный таймер прошлого периода больше не
  перетирает данные нового.
- [x] 7.5 Ошибка запроса не подменяет собой экран и снимается следующим
  удачным ответом: переключатель периода и уже загруженные данные остаются на
  месте.
- [x] 7.6 Заход несёт свой день (`day`) из ответа демона; браузер день не
  пересчитывает, и сужение графика на пайплайн не зависит от пояса витрины.
- [x] 7.7 Тест «прогон относится к дню своего старта» (заход через полночь) и
  тест пустого периода в `test/ui-server.test.ts`.
- [x] 7.8 Комментарий каркаса `ui/src/App.tsx` называет пять пунктов меню.
