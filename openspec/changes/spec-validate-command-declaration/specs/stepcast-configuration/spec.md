## ADDED Requirements

### Requirement: Команда проверки документов изменения объявляется в конфигурации

Конфигурация SHALL принимать в секции `project.spec` ключ `check` — полную команду, которой репозиторий проверяет документы изменения.

Значение — строка целиком, а не имя инструмента с дописанными движком
подкомандой и флагами: устройство команды знает только объявивший её, и
движок MUST передавать её оболочке не разбирая — тем же правилом, каким он
передаёт `project.check`.

Ключ MUST проверяться той же моделью, что `project.check` и
`project.spec.tool`: непустая строка, строка из одних пробельных символов
отклоняется разбором конфигурации. Требование непустоты MUST быть выражено и
в публикуемой JSON Schema, а не только в модели.

Встроенного умолчания у ключа MUST NOT быть: команда, подставленная за автора,
была бы верна ровно для того репозитория, из которого её списали. Ключ MUST
оставаться необязательным сам по себе — его отсутствие не ошибка, пока на него
никто не сослался.

Ключ MUST быть допустим только в `.stepcast/config.yml` и отклоняться в
`~/.stepcast/config.yml` тем же правилом, что остальные ключи секции
`project`: практика спецификации принадлежит репозиторию, а не машине.

Слияние секции по листьям MUST сохраняться: объявить `check` в одном слое, а
`dir`, `rules` или `tool` в другом можно, и одно другого не затирает.

Ключ MUST приниматься и объектной формой элемента `project.nested_repos` — той
же моделью объявления практики, что у корня, а не отдельной.

#### Scenario: Ключ объявлен в проектном конфиге

- **WHEN** `.stepcast/config.yml` содержит `project: { spec: { check: 'openspec validate "$SPEC_CHANGE" --strict' } }`
- **THEN** действующее значение `project.spec.check` равно объявленной строке целиком
- **AND** отчёт `stepcast config` называет источником этот файл

#### Scenario: Ключ не объявлен

- **WHEN** ни один слой конфигурации не задаёт `project.spec.check`
- **THEN** конфигурация разрешается без ошибки, а значение отсутствует

#### Scenario: Пустая команда

- **WHEN** конфигурация содержит `project: { spec: { check: "   " } }`
- **THEN** чтение конфигурации завершается ошибкой, называющей файл и ключ

#### Scenario: Ключ в глобальном конфиге

- **WHEN** `~/.stepcast/config.yml` содержит `project: { spec: { check: "make spec-check" } }`
- **THEN** чтение конфигурации завершается ошибкой, называющей файл и предлагающей `.stepcast/config.yml`

#### Scenario: Соседний ключ группы не затирается

- **WHEN** `.stepcast/config.yml` объявляет `project.spec.dir`, `project.spec.rules` и `project.spec.tool`, а документ пайплайна — только `project.spec.check`
- **THEN** действуют все четыре значения: три из конфигурации, `check` из пайплайна

#### Scenario: Вложенный репозиторий объявляет свою команду

- **WHEN** элемент `project.nested_repos` объявлен объектом `{ dir: backend, check: "make test", spec: { dir: docs/changes, rules: docs/rules.md, tool: make, check: "make spec-check" } }`
- **THEN** конфигурация разрешается без ошибки, а объявление этого репозитория несёт свою команду проверки документов изменения

#### Scenario: Публикуемая схема повторяет требование

- **WHEN** `schema/config.schema.json` описывает `project.spec.check`
- **THEN** описание требует строку с непустой длиной и образцом непробельного символа — тем же, что у `project.check`
