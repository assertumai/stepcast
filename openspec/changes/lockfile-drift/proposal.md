## Why

Дорожки петли поднимаются с чистого HEAD установкой зависимостей заново, и
сейчас это `npm install`, который тихо чинит расхождение между
`package.json` и `package-lock.json`, а не показывает его. Если расхождение
случится снова (в прошлом такое уже было — лок просил `@types/node@26.2.0`
при объявленном в манифесте `^24.0.0`), об этом можно не узнать до случайного
`npm ci` в чистом дереве, где ровно эта проверка встроена в саму команду и
проваливает установку ещё до первого шага. `npm run check` сегодня такого
расхождения не ловит вовсе.

На момент этого изменения корневая запись `package-lock.json`
(`packages[""].dependencies`/`devDependencies`) уже посимвольно совпадает с
`package.json` — конкретный случай из обоснования пункта очереди на HEAD не
воспроизводится. Остаётся сам пробел: ничто не мешает дрейфу накопиться снова
незамеченным.

Признак выполненности пункта очереди называет условием ещё и обновление
`docs/status.md` — этого документа в репозитории больше нет, его снял
`drop-status-doc` (коммит `f45e3c62`), и `test/no-status-doc.test.ts` держит
красным любое упоминание сведённого учёта. Формулировка `backlog.md` не
переигрывалась вслед за той правкой; обновлять здесь нечего.

## What Changes

- Добавляется тест, сверяющий диапазоны версий в `dependencies` /
  `devDependencies` / `optionalDependencies` `package.json` с записью
  корневого пакета `packages[""]` в `package-lock.json` — той же сверкой,
  которую перед установкой делает `npm ci`. Тест красный при любом
  расхождении хотя бы одной зависимости.
- Новый тест ложится в `test/`, компилируется вместе с остальными в
  `dist/test` и подхватывается уже существующим `npm run test:only` — части
  `npm run check`. Ни `package.json`, ни состав `npm run check` менять не
  нужно.
- Правка самого `package-lock.json` не планируется: он уже в синхроне с
  `package.json` на HEAD. Задача синхронизации остаётся в `tasks.md` как
  проверка (`npm ci` в чистом рабочем дереве), а не как известная правка.

## Capabilities

### New Capabilities

- `dependency-lockfile`: гарантирует, что диапазоны версий зависимостей в
  `package-lock.json` совпадают с объявленными в `package.json`, и что
  `npm run check` отказывает при расхождении, а не пропускает его молча
  дальше к случайному отказу `npm ci`.

## Impact

- Новый файл `test/lockfile-sync.test.ts` — часть `npm run check` через уже
  существующий `test:only`, без изменений `package.json`.
- `package-lock.json` — изменения не ожидаются (уже синхронен); если
  проверка на реализации найдёт иное, лок переигрывается и коммитится.
