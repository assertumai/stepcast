## ADDED Requirements

### Requirement: Схемы документов порождаются моделями разбора

Схемы документов пайплайна и работы для редактора SHALL порождаться теми же моделями, какими документ проверяется при разборе, и расхождение файла с моделью MUST обнаруживаться проверкой репозитория, а не молча переживать сборку.

Схемы, поставляемые пакетом (`schema/pipeline.schema.json`,
`schema/job.schema.json`), MUST печататься из моделей встроенного набора
предикатов и MUST оставаться частью пакета. Печать схем пакета и печать схем
проекта MUST идти одним кодом: две реализации одного преобразования
разошлись бы, и подсказка редактора снова начала бы врать.

#### Scenario: Модель изменили, схему не перегенерировали

- **WHEN** модель документа изменена, а файл `schema/pipeline.schema.json` остался прежним
- **THEN** проверка репозитория завершается ошибкой, называющей разошедшийся файл

#### Scenario: Пакет поставляет схемы

- **WHEN** пакет `stepcast` установлен
- **THEN** в нём есть `schema/pipeline.schema.json` и `schema/job.schema.json` встроенного набора предикатов

### Requirement: Команда печатает схему документов проекта

Команда `stepcast schema` SHALL печатать в репозиторий проекта схемы его документов пайплайна и работы, построенные от того же реестра вкладов, каким документ этого проекта разбирается.

Схемы MUST записываться файлами `pipeline.schema.json` и `job.schema.json` в
каталог `.stepcast/schema/` проекта; ключ `--out` MUST переопределять каталог.
Команда MUST называть записанные пути. Плагины проекта MUST загружаться тем
же ходом, что и для остальных команд: отказ загрузки объявленного плагина
MUST прекращать команду ошибкой конфигурации и MUST NOT приводить к записи
схемы от неполного реестра. Ключ каждого предиката, внесённого загруженным
плагином, MUST признаваться напечатанной схемой везде, где документ допускает
предикат, — и в `expect` шага, и в `until.check` работы.

#### Scenario: Проект объявил плагин с предикатом

- **WHEN** конфигурация проекта объявляет плагин, вносящий предикат `http_ok`, и вызвана `stepcast schema`
- **THEN** записанные схемы признают документ, объявляющий `expect: [{ http_ok: … }]` в шаге и `until.check: [{ http_ok: … }]` в работе

#### Scenario: Опечатка остаётся ошибкой

- **WHEN** документ проверяется схемой проекта и объявляет `expect: [{ exit_cod: 0 }]`
- **THEN** схема отклоняет документ: ключ не известен ни встроенно, ни плагином

#### Scenario: Каталог вывода переопределён

- **WHEN** вызвана `stepcast schema --out schemas`
- **THEN** файлы записаны в `schemas/`, и команда называет эти пути

#### Scenario: Плагин не загружается

- **WHEN** объявленный плагин не импортируется
- **THEN** команда завершается ошибкой конфигурации и не записывает ни одного файла

### Requirement: Проект без плагинных предикатов получает схему пакета

Схема, напечатанная для проекта, у которого ни один загруженный плагин не вносит предикатов, SHALL совпадать с поставляемой пакетом схемой того же документа побайтово.

Появление плагинных предикатов MUST быть единственной причиной различия:
схема проекта MUST NOT заводить собственных полей документа и MUST NOT менять
описание встроенных. Отличие от поставляемой схемы MUST называться в самой
схеме — перечнем предикатов, которые она знает, и внёсших их плагинов.

#### Scenario: Плагинов нет

- **WHEN** проект не объявляет плагинов и вызвана `stepcast schema`
- **THEN** записанный `pipeline.schema.json` побайтово равен поставляемому пакетом

#### Scenario: Плагин без предикатов

- **WHEN** загруженный плагин вносит только бэкенд
- **THEN** записанная схема побайтово равна поставляемой пакетом

#### Scenario: Схема называет, чем отличается

- **WHEN** загруженный плагин вносит предикат
- **THEN** записанная схема содержит описание с именем предиката и именем внёсшего его плагина

### Requirement: Форма значения плагинного предиката описана схемой вклада

Схема документа, напечатанная для проекта, SHALL описывать значение плагинного предиката той же JSON Schema, какой это значение проверяется при разборе, — объявленной вкладом плагина.

Схема значения, которую нельзя вложить в документ — она не принимается
валидатором, либо содержит на любом уровне ключ ссылки или цели ссылки
(`$ref`, `$id`, `$schema`, `$anchor`, `$dynamicRef`, `$dynamicAnchor`,
`$recursiveRef`, `$recursiveAnchor`), — MUST NOT отменять печати: ключ
предиката MUST оставаться признанным, значение MUST оставаться
неограниченным, а команда MUST печатать заметку, называющую предикат, внёсший
его плагин и причину. Молча терять проверку значения команда MUST NOT.

Напечатанная схема документа MUST компилироваться валидатором целиком: схема,
которую редактор не может загрузить, теряет подсказку по всему документу
сразу. Схема значения, после вложения которой документ не компилируется, MUST
обрабатываться как невложимая — заметкой, а не отказом печати.

#### Scenario: Значение проверяется схемой вклада

- **WHEN** плагин объявил предикату `http_ok` схему значения `{ "type": "string" }`, и документ объявляет `expect: [{ http_ok: 42 }]`
- **THEN** схема проекта отклоняет документ

#### Scenario: Схема значения содержит ссылку

- **WHEN** плагин объявил схему значения с `$ref`
- **THEN** ключ предиката признаётся схемой, значение остаётся неограниченным, и команда печатает заметку с именем предиката, именем плагина и причиной

#### Scenario: Схема значения непригодна

- **WHEN** объявленная плагином схема значения не принимается валидатором
- **THEN** печать остальных схем происходит, а команда печатает заметку с причиной

#### Scenario: Собранный документ не компилируется

- **WHEN** схема значения принимается валидатором сама по себе, но документ с ней вложенной валидатор не компилирует
- **THEN** ключ предиката признаётся схемой, значение остаётся неограниченным, схемы остальных предикатов остаются вложенными, и команда печатает заметку с причиной

### Requirement: Устаревшая схема проекта называется линтом

Команда `stepcast lint` SHALL сообщать предупреждением, что записанная схема проекта разошлась с тем, что дал бы текущий состав плагинов, — устаревшая подсказка редактора врёт так же, как статическая.

Проверка MUST выполняться, только если файл схемы проекта существует, и MUST
сравнивать его с тем, что напечаталось бы сейчас. Диагностика MUST называть
путь файла и способ его перегенерировать. Она MUST быть предупреждением:
устаревшая подсказка редактора прогону не мешает, и останавливать им прогон
MUST NOT.

#### Scenario: Плагин добавлен, схема не перегенерирована

- **WHEN** `.stepcast/schema/pipeline.schema.json` записан до объявления плагина с предикатом, и вызвана `stepcast lint`
- **THEN** печатается предупреждение с путём файла и подсказкой перегенерировать, а код возврата остаётся нулевым

#### Scenario: Схема свежа

- **WHEN** записанная схема совпадает с текущей
- **THEN** предупреждения нет

#### Scenario: Схемы проекта нет

- **WHEN** каталог `.stepcast/schema/` отсутствует
- **THEN** линт о схеме проекта не говорит ничего
