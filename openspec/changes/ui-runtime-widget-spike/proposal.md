## Why

Витрина сегодня **закрыта для пользователя по построению**.

Она собирается Vite в один самодостаточный файл и отдаётся демоном как строка,
прочитанная с диска один раз за запуск (`viteSingleFile`, `vite.config.ts:26`;
`dashboardHtml`, `src/ui/assets.ts:38`). Это свойство выбрано намеренно и
записано в комментарии обоих файлов: демон отдаёт **одну** страницу и не
становится файловым сервером с разбором MIME и защитой от обхода путей. Цена —
то, что любая правка интерфейса требует `npm run build:ui` и перезапуска
демона, а код пользователя в страницу не попадает вовсе: попасть ему некуда,
`App.tsx` выбирает экран из девяти импортированных на сборке модулей.

Замысел группы `ui-runtime` — личный кабинет, где пользователь сам пишет
виджеты, экраны и панели управления файлами в своём проекте. Девять пунктов,
идущих следом (`cordis-kernel-daemon` … `dashboards-as-files`), стоят на одном
допущении: **исходник пользователя можно скомпилировать демоном, отдать
браузеру и заменить на живой странице**. Допущение недёшево — в нём пять
независимых мест, каждое из которых умеет не сработать:

1. **Компилятор внутри демона.** `esbuild` в дереве зависимостей отсутствует:
   Vite 8 собирает витрину Rolldown (`node_modules/rolldown` —
   единственное совпадение в `package-lock.json`). Значит, компилятор — новая
   зависимость времени исполнения у пакета, чьи нынешние четыре зависимости
   (`ajv`, `execa`, `yaml`, `zod`) не тянут платформенных бинарников вовсе.
2. **Единственный экземпляр React.** Виджет, получивший свой React, молча
   ломает хуки. Витрина собрана единым файлом, и её React не адресуется
   модулем — значит, разделить экземпляр обычным способом (оба импортируют
   один URL) нельзя.
3. **Замена на лету.** Реестр модулей браузера неизменен: повторный `import()`
   того же адреса возвращает прежний модуль. Перезагрузка страницы и
   перезапуск демона запрещены признаком выполненности.
4. **Отдача файлов.** Демон получает первый маршрут, отдающий содержимое,
   выведенное из пути запроса, — ровно то, от чего он до сих пор уклонялся.
5. **Жизненный цикл компилятора.** Нативный `esbuild` поднимает служебный
   процесс; не остановленный, он переживает `stepcast down` и вешает
   `node --test`.

Проверять это внутри перестройки витрины на Cordis — значит смешать два
незнакомых риска в одном изменении. Спайк проходит цепочку целиком на
**одном виджете**, ничего не перестраивая, и оставляет после себя два
результата: работающий образец, с которого снимаются последующие пункты, и
записанное решение о компиляторе с замером.

## What Changes

- **Каталог виджетов проекта — `<проект>/.stepcast/widgets/<id>.tsx`.**
  Проекты демон уже знает: `listProjects` читает `projects.json`
  (`src/core/journal/reader.ts:233`), а экран «Шаги» тем же обходом читает
  `<проект>/.stepcast/steps/` (`buildSteps`, `src/ui/steps.ts:149`). Виджеты
  встают соседним каталогом и читаются тем же способом.
- **Адрес виджета несёт ключ проекта: `/widgets/<projectKey>/<id>.js`.** Пункт
  очереди называет `/widgets/<id>.js`; это уточнено намеренно. Демон
  наблюдает за всеми проектами разом, и `<id>` без проекта становится
  двусмысленным в тот день, когда `clock.tsx` заведут в двух проектах. Ключ
  проекта — та же единица адресации, которой уже адресуется прогон
  (`runHref`, `src/ui/routes.ts`).
- **Компиляция при запросе, `transform`, а не `build`.** Демон компилирует
  один файл, не разрешая его импортов. Бандлинг открыл бы чтение произвольных
  файлов диска через `import '../../../..'` — то есть обошёл бы белый список
  путей изнутри. Локальные импорты внутри виджета — предмет следующего пункта
  (`user-plugins-from-files`), не этого.
- **Три имени резолвятся в модули демона через import map.** Страница
  объявляет карту для `react`, `react-dom` и `react/jsx-runtime`; демон отдаёт
  по этим адресам сгенерированные модули-переходники, реэкспортирующие
  экземпляр React **самой страницы**, опубликованный ею при загрузке. Отсюда
  единственность экземпляра следует по построению, а не по совпадению версий.
  Перечень реэкспортируемых имён явный — это и есть объявленная поверхность
  API виджета.
- **Событие `widgets` в уже существующем потоке `/api/events`.** Наблюдатель
  (`src/ui/watcher.ts:100`) получает третью часть отпечатка — рядом с `runs` и
  `backlog`, тем же приёмом «mtime и размер». Событие несёт состав виджетов
  каждого проекта и версию каждого; версия идёт в запрос
  (`/widgets/<key>/<id>.js?v=<версия>`), и переимпорт по новому адресу
  обходит неизменяемый реестр модулей.
- **Ошибка компиляции — это модуль, а не отказ HTTP.** `import()` превращает
  любой не-2xx в невнятный `TypeError` без диагностики, поэтому демон на
  непроходящий файл отдаёт 200 и модуль, экспортирующий разобранную ошибку —
  файл, строку, колонку, текст. Страница показывает её карточкой на месте
  виджета. Заголовок ответа помечает такой модуль, чтобы отказ был виден
  проверке и `curl`, а не только глазами.
- **Каждый виджет отделён границей ошибок.** Исключение при отрисовке валит
  дерево React целиком; без границы свойство «остальная страница цела»
  держалось бы только на исправных виджетах.
- **Экран «Виджеты» — леса спайка.** Пункт меню, перечисляющий виджеты
  проектов и отрисовывающий каждый карточкой. Заявлен как временный: его
  сменят `builtin-pages-as-plugins` и `dashboards-as-files`.
- **Решение о компиляторе записано в `docs/` с замером.** `esbuild` против
  `esbuild-wasm`: холодное и тёплое время компиляции представительного
  виджета, вес установки, поведение при отсутствующем платформенном бинарнике.
  Замер воспроизводим командой, а не назван по памяти.
- **Компилятор не переживает демон.** Служебный процесс `esbuild`
  останавливается вместе с сервером (`UiServer.close()`), а поднимается лениво
  — первым запросом виджета, чтобы демон без виджетов не платил за компилятор
  ни памятью, ни процессом.

## Capabilities

### New Capabilities

- `ui-widgets`: виджет пользователя как единица — где лежит файл, чем и когда
  компилируется, каким адресом отдаётся, что экспортирует, какими именами
  пользуется, как объявляется его замена и как называется его поломка; границы
  отдачи файлов демоном.

### Modified Capabilities

- `ui-dashboard`: страница объявляет import map и публикует свой экземпляр
  React; поток `/api/events` получает событие `widgets`; экран виджетов,
  переимпорт по событию без перезагрузки, показ ошибки компиляции на месте
  виджета и изоляция сбойного виджета от остальной страницы.
- `ui-daemon`: демон отдаёт, кроме страницы витрины, сгенерированный JS по
  двум объявленным формам адреса и ничего сверх того; компилятор поднимается
  лениво и не переживает остановку демона.

## Impact

- Добавляется: `src/ui/widgets.ts` — перечисление виджетов проекта, разрешение
  пути, компиляция и кеш результата; `src/ui/widgetRuntime.ts` — тексты
  модулей-переходников и перечень реэкспортируемых имён;
  `ui/src/pages/Widgets.tsx` — экран; `ui/src/widgetHost.tsx` — загрузка
  модуля, граница ошибок, карточка ошибки компиляции.
- Изменяется: `src/ui/server.ts` — маршруты `/widgets/...`, событие `widgets` в
  `handleEvents` (`:774`), подъём и остановка компилятора в `createUiServer`
  (`:835`) рядом с `registryCache` (`:849`); `src/ui/watcher.ts` — третья часть
  отпечатка и `currentWidgets()`; `src/ui/routes.ts` — маршрут и пункт `MENU`;
  `ui/index.html` — import map до первого модульного скрипта; `ui/src/main.tsx`
  — публикация экземпляра React до отрисовки; `ui/src/live.ts` — подписка на
  событие `widgets`; `ui/src/App.tsx` — новый экран; `ui/tsconfig.json` —
  включение нового общего модуля, если он появится; `vite.config.ts` — проксирование
  `/widgets` на демон в режиме `npm run dev:ui`.
- Зависимости: `esbuild` (или `esbuild-wasm` — по итогу замера) в
  `dependencies` пакета. Первая зависимость времени исполнения с платформенным
  бинарником; её отсутствие или неустановленность обязана давать названную
  ошибку на экране виджетов, а не падение демона.
- Тесты: `test/ui-widgets.test.ts` — компиляция, кеш по mtime, ошибка
  компиляции как модуль, обход каталога (`..`, абсолютный путь, символическая
  ссылка наружу, чужое расширение, неизвестный ключ проекта), остановка
  компилятора вместе с сервером; `test/ui-watcher.test.ts` — появление,
  правка и удаление файла виджета меняют отпечаток, неизменный каталог не
  порождает события; `test/ui-server.test.ts` — отдача модуля и переходников,
  событие `widgets` в потоке `/api/events`, отсутствие маршрутов сверх двух
  объявленных форм.
- Документация: новый `docs/widgets.md` — файл виджета, адрес, доступные
  имена, событие замены, контракт ошибки, границы отдачи и решение о
  компиляторе с замером; `README.md` — строка о виджетах в обзоре
  возможностей.
- Не входит в изменение (см. `design.md`, Non-Goals): плагин с серверной
  половиной, слои проект/дом/встроенное, локальные импорты и зависимости
  внутри виджета, props и доступ виджета к данным прогонов, дашборд как файл,
  сохранение раскладки, проверка типов виджета, песочница для чужого кода.
