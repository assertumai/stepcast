## ADDED Requirements

### Requirement: Виджет проекта — файл в объявленном каталоге

Виджетом проекта SHALL считаться файл `<проект>/.stepcast/widgets/<id>.tsx`, лежащий непосредственно в этом каталоге, где `<id>` — один безопасный сегмент пути без разделителей и без шага вверх по дереву. Путь проекта берётся из указателя `projects.json` тем же обходом, каким его берёт каталог переиспользуемых шагов. Проект без записи о пути, проект с несуществующим путём и проект без каталога виджетов SHALL считаться проектом без виджетов, а не ошибкой. Вложенные каталоги и файлы с иным расширением MUST NOT считаться виджетами.

#### Scenario: Файл становится виджетом проекта

- **WHEN** в `<проект>/.stepcast/widgets/` появился файл `clock.tsx`
- **THEN** виджет `clock` значится в составе виджетов этого проекта

#### Scenario: Каталога виджетов нет

- **WHEN** у проекта нет каталога `.stepcast/widgets/`
- **THEN** состав его виджетов пуст, и ни демон, ни витрина не сообщают об ошибке

#### Scenario: Проект без известного пути

- **WHEN** каталог прогонов проекта есть, но его пути нет в `projects.json`
- **THEN** виджеты у этого проекта не ищутся, и остальные проекты остаются с их виджетами

#### Scenario: Вложенный файл и чужое расширение

- **WHEN** в каталоге виджетов лежат `sub/deep.tsx` и `notes.md`
- **THEN** ни `sub/deep`, ни `notes` не значатся виджетами

### Requirement: Демон компилирует виджет при запросе и отдаёт его ES-модулем

Демон SHALL отдавать по адресу `/widgets/<projectKey>/<id>.js` результат компиляции файла виджета как ES-модуль с типом содержимого `text/javascript`. Компиляция MUST снимать типы и разворачивать JSX автоматическим преобразованием, но MUST NOT разрешать импорты файла: имена `react`, `react-dom` и `react/jsx-runtime` остаются в модуле импортами, то есть внешними. Модуль виджета SHALL экспортировать компонент по умолчанию. Неизвестный ключ проекта, проект без известного пути и отсутствующий файл виджета SHALL давать один и тот же отказ 404, не сообщая, какая из причин сработала.

#### Scenario: Виджет отдан модулем

- **WHEN** запрошен `/widgets/<ключ проекта>/clock.js` для существующего файла `clock.tsx`
- **THEN** ответ — ES-модуль с типом `text/javascript`, экспортирующий компонент по умолчанию

#### Scenario: Имена React остаются импортами

- **WHEN** виджет пользуется хуком и JSX
- **THEN** отданный модуль содержит импорты `react` и `react/jsx-runtime`, а не встроенный в него React

#### Scenario: Виджета нет

- **WHEN** запрошен виджет, файла которого нет, либо запрошен неизвестный ключ проекта
- **THEN** ответ 404, и по нему не видно, какие проекты известны демону

### Requirement: Отдача содержимого ограничена двумя формами адреса

Демон SHALL отдавать выведенное из пути запроса содержимое ровно по двум формам адреса: `/widgets/<projectKey>/<id>.js` и `/widgets/runtime/<имя>.js`, где `<имя>` принадлежит закрытому перечню модулей-переходников. Оба сегмента адреса виджета MUST проверяться как безопасные сегменты пути, итоговый путь файла MUST оставаться внутри каталога виджетов проекта после приведения к реальному пути, и расширение исходника MUST быть фиксированным. Любой другой путь под `/widgets/` SHALL давать 404, а перечисления содержимого каталога демон MUST NOT отдавать ни под каким адресом.

#### Scenario: Шаг вверх по дереву

- **WHEN** запрошен виджет, чей идентификатор содержит `..` или разделитель пути
- **THEN** запрос отклонён, файл не отдан

#### Scenario: Абсолютный путь в адресе

- **WHEN** запрошен виджет, чей идентификатор выглядит абсолютным путём
- **THEN** запрос отклонён, файл не отдан

#### Scenario: Символическая ссылка из каталога виджетов наружу

- **WHEN** в каталоге виджетов лежит символическая ссылка `escape.tsx` на файл вне этого каталога, и она запрошена
- **THEN** запрос отклонён, содержимое файла за пределами каталога не отдано

#### Scenario: Путь под /widgets сверх объявленных форм

- **WHEN** запрошен путь под `/widgets/`, не совпадающий ни с формой виджета, ни с формой переходника
- **THEN** ответ 404, и содержимое каталога не перечислено

### Requirement: Имена React резолвятся в модули-переходники с экземпляром страницы

Демон SHALL отдавать по адресам `/widgets/runtime/<имя>.js` сгенерированные модули-переходники, которые читают экземпляры `react`, `react-dom` и `react/jsx-runtime`, опубликованные самой страницей витрины, и реэкспортируют из них имена закрытого объявленного перечня. Перечень имён MUST быть объявлен одним местом и MUST совпадать с тем, что действительно экспортирует React используемой версии. Переходник MUST отдавать и экспорт по умолчанию для тех имён, у которых он есть у самого пакета, — иначе обычная идиома `import React, { useState } from 'react'` не связывается вовсе. Виджет, импортирующий эти имена, SHALL получать тот же экземпляр React, что и витрина, — так, что состояние хуков внутри виджета работает. Переходник, не нашедший опубликованных экземпляров, MUST отказывать названной ошибкой, называющей причину.

#### Scenario: Хук внутри виджета работает

- **WHEN** виджет держит состояние хуком `useState` и перерисовывается по действию пользователя
- **THEN** состояние сохраняется между перерисовками, то есть экземпляр React у виджета и у витрины один

#### Scenario: Перечень имён не разъезжается с React

- **WHEN** перечень реэкспортируемых имён сверяется с экспортом установленной версии React
- **THEN** каждое объявленное имя действительно экспортируется, а отсутствующее называет отказ проверки

#### Scenario: Виджет написан с экспортом по умолчанию

- **WHEN** виджет импортирует React идиомой `import React, { useState } from 'react'`
- **THEN** модуль связывается, и оба имени указывают на экземпляр витрины

#### Scenario: Переходник открыт без страницы витрины

- **WHEN** адрес `/widgets/runtime/react.js` запрошен и исполнен там, где страница не публиковала своих экземпляров
- **THEN** модуль отказывает ошибкой, называющей отсутствие опубликованного экземпляра, а не обращением к неопределённому значению

### Requirement: Ошибка компиляции отдаётся модулем, а не отказом запроса

Демон SHALL отвечать на непроходящий файл виджета кодом 200 и ES-модулем, экспортирующим разобранную ошибку компиляции: путь файла, строку, колонку и текст. Такой ответ MUST нести заголовок, по которому отказ виден без разбора JavaScript. Отказом запроса (кодом 4xx или 5xx) ошибка компиляции MUST NOT сообщаться: динамический импорт превращает не-2xx ответ в исключение без тела, теряя файл и строку. Исправление файла SHALL давать по следующему запросу рабочий модуль без перезапуска демона.

#### Scenario: Файл не компилируется

- **WHEN** запрошен виджет, чей файл содержит синтаксическую ошибку
- **THEN** ответ 200, модуль экспортирует ошибку с путём файла, строкой, колонкой и текстом, и ответ помечен заголовком ошибки

#### Scenario: Ошибка исправлена

- **WHEN** файл, ранее не компилировавшийся, исправлен и виджет запрошен снова
- **THEN** отдан рабочий модуль, демон не перезапускался

### Requirement: Состав и версия виджетов объявляются потоком событий

Демон SHALL объявлять поток событий витрины составом виджетов каждого проекта и версией каждого виджета, где версия выведена из отпечатка файла — времени изменения и размера. Состав виджетов MUST наблюдаться тем же единственным наблюдателем демона, что и корень прогонов, отдельной частью его отпечатка, и MUST NOT перечитываться, когда изменилась лишь другая часть. Эта часть отпечатка MUST покрывать и состав самих проектов, а не только файлы виджетов: проект без виджетов — тоже раздел состава. Событие о виджетах SHALL отправляться подписчику только тогда, когда состав или версия действительно изменились. Версия SHALL служить признаком, по которому запрос виджета отличает новую редакцию файла от прежней.

#### Scenario: Правка файла меняет версию

- **WHEN** файл виджета изменён
- **THEN** поток событий объявляет тот же виджет с другой версией

#### Scenario: Появление и удаление виджета

- **WHEN** файл виджета добавлен, а другой удалён
- **THEN** поток событий объявляет новый состав виджетов проекта

#### Scenario: Появился проект без виджетов

- **WHEN** в указателе проектов появился проект, у которого нет ни одного файла виджета
- **THEN** состав виджетов объявляет его пустым разделом, не дожидаясь правки какого-нибудь виджета

#### Scenario: Неизменные виджеты не порождают событий

- **WHEN** идёт прогон и обзор меняется на каждом такте наблюдателя, а каталоги виджетов не менялись
- **THEN** события о виджетах подписчику не отправляются

### Requirement: Результат компиляции кешируется по отпечатку файла

Демон SHALL кешировать результат компиляции виджета по пути файла вместе с его временем изменения и размером и MUST NOT компилировать заново, пока отпечаток тот же. Кеш MUST принадлежать серверу витрины, а не модулю, чтобы несколько серверов в одном процессе не делили чужие результаты. Число записей кеша SHALL быть ограничено, а давние записи — вытесняться, чтобы долгая череда правок не копила записи без предела.

#### Scenario: Повторный запрос без правки

- **WHEN** тот же виджет запрошен дважды, а файл между запросами не менялся
- **THEN** второй ответ отдан без повторной компиляции

#### Scenario: Правка обесценивает кеш

- **WHEN** файл виджета изменён и виджет запрошен снова
- **THEN** отдан результат компиляции новой редакции файла

#### Scenario: Два сервера в одном процессе

- **WHEN** в одном процессе поднято два сервера витрины с разными каталогами проектов
- **THEN** каждый отдаёт виджеты своего каталога, и результат одного не попадает в ответ другого
