## MODIFIED Requirements

### Requirement: Потолки limits ограничивают пайплайн

Значения `limits` из конфигурации SHALL задавать верхнюю границу для
соответствующих значений пайплайна, включая денежный потолок `limits.cost`.
Пайплайн, превышающий потолок, MUST отклоняться с ошибкой, а не урезаться
молча. Значения `limits` MUST оставаться границей для объявляемого и MUST NOT
применяться как самостоятельный потолок прогона.

#### Scenario: Бюджет пайплайна выше потолка

- **WHEN** конфиг задаёт `limits.tokens: 5M`, а пайплайн `budget.tokens: 8M`
- **THEN** `stepcast lint` завершается ошибкой с указанием обоих значений
- **AND** `stepcast run` не начинает прогон

#### Scenario: Число попыток выше потолка

- **WHEN** конфиг задаёт `limits.attempts: 5`, а шаг `attempts.max: 9`
- **THEN** `stepcast lint` завершается ошибкой

#### Scenario: Денежный потолок выше потолка проекта

- **WHEN** конфиг задаёт `limits.cost: "$50"`, а пайплайн `budget.cost: 200`
- **THEN** `stepcast lint` завершается ошибкой с указанием обоих значений
- **AND** `stepcast run` не начинает прогон

#### Scenario: Денежный потолок проекта не ограничивает прогон сам по себе

- **WHEN** пайплайн не объявляет `budget.cost`, а конфиг задаёт `limits.cost`
- **THEN** прогон исполняется без денежного потолка
