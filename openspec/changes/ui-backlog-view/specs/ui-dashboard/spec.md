## ADDED Requirements

### Requirement: Витрина показывает очередь улучшений отдельным экраном

Витрина SHALL показывать очередь улучшений отдельным экраном, доступным пунктом бокового меню и собственным адресом, и SHALL показывать на нём пункты очереди каждого проекта, видимого в обзоре. По каждому пункту экран MUST показывать его слаг, статус, заголовок, действующую группу и объявленную дорожку; у пункта, взятого в работу, MUST быть виден момент взятия, у отказавшего — причина отказа. Пункты проекта SHALL идти в порядке файла очереди, потому что этот порядок и есть приоритет отбора. Проект, у которого нет ни одного прогона, экран MUST NOT показывать вовсе; проект, у которого нет файла очереди, MUST оставаться без раздела и MUST NOT считаться ошибкой. Проект, чьего пути нет в указателе `projects.json`, MUST пропускаться, а не подписываться догадкой о пути. Проект, чей файл очереди есть, но не содержит ни одного пункта, MUST показываться разделом, прямо говорящим, что очередь пуста, а не пустой таблицей из одних заголовков колонок.

#### Scenario: Пункт меню ведёт на экран очереди

- **WHEN** пользователь открывает витрину
- **THEN** в боковом меню есть пункт «Бэклог», ведущий на экран очереди по собственному адресу

#### Scenario: Очереди двух проектов на одном экране

- **WHEN** у двух проектов, чьи прогоны видны в обзоре, есть свои файлы очереди
- **THEN** экран показывает разделы обоих проектов с пунктами каждого

#### Scenario: Порядок пунктов совпадает с порядком файла

- **WHEN** в файле очереди пункты идут в некотором порядке
- **THEN** экран показывает их в том же порядке, не переставляя по статусу или заголовку

#### Scenario: Действующая группа пункта без поля group

- **WHEN** пункт очереди не объявляет поле `group`
- **THEN** экран показывает его действующей группой слаг самого пункта

#### Scenario: Пункт без объявленной дорожки

- **WHEN** пункт очереди не объявляет поле `track`
- **THEN** экран показывает дорожку пустой и MUST NOT подставлять слово по умолчанию

#### Scenario: Взятый в работу и отказавший пункты

- **WHEN** один пункт помечен `in_progress` с моментом взятия, а другой — `failed` с причиной
- **THEN** экран показывает статус каждого, момент взятия у первого и причину отказа у второго

#### Scenario: Проект без файла очереди

- **WHEN** у проекта, чьи прогоны видны в обзоре, нет файла `backlog.md`
- **THEN** экран не показывает раздела этого проекта и не сообщает об ошибке

#### Scenario: Файл очереди без единого пункта

- **WHEN** у проекта есть файл очереди, но пунктов в нём не осталось
- **THEN** раздел проекта говорит, что очередь пуста, вместо таблицы без единой строки

#### Scenario: Проект без прогонов

- **WHEN** в корне прогонов нет ни одного прогона проекта
- **THEN** экран не показывает его очереди, даже если файл очереди у проекта есть

#### Scenario: Ни у одного проекта нет очереди

- **WHEN** ни у одного наблюдаемого проекта нет файла очереди
- **THEN** экран объясняет, что очередей не найдено, и называет, где демон их ищет

### Requirement: Очередь читается тем же разбором, что и команда очереди

Демон SHALL разбирать файл очереди тем же кодом разбора, которым пользуется команда `stepcast backlog list`, и MUST NOT заводить вторую реализацию формата очереди. Публикуемая запись пункта, которую печатают `backlog list` и `backlog pick`, MUST оставаться неизменной: показ на витрине MUST NOT расширять её договор. Файл очереди, который не разбирается, SHALL показываться разделом проекта с объяснением — текстом отказа, файлом и местом внутри документа, каждым отдельным полем, — и MUST NOT ни пропускаться молча, ни отменять показ очередей остальных проектов. Пункт с полем, которого формат не знает, MUST показываться, а не отвергаться.

#### Scenario: Отказ разбора показан с объяснением

- **WHEN** файл очереди проекта содержит строку, не разбираемую ни как заголовок пункта, ни как поле
- **THEN** раздел этого проекта показывает текст отказа, имя файла и место внутри документа — каждое отдельным полем

#### Scenario: Сломанная очередь не отменяет остальных

- **WHEN** очередь одного проекта не разбирается, а очередь второго разбирается
- **THEN** экран показывает объяснение по первому проекту и пункты по второму

#### Scenario: Неизвестное поле пункта переживает показ

- **WHEN** пункт очереди объявляет поле, которого нет в перечне известных
- **THEN** пункт показан на экране, а разбор не отвергает его

#### Scenario: Договор команды очереди не тронут

- **WHEN** витрина показывает статус пункта
- **THEN** запись пункта, печатаемая `stepcast backlog list` и `stepcast backlog pick`, остаётся прежней

### Requirement: Очередь обновляется без перезагрузки страницы

Пока экран очереди открыт, витрина SHALL получать изменения файлов очереди по мере того, как их правят: смену статуса пункта по ходу прогона, появление новых пунктов и исчезновение прежних. Обновление MUST происходить без ручной перезагрузки страницы браузером и MUST приходить тем же живым потоком, что и обзор, без второй подписки на вкладку. Демон SHALL перечитывать файл очереди, только когда тот изменился, и SHALL вести это наблюдение одним общим наблюдателем, разделяемым всеми подключёнными клиентами, а не отдельным на каждое подключение. Изменение прогона, не затронувшее файлов очереди, MUST NOT ни вызывать разбора этих файлов заново, ни слать открытому клиенту повторный кадр прежней очереди.

#### Scenario: Статус пункта меняется на лету

- **WHEN** экран очереди открыт, и идущий заход помечает свой пункт `in_progress`, а затем `done`
- **THEN** экран показывает новый статус пункта без перезагрузки страницы

#### Scenario: Новый пункт появляется сам

- **WHEN** экран очереди открыт, и в файл очереди дописан новый пункт
- **THEN** он появляется на экране без перезагрузки страницы

#### Scenario: Несколько открытых вкладок

- **WHEN** экран очереди открыт в нескольких вкладках одновременно
- **THEN** все они получают одни и те же обновления, а число наблюдателей в демоне не растёт с числом вкладок

#### Scenario: Неизменный файл не перечитывается

- **WHEN** демон опрашивает корень прогонов, а файлы очереди не менялись
- **THEN** очередь не разбирается заново, и клиентам уходит прежнее её содержимое

#### Scenario: Изменение прогона не перечитывает очередь

- **WHEN** идущий прогон переписывает своё состояние, а файлы очереди не менялись
- **THEN** очередь не разбирается заново, и повторного её кадра открытым клиентам не уходит
