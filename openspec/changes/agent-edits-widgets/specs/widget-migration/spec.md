## ADDED Requirements

### Requirement: Таблица общих модулей объявляет версию и заметки о смене имени

Таблица общих модулей витрины SHALL объявлять рядом с перечнем имён номер своей версии и записи о смене — что случилось с именем: ушло, переименовано, заменено, — с текстом, годным для чтения агентом миграции. Проверка сборки MUST держать версию и перечень сведёнными: правка перечня имён без поднятой версии и без записи о смене MUST быть отказом проверки, а не расхождением, которое обнаружится в браузере пользователя карточкой неразрешённого импорта.

#### Scenario: Имя ушло из таблицы вместе с версией и заметкой

- **WHEN** из таблицы убрано имя, версия поднята и заведена запись о смене
- **THEN** проверка проходит, а заметка доступна тем, кто объясняет устаревание

#### Scenario: Перечень правили молча

- **WHEN** перечень имён изменён, а версия и записи о смене остались прежними
- **THEN** проверка красная и называет расхождение

### Requirement: Виджет, импортирующий имя не из таблицы, считается устаревшим

Устаревшим SHALL считаться виджет проекта, чей файл импортирует голым спецификатором имя, которого действующая таблица общих модулей не несёт. Неразрешимым MUST считаться и сам голый спецификатор, которого в таблице нет вовсе — ушедшее целиком имя, подпуть пакета таблицы, сторонний пакет, — и имя клаузы у спецификатора, который таблица знает: карта имён страницы несёт ровно спецификаторы таблицы, и в браузере не разрешится ни то, ни другое. Признак MUST выводиться из самого файла виджета, а не из записанного в проект номера версии таблицы: движок MUST не заводить в кабинете пользователя собственного файла состояния ради этого признака. Причина устаревания MUST называть то, чего таблица больше не несёт, и, если о нём есть запись о смене, — её текст. Фоновый такт наблюдателя MUST не читать исходники виджетов: часть отпечатка каталога виджетов остаётся на `mtime` и размере, а признак пересчитывается на такте, где эта часть сдвинулась. Виджет, импортирующий только имена таблицы, MUST устаревшим не считаться.

#### Scenario: Виджет ссылается на ушедшее имя

- **WHEN** файл виджета импортирует имя, которого в таблице нет
- **THEN** виджет назван устаревшим, и причина называет это имя

#### Scenario: Спецификатора нет в таблице вовсе

- **WHEN** файл виджета импортирует голый спецификатор, которого действующая таблица не несёт
- **THEN** виджет назван устаревшим, и причина называет сам спецификатор

#### Scenario: Такт наблюдателя не читает исходники

- **WHEN** наблюдатель прошёл такт по каталогу виджетов без правок
- **THEN** часть отпечатка посчитана по `mtime` и размеру, а содержимое файлов виджетов не читалось

#### Scenario: Виджет в порядке

- **WHEN** файл виджета импортирует только имена действующей таблицы
- **THEN** виджет устаревшим не считается

#### Scenario: Признак не требует состояния в проекте

- **WHEN** признак устаревания вычислен для проекта
- **THEN** ни одного файла в кабинете проекта при этом не создано и не изменено

### Requirement: Команда печатает состав виджетов проекта и их разрешимость

Команда `stepcast widgets [--json]` SHALL печатать состав виджетов проекта: имя виджета, файл, голые спецификаторы, которые он импортирует, имена среди них, которых действующая таблица не несёт, и версию самой таблицы. Вывод `--json` MUST быть тем же содержимым машинным видом, годным входом для шага пайплайна. Проект без виджетов MUST давать пустой состав и нулевой код возврата, а не отказ.

#### Scenario: Состав с устаревшим виджетом

- **WHEN** в проекте два виджета, и один ссылается на ушедшее имя
- **THEN** команда печатает оба, называя у второго неразрешимое имя и версию таблицы

#### Scenario: Машинный вид

- **WHEN** команда вызвана с `--json`
- **THEN** вывод разбирается как JSON и несёт тот же состав

#### Scenario: Виджетов нет

- **WHEN** у проекта нет каталога виджетов
- **THEN** команда печатает пустой состав и завершается успехом

### Requirement: Пакет поставляет пайплайн миграции виджетов

Пакет SHALL поставлять пайплайн `migrate-widgets`, запускаемый ссылкой на пайплайн поставки из корня проекта. Пайплайн MUST состоять из работы обзора, снимающей состав виджетов командой, и работы миграции, в которой агент видит обзор, исходники затронутых виджетов и заметки о смене таблицы. Агентский шаг миграции MUST объявлять права, дающие чтение и вызов постановки предложения, но не правку файлов, MUST писать новые версии виджетов в каталог черновиков работы, лежащий вне рабочего дерева, и MUST ставить каждую новую версию в очередь предложений, а не записывать файл кабинета. Форма вызова, которой промпт учит агента, MUST подходить под объявленное право шага — иначе жёсткий режим доступа отклонил бы её, и миграция завершилась бы успехом, не поставив ни одной записи, — и MUST звать движок надёжным способом, не полагаясь на то, что имя команды разрешится в `PATH`. Пайплайн MUST быть годным входом кнопки витрины, предлагающей миграцию.

#### Scenario: Миграция кладёт результат в очередь

- **WHEN** в проекте есть устаревший виджет и пайплайн миграции пройден
- **THEN** файл виджета на диске не изменился, а в очереди появилась открытая запись с новой версией этого виджета и причиной

#### Scenario: Виджет не тронут в дереве

- **WHEN** работа миграции завершилась
- **THEN** рабочее дерево проекта не несёт изменений виджетов, а черновики остались вне дерева

#### Scenario: Мигрировать нечего

- **WHEN** ни один виджет проекта не устарел
- **THEN** прогон завершается успехом, не поставив в очередь ни одной записи

### Requirement: Миграцию можно направить на названный виджет

Пайплайн миграции SHALL принимать вход, называющий виджеты, которые нужно прогнать через агента, — названный виджет либо все, — чтобы случай, который сканирование импортов не ловит, закрывался запуском руками. Названное значение MUST доходить до агента текстом его промпта: вход, принятый пайплайном и не дошедший до агента, означал бы, что запуск с входом ведёт себя ровно как запуск без него. Без входа MUST мигрироваться только устаревшие виджеты.

#### Scenario: Смена смысла оставшегося имени

- **WHEN** миграция запущена с входом, называющим виджет, чьи импорты разрешимы
- **THEN** агент прогоняет этот виджет и вправе поставить его новую версию в очередь

#### Scenario: Названный виджет доходит до агента

- **WHEN** миграция запущена с входом, называющим виджет
- **THEN** промпт, который получил агент, несёт это значение, а не неразвёрнутую подстановку

#### Scenario: Запуск без входа

- **WHEN** миграция запущена без входа
- **THEN** через агента проходят только устаревшие виджеты
