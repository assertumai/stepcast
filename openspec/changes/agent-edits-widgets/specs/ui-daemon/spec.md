## ADDED Requirements

### Requirement: Демон пишет файл кабинета из очереди только по явному действию пользователя

Право записи демона SHALL расширяться третьим видом файла — файлом кабинета проекта, записываемым принятием записи очереди, — после файла маршрутов слоя и файла дашборда. Запись MUST происходить только как следствие явного действия пользователя над названной записью очереди и MUST касаться ровно цели этой записи и самой записи: ни одного иного файла проекта демон при этом MUST не менять. В файлы прогонов демон MUST по-прежнему не писать вовсе. Отпечаток цели MUST сверяться перед записью, а наблюдатель MUST быть разбужен сразу после неё, чтобы правка, сделанная самим демоном, не ждала такта опроса.

#### Scenario: Принятие пишет ровно цель

- **WHEN** пользователь принял запись очереди
- **THEN** записаны цель этой записи и сама запись, а прочие файлы проекта и файлы прогонов не изменены

#### Scenario: Фоновый такт ничего не пишет

- **WHEN** наблюдатель прошёл такт по каталогу очереди без действий пользователя
- **THEN** ни один файл проекта не изменён

### Requirement: Наблюдение очереди её не изменяет

Наблюдатель демона SHALL читать каталог очереди тем же способом, каким читает прочие каталоги кабинета, и MUST не создавать, не чинить и не убирать его записей. Негодная запись MUST оставаться на диске и показываться причиной, а не стираться наблюдателем. Отсутствие каталога очереди MUST быть обычным состоянием наблюдения.

#### Scenario: Негодная запись переживает такт

- **WHEN** в каталоге очереди лежит файл, не разбираемый как запись
- **THEN** он остаётся на диске, а витрина показывает его негодной записью с именем файла

### Requirement: Запуск прогона принимает пайплайн поставки

Маршрут запуска прогона SHALL принимать, помимо файла пайплайна проекта, ссылку на пайплайн поставки вида `stepcast:<имя>`. Имя MUST проверяться по закрытому перечню пайплайнов, которые везёт пакет: имени вне перечня MUST быть отказ с этим перечнем, а не порождение процесса. Проект MUST по-прежнему называться ключом, известным указателю проектов, дочерний процесс MUST порождаться отсоединённым в корне этого проекта, и ответ MUST оставаться подтверждением приёма, а не обещанием идентификатора прогона.

#### Scenario: Запуск встроенного пайплайна кнопкой

- **WHEN** витрина просит запустить `stepcast:migrate-widgets` в известном проекте
- **THEN** в корне проекта порождается отсоединённый прогон этого пайплайна, а ответ подтверждает приём запуска

#### Scenario: Неизвестное имя поставки

- **WHEN** запрошен `stepcast:<имя>`, которого пакет не везёт
- **THEN** маршрут отказывает, называя перечень поставляемых имён, и ни одного процесса не порождает
