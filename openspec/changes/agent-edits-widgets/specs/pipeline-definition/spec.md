## ADDED Requirements

### Requirement: Ссылка на поставку называет и пайплайн, а не только схему

Значение `stepcast:<имя>` SHALL называть, помимо схемы поставки, пайплайн, поставляемый пакетом: `stepcast run stepcast:<имя>` MUST раскрывать пайплайн из встроенного каталога пайплайнов пакета и исполнять его в каталоге запуска, как исполняется пайплайн проекта. Путь к файлу MUST разрешаться от расположения самого движка, а не от каталога запуска, чтобы форма работала одинаково из исходников, из `dist/`, из `node_modules` целевого репозитория и из глобальной установки. Имя MUST быть слагом в kebab-case; `/`, `.` и `..` в имени, а также имя, которого пакет не везёт, MUST быть отказом разбора с перечнем поставляемых имён. Пути внутри самого документа пайплайна поставки (работы, промпты, схемы) MUST разрешаться обычными правилами — от файла, в котором объявлены, — и оставаться внутри пакета. Позиционный аргумент без префикса `stepcast:` MUST по-прежнему считаться путём: голое имя файла остаётся файлом каталога запуска.

#### Scenario: Запуск пайплайна поставки

- **WHEN** в корне проекта вызвано `stepcast run stepcast:migrate-widgets`
- **THEN** раскрывается пайплайн из встроенного каталога пакета, и прогон идёт в этом проекте

#### Scenario: Имени нет в поставке

- **WHEN** вызвано `stepcast run stepcast:нет-такого`
- **THEN** разбор отказывает, перечисляя поставляемые имена, и прогон не заводится

#### Scenario: Имя с разделителем пути

- **WHEN** вызвано `stepcast run stepcast:../secret`
- **THEN** разбор отказывает, называя требование к имени

#### Scenario: Путь остаётся путём

- **WHEN** вызвано `stepcast run migrate-widgets.yml` и такой файл лежит в каталоге запуска
- **THEN** раскрывается файл каталога запуска, а не пайплайн поставки
