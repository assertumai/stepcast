## MODIFIED Requirements

### Requirement: Ключ шага вычисляется, записывается и определяет переиспользование

Для каждого шага система SHALL вычислять ключ от нормализованного определения шага и работы, взятого **до раскрытия отложенных подстановок**, от текста промпта и контекста в том же нераскрытом виде, идентификатора и версии бэкенда, модели, выходов работ выше по графу и отпечатка входов шага, и записывать его в `step.json`. Величины пространства `run` — идентификатор прогона, его директория и рабочая директория — MUST NOT влиять на ключ ни прямо, ни через раскрытый текст. Выходы работ выше по графу MUST входить в ключ отдельной составляющей, а не через раскрытый текст, чтобы их изменение меняло ключ и при нераскрытом определении. Значения, подставляемые из `env` работы, MUST влиять на ключ как часть определения работы. Вычисленный ключ SHALL быть единственным основанием для решения о переиспользовании результата шага из другого прогона. Отпечаток входов и его происхождение MUST записываться рядом с ключом, чтобы решение о валидности можно было объяснить без повторного вычисления. Ключ MUST вычисляться из одинаково собранного входа независимо от того, вычисляет его исполнитель или планировщик возобновления.

#### Scenario: Одинаковые условия дают одинаковый ключ

- **WHEN** шаг исполняется дважды на неизменном рабочем дереве с теми же входами
- **THEN** вычисленные ключи совпадают

#### Scenario: Отложенная подстановка величины прогона не меняет ключ

- **WHEN** работа подключает контекстом `${run.dir}/item.json` и исполняется в двух разных прогонах при неизменных определении, входах и выходах предшественников
- **THEN** ключи её шагов в обоих прогонах совпадают

#### Scenario: Порядок работ не влияет на ключ

- **WHEN** работа объявлена раньше своей зависимости и потому исполняется не в порядке объявления
- **THEN** ключ её шагов, вычисленный планировщиком возобновления, совпадает с записанным исполнителем, и её шаги переиспользуются

#### Scenario: Изменение промпта меняет ключ

- **WHEN** изменён файл промпта шага
- **THEN** вычисленный ключ отличается от предыдущего

#### Scenario: Изменение определения работы с отложенной подстановкой меняет ключ

- **WHEN** в файле работы, использующей `${run.dir}`, изменено любое другое поле её определения
- **THEN** вычисленный ключ её шагов отличается от записанного в прошлом прогоне

#### Scenario: Изменение выхода работы выше по графу меняет ключ

- **WHEN** работа выше по графу опубликовала другой выход, а определение шага не менялось
- **THEN** вычисленный ключ шага отличается от записанного в прошлом прогоне

#### Scenario: Изменение рабочего дерева меняет ключ

- **WHEN** между прогонами изменён файл, входящий в отпечаток входов шага
- **THEN** вычисленный ключ отличается от записанного в прошлом прогоне

#### Scenario: Совпадение ключа — основание для переиспользования

- **WHEN** ключ шага совпал с ключом успешного шага исходного прогона
- **THEN** шаг признан валидным и его результат берётся из исходного прогона

#### Scenario: Решение объяснимо по записи

- **WHEN** шаг признан невалидным
- **THEN** его запись содержит отпечаток входов и его происхождение, достаточные, чтобы назвать причину

#### Scenario: Раскрытое определение остаётся в журнале

- **WHEN** работа с отложенными подстановками исполнена
- **THEN** директория работы содержит раскрытое определение, по которому шаги фактически исполнялись
