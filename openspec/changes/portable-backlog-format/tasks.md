# Задачи

Порядок — из плана миграции `design.md`: снизу вверх, так чтобы петля ни на
одном шаге не осталась без работающего разбора очереди. Скрипт
`scripts/backlog.mjs` удаляется только после того, как его зовущих не
остаётся. Каждая задача — код **и** тест; тест обязан падать до правки.

Границу `changed_only` захода расширять не нужно: `src/**`, `test/**`,
`docs/**`, `schema/**`, `scripts/**`, `.stepcast/jobs/**`,
`.stepcast/schemas/**` и `openspec/changes/**` уже в ней. Сам `backlog.md` в
границу не входит и в этом изменении не правится — см. решение «Преамбула
`backlog.md` не трогается» в `design.md`.

## 1. Ядро очереди

- [x] 1.1 `src/core/backlog/schema.ts` — zod-модель пункта очереди (слаг,
      `status` из закрытого перечня, обязательные `title`, `why`, `done_when`,
      необязательные `group`, `started_at`, `reason`, действующая группа) и
      модель ответа `pick --lanes` (дорожка: признак заполненности, слаг,
      заголовок, группа, запись пункта либо её отсутствие). Критерий: обе
      модели пригодны для `z.toJSONSchema` — из них печатаются публикуемые
      схемы задачи 2.1, второго описания той же формы в коде нет.
- [x] 1.2 `src/core/backlog/parse.ts` — разбор текста в пункты с позициями
      полей: заголовок второго уровня начинает пункт, всё до первого заголовка
      — преамбула, пустые строки внутри пункта пропускаются, прочие строки
      разбираются как `ключ: значение`. Разбор заканчивается прогоном каждого
      пункта через схему 1.1. Критерий: отказ — `StepcastError` с кодом ошибки
      конфигурации, называющий слаг пункта и, где позиция известна, номер
      строки; неизвестные поля принимаются и сохраняются в записи пункта.
      Ввода-вывода в модуле нет: на входе строка.
- [x] 1.3 `src/core/backlog/select.ts` — свобода пункта (`pending`; `in_progress`
      старше порога; `in_progress` без разбираемого `started_at`), занятость
      группы (только независший `in_progress`) и отбор до `N` пунктов сверху
      вниз по одному на действующую группу. Критерий: текущий момент и порог
      приходят аргументами, `Date.now()` внутри не зовётся; занятые группы
      собираются по всей очереди до отбора и пополняются по ходу.
- [x] 1.4 `src/core/backlog/write.ts` — правка полей пункта в тексте:
      существующее поле переписывается на месте, новое дописывается за
      последним полем своего пункта. Критерий: строки других пунктов и
      преамбулы не меняются посимвольно; функция возвращает новый текст и
      файлов не трогает.
- [x] 1.5 `src/core/backlog/index.ts` и экспорт из `src/core/index.ts` —
      разбор, отбор, правка и типы наружу, тем же порядком и стилем, что и
      остальные экспорты.
- [x] 1.6 Переписать `test/backlog.test.ts` с запуска скрипта отдельным
      процессом на проверки ядра: разбор со всеми полями, преамбула не
      разбирается, неразбираемая строка, неизвестный статус, недостающее
      обязательное поле, заголовок не слаг, группа не слаг, повторный слаг,
      сохранение неизвестного поля при правке; свобода `pending`, занятость
      свежего `in_progress`, зависший `in_progress`, `in_progress` без
      `started_at` и с мусорным `started_at`, `done`/`failed` не свободны;
      отбор — пункт без группы образует свою, занятая группа не выдаётся (в
      том числе занятым пунктом ниже места отбора), два свободных пункта одной
      группы за проход, завершённый пункт группу не запирает, свободных меньше
      запрошенного; правка — поле на месте, новое поле следом за последним,
      соседние пункты нетронуты. Критерий: временных каталогов и подпроцессов
      тест не заводит.
- [x] 1.7 Тест: `backlog.md` этого репозитория разбирается движком как есть —
      без правок файла и без единого отказа схемы. Критерий: путь считается от
      собранного файла теста, а не от рабочего каталога; тест падает, если
      формат разойдётся с моделью движка.

## 2. Схемы, публикуемые пакетом

- [x] 2.1 Добавить в `scripts/generate-schema.ts` две цели —
      `schema/backlog.schema.json` (пункт очереди) и
      `schema/backlog-slots.schema.json` (ответ `pick --lanes`), — рядом с
      тремя существующими. Критерий: для ответа команды выбран режим `io`,
      дающий форму выхода, а не входа; порождённые файлы закоммичены. Печатать
      их следует уже собранным движком (`node dist/scripts/generate-schema.js`
      после зелёной сборки), не вызывая `npm run build` отдельной командой.
- [x] 2.2 Тест: сгенерированные схемы совпадают с тем, что даёт модель, —
      проверкой в тесте, а не только глазами. Критерий: правка модели без
      перегенерации схемы роняет `npm run check`.

      Перегенерация задела и две старые схемы: `schema/job.schema.json` и
      `schema/pipeline.schema.json` получили свойство `output_schema` —
      закоммиченные файлы отстали от моделей ещё до этого изменения. Правка
      верна и как раз того рода, которую отныне ловит тест свежести, но
      ожидание «три существующие цели переезжают, не меняя ни байта» было
      неверным: цели переехали без изменений, а вот файлы были несвежими.

## 3. Команда `stepcast backlog`

- [x] 3.1 `src/cli/commands/backlog.ts` — подкоманды `list`, `pick`, `finish`:
      чтение файла (`--file`, по умолчанию `backlog.md` в рабочем каталоге),
      вызов ядра, печать JSON, запись файла через `atomicWrite`. Критерий: ни
      конфигурация, ни корень проекта, ни каталог прогона командой не
      разрешаются и не требуются; отсутствующий, нечитаемый и неразбираемый
      файл дают `StepcastError` с кодом ошибки конфигурации и путём.
- [x] 3.2 `pick`: формы `--slots N` (массив, `N = 1` по умолчанию) и
      `--lanes a,b` (объект дорожек), ключи `--stale-hours` и `--run-dir`.
      Критерий: всем взятым за один вызов пунктам проставляется одна и та же
      метка `started_at`; каждая названная дорожка присутствует в ответе, в
      том числе незаполненная; при `--run-dir` заполненная дорожка получает
      свой файл записи пункта, незаполненная — нет; отсутствие свободных
      пунктов даёт код `0` и пустую выдачу, а файл очереди остаётся
      неизменным. Ключей `--now` и `--out` у команды нет.
- [x] 3.3 `finish`: `--status done|failed`, обязательная `--reason` при
      `failed`, уже проставленный исход не переписывается и отказом не
      считается, отсутствующий слаг — ошибка.
- [x] 3.4 Зарегистрировать команду в `src/cli/main.ts`: запись в `COMMANDS`
      с позиционными `action` и `slug` и описаниями всех флагов, ветка в
      `switch`. Критерий: `stepcast` без аргументов печатает `backlog` в
      перечне команд; неизвестная подкоманда отклоняется с перечислением
      известных.
- [x] 3.5 Тест команды (`test/cli-backlog.test.ts`): вызовы через `run(argv,
      io)` во временном каталоге без `stepcast.yml`, `.stepcast/` и
      конфигурации — `list` не правит файл; `pick` берёт пункт и проставляет
      поля; `pick --lanes` раздаёт дорожки и пишет файлы в `--run-dir`;
      пустая очередь даёт код `0`; `finish done`/`failed`; повторный `finish`
      файл не меняет; отсутствующий файл, отсутствующий слаг, `failed` без
      причины и ошибочный перечень дорожек дают код ошибки конфигурации.

## 8. Правки по ревью

- [x] 8.1 Однострочность значения держится кодом, а не соглашением:
      `withFields` отвергает значение с переводом строки, а `finish` сводит
      причину к одной строке и урезает по длине. Критерий: причина, собранная
      `finalize.mjs` из многострочного `stderr` красной проверки, не делает
      очередь неразбираемой — до правки следующий `list|pick|finish` отказывал
      бы кодом 2 на всём файле.
- [x] 8.2 `pick --lanes`: каталог `--run-dir` разрешается от рабочего каталога
      команды (как `--file`, а не от `process.cwd()`) и готовится до правки
      очереди. Критерий: недоступный путь — отказ при нетронутой очереди, а не
      пункты, взятые без файлов дорожек.
- [x] 8.3 `--lanes` вместе с `--slots` отклоняется, а не выбирает форму молча.
- [x] 8.4 Огороженный блок кода в преамбуле разбору не подлежит: пример пункта
      во вводном тексте очереди пунктом не становится.
- [x] 8.5 `docs/backlog.md` перестаёт требовать `reason` при `status: failed`
      — этого не требуют ни схема, ни спека: обязателен ключ команды `finish`,
      а не поле у разбора.
- [x] 8.6 Тесты, проверявшие меньше заявленного: разбор называет номер строки
      (а не только слаг), стенд `finalize` сверяет код отказавшего вызова
      (`кодом 2`), а не любую двойку в выводе.
- [x] 8.7 Переносимость ссылки работы `slots` на схему движка названа там, где
      её увидит заводящий очередь у себя: разделом «Схема формата в чужом
      репозитории» в `docs/backlog.md`, разбором сделки в `design.md` и
      известным ограничением в состоянии реализации. Сам `slots.yml` при этом
      не правится: `.stepcast/jobs/**` не входит в границу правок работы
      `fix-review`.
