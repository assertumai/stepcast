## ADDED Requirements

### Requirement: Пайплайн раскрывается реестром вкладов своего проекта

Витрина SHALL раскрывать пайплайн реестром вкладов, собранным из конфигурации того проекта, которому файл принадлежит.
Предикат, внесённый плагином этого проекта, MUST разбираться так же, как его
разбирают `stepcast lint` и `stepcast run` того же документа, и MUST NOT
отклоняться как неизвестный ключ. Умолчания, объявленные плагином своему
бэкенду, MUST участвовать в выборе модели шага наравне с прочими слоями
конфигурации: модель на карточке шага MUST совпадать с той, которой шаг
исполнится. Реестр одного проекта MUST NOT действовать в другом: плагин, не
объявленный конфигурацией проекта, MUST оставаться для его документов
неизвестным. Проект, не объявивший плагинов вовсе, MUST раскрываться встроенным
реестром и MUST NOT приводить к загрузке стороннего кода.

#### Scenario: Предикат плагина в проверке результата

- **WHEN** проект объявляет плагин с предикатом `http_ok`, а его пайплайн проверяет шаг записью `expect: [{ http_ok: … }]`
- **THEN** карточка пайплайна показывает устройство работ и шагов и не показывает ошибку

#### Scenario: Предикат плагина в условии повторения

- **WHEN** тот же предикат стоит в `until.check` работы этого проекта
- **THEN** пайплайн раскрыт, и карточка не показывает ошибку

#### Scenario: Плагин чужого проекта не расширяет разбор

- **WHEN** предикат плагина объявлен конфигурацией одного проекта, а тот же ключ встречается в пайплайне соседнего проекта, который этого плагина не объявляет
- **THEN** пайплайн первого проекта раскрыт, а пайплайн соседнего показан ошибкой о неизвестном ключе

#### Scenario: Модель из умолчания плагинного бэкенда

- **WHEN** шаг не объявляет модели, его агент — бэкенд плагина, и модель этому бэкенду даёт умолчание самого плагина
- **THEN** карточка шага показывает эту модель и называет слоем бэкенд, а не сообщает, что модель не задана

#### Scenario: Проект без плагинов

- **WHEN** проект не объявляет `plugins`
- **THEN** его пайплайны раскрываются как раньше, и сторонний код не загружается

### Requirement: Отказ загрузки плагина проекта не скрывает остальные проекты

Витрина SHALL показывать пайплайны проекта, чей плагин не загрузился, карточками с этой ошибкой.
Сообщение MUST называть причину и файл конфигурации, объявивший плагин, — тем же
составом полей, каким витрина показывает нечитаемую конфигурацию проекта, и для
конфликта имён вкладов тоже. Файл, объявивший плагин вне корня проекта
(глобальная конфигурация пользователя), MUST быть назван абсолютным путём, а не
цепочкой перехода вверх от корня проекта. Пайплайны прочих проектов корня
прогонов MUST раскрываться как обычно, а демон MUST продолжать отвечать. Отказ
MUST NOT переживать своё исправление: запрос после правки объявления MUST
показывать раскрытый пайплайн без перезапуска демона.

#### Scenario: Объявленный модуль не найден

- **WHEN** проект объявляет плагин, модуля которого на диске нет
- **THEN** его пайплайны показаны карточками с этой ошибкой, называющей строку объявления и файл конфигурации

#### Scenario: Вклады плагина спорят за занятое имя

- **WHEN** плагин проекта объявляет предикат под уже занятым именем и загрузка отказывает
- **THEN** пайплайны этого проекта показаны карточками с текстом отказа, файлом объявления и местом `plugins`

#### Scenario: Плагин объявлен глобальной конфигурацией

- **WHEN** плагин объявлен `~/.stepcast/config.yml` и не загружается
- **THEN** карточки проекта называют этот файл абсолютным путём

#### Scenario: Соседний проект остаётся видимым

- **WHEN** плагин одного проекта не загружается, а второй проект корня прогонов исправен
- **THEN** пайплайны второго проекта показаны раскрытыми, и витрина продолжает отвечать

#### Scenario: Исправленное объявление действует сразу

- **WHEN** объявление плагина исправлено после отказа и страница обновлена
- **THEN** пайплайны проекта показаны раскрытыми без перезапуска демона
