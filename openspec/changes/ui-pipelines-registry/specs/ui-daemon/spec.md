## ADDED Requirements

### Requirement: Реестр вкладов собирается на корень проекта

Демон SHALL собирать реестр вкладов отдельно по каждому проекту, чьи пайплайны показывает, из конфигурации этого проекта.
Одного реестра на процесс — собранного по каталогу, из которого поднят
`stepcast up`, — для показа MUST NOT хватать: ключ `plugins` объявляет проектная
конфигурация, и проекты корня прогонов вправе объявлять разные плагины.
Собранный реестр MAY переживать запрос: демон вправе держать его, пока
объявления плагинов проекта не изменились. Появление, исчезновение или замена
объявления в конфигурации проекта MUST действовать со следующего запроса, без
перезапуска демона. Изменённый на диске код уже загруженного плагина
MUST NOT считаться подхваченным: демон продолжает раскрывать прежним кодом, и
это ограничение MUST быть названо в документации вместе с тем, что снимает его
перезапуск демона. Собранный реестр MUST жить не дольше самого демона.

#### Scenario: Два проекта со своими плагинами

- **WHEN** два проекта корня прогонов объявляют разные плагины, и пайплайн каждого пользуется предикатом своего
- **THEN** оба пайплайна раскрыты, каждый — реестром своего проекта

#### Scenario: Новое объявление плагина действует со следующего запроса

- **WHEN** в конфигурацию проекта добавлено объявление плагина, и страница пайплайнов обновлена
- **THEN** документ с предикатом этого плагина раскрыт, а демон не перезапускался

#### Scenario: Изменённый код плагина требует перезапуска

- **WHEN** код уже загруженного плагина изменён на диске
- **THEN** витрина продолжает раскрывать пайплайны прежним кодом до перезапуска демона, и документация называет это ограничение

### Requirement: Демон загружает только объявленные плагины показываемых проектов

Демон SHALL загружать код плагина только тогда, когда его объявляет конфигурация показываемого проекта или глобальная конфигурация пользователя.
Собственного списка «плагинов витрины» демон MUST NOT заводить. Проект, которого
нет в указателе `projects.json`, у которого не нашлось файлов пайплайнов или
который плагинов не объявляет, MUST NOT приводить к загрузке стороннего кода.
Загрузка MUST оставаться чтением журнала неизменным: она MUST NOT создавать,
изменять или удалять файлы прогонов.

#### Scenario: Проект без объявленных плагинов

- **WHEN** проект корня прогонов не объявляет `plugins`
- **THEN** его пайплайны раскрыты, и ни один сторонний модуль не загружен

#### Scenario: Проект без файлов пайплайнов

- **WHEN** у проекта нет ни одного файла пайплайна
- **THEN** плагины этого проекта не загружаются

#### Scenario: Загрузка не трогает журнал

- **WHEN** демон собрал реестры проектов и отдал экран пайплайнов
- **THEN** файлы прогонов остались теми же, какими их записал движок
