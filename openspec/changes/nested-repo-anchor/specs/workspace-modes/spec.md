## ADDED Requirements

### Requirement: Объявленный состав вложенных репозиториев проверяется до первой работы

Пригодность объявленного состава вложенных репозиториев SHALL проверяться один раз до запуска первой работы, а непригодность MUST быть ошибкой конфигурации, а не отказом бухгалтерии посреди прогона.

Проверка MUST убеждаться, что корень рабочего дерева — репозиторий git, что
каждый объявленный каталог существует, что он является рабочим деревом git и
что он является деревом собственного репозитория, а не подкаталогом корневого.
Сообщение MUST называть каталог и причину: три случая — несуществующий
каталог, каталог вне git и обычный подкаталог корня — MUST различаться, потому
что чинятся они по-разному, а последний иначе означал бы двойной учёт
содержимого корня.

Проверка MUST отклонять и объявленный каталог, который корневой репозиторий
не сможет обойти при снятии якоря: вложенный репозиторий без единого коммита
корневой git ссылкой на коммит не встраивает, а отказывает целиком, и якорь
не снялся бы вовсе. Отказ MUST относиться только к тем частям, до которых
корень действительно доходит: часть, которую он игнорирует, в его обход не
попадает и своим репозиторием снимается без коммита — отклонять её MUST NOT.

#### Scenario: Объявленный каталог без единого коммита

- **WHEN** объявленный каталог является репозиторием git без единого коммита и корневым репозиторием не игнорируется
- **THEN** прогон завершается ошибкой конфигурации до запуска первой работы, называющей каталог и причину

#### Scenario: Игнорируемая корнем часть без коммита допустима

- **WHEN** объявленный каталог является репозиторием git без единого коммита, но игнорируется корневым репозиторием
- **THEN** прогон начинается обычным порядком

#### Scenario: Объявленный каталог отсутствует

- **WHEN** объявлен вложенный репозиторий, каталога которого в дереве нет
- **THEN** прогон завершается ошибкой конфигурации до запуска первой работы, называющей каталог

#### Scenario: Объявленный каталог не репозиторий

- **WHEN** объявленный каталог существует, но рабочим деревом git не является
- **THEN** прогон завершается ошибкой конфигурации, называющей каталог и причину

#### Scenario: Объявлен подкаталог корневого репозитория

- **WHEN** объявленный каталог принадлежит корневому репозиторию, а не собственному
- **THEN** прогон завершается ошибкой конфигурации, называющей каталог и его репозиторий

#### Scenario: Корень вне git

- **WHEN** состав объявлен в дереве, которое само репозиторием git не является
- **THEN** прогон завершается ошибкой конфигурации до запуска первой работы

#### Scenario: Пригодный состав не мешает прогону

- **WHEN** все объявленные каталоги существуют и являются отдельными репозиториями
- **THEN** прогон начинается обычным порядком

### Requirement: Изолированные режимы несовместимы с объявленным составом

При объявленных вложенных репозиториях режимы `worktree` и `copy` SHALL отклоняться до запуска первой работы, а прогон MUST выполняться в каталоге запуска.

Причина MUST называться в сообщении: изолированное дерево объявленных
вложенных репозиториев не содержит — `worktree` выкладывает корневое дерево из
`HEAD`, а `copy` копирует то, что видит корневой git, — и снятый в нём якорь
снова был бы однорепозиторным, то есть границы правок оказались бы сняты молча.
Сообщение MUST называть работу и её режим.

Тот же случай MUST выявляться статической проверкой пайплайна наравне с
прочими отказами пригодности режима: прогон, минующий её, MUST отказывать до
первой работы, а не при подготовке директории.

#### Scenario: Работа в изолированном режиме при объявленном составе

- **WHEN** объявлены вложенные репозитории, а работа пайплайна объявляет `workspace.mode: copy`
- **THEN** прогон завершается ошибкой конфигурации до запуска первой работы, называющей работу, её режим и причину

#### Scenario: Статическая проверка называет то же самое

- **WHEN** `stepcast lint` разбирает такой пайплайн
- **THEN** он сообщает об ошибке, называя работу и её режим

#### Scenario: Режим каталога запуска допустим

- **WHEN** объявлены вложенные репозитории, а все работы пайплайна исполняются в каталоге запуска
- **THEN** прогон начинается обычным порядком

#### Scenario: Без объявленного состава режимы не ограничены

- **WHEN** вложенные репозитории не объявлены
- **THEN** режимы `worktree` и `copy` доступны как прежде
