## ADDED Requirements

### Requirement: Возобновление считает вложенные репозитории наравне с корнем

Возобновление SHALL признавать шаг невалидным при изменении объявленного вложенного репозитория так же, как при изменении корня, а прогон, снятый другим составом, MUST признаваться несравнимым целиком с названной причиной.

Область изменений, по которой решается валидность, MUST включать пути частей с
префиксом их каталога — тем же перечнем, что даёт сравнение состояний. Все уже
действующие правила сужения MUST применяться к ним без исключений: объявленные
входы работы, наблюдённые входы и вычитание путей, произведённых самим исходным
прогоном, MUST работать по путям с префиксом так же, как по путям корня.

Прогон, объявлявший другой состав вложенных репозиториев, MUST давать
несравнимое состояние: все его шаги MUST признаваться невалидными, а причина
MUST называть несовпадение состава, а не изменение дерева. Восстановление
дерева перед первым переисполняемым шагом MUST заходить внутрь частей — путь
части MUST восстанавливаться её собственным состоянием.

#### Scenario: Правка во вложенном репозитории обесценивает шаг

- **WHEN** между прогонами изменён файл объявленного вложенного репозитория, входящий в область шага
- **THEN** шаг признан невалидным, а причиной названо изменение дерева с указанием пути с префиксом каталога части

#### Scenario: Правка вне области не обесценивает

- **WHEN** между прогонами изменён файл объявленного вложенного репозитория, отсутствующий в объявленных входах работы
- **THEN** отпечаток входов её шагов не изменился

#### Scenario: Состав изменился между прогонами

- **WHEN** возобновляется прогон, объявлявший другой состав вложенных репозиториев
- **THEN** переиспользовать нечего, пайплайн исполняется с начала, а причиной названо несовпадение состава

#### Scenario: Восстановление заходит в часть

- **WHEN** возобновление восстанавливает дерево, среди путей которого есть путь объявленной части
- **THEN** файл части приведён к состоянию последнего переиспользованного шага

#### Scenario: Объяснение называет путь целиком

- **WHEN** пользователь выполняет `stepcast resume --dry-run` после правки во вложенном репозитории
- **THEN** в объяснении инвалидации путь назван относительно корня рабочего дерева, с каталогом части
