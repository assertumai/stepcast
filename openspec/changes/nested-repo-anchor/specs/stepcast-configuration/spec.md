## ADDED Requirements

### Requirement: Секция project объявляет вложенные репозитории дерева

Секция `project` SHALL принимать ключ `nested_repos` — непустой список каталогов рабочего дерева, каждый из которых является отдельным репозиторием git.

Каждый элемент MUST быть относительным путём от корня репозитория без сегмента
`..` — той же моделью, что `project.spec.dir` и `project.edit_paths`. Сверх неё
элемент MUST NOT содержать символов шаблона глоба: значение называет конкретный
каталог, по которому заводится отдельное частное состояние и чьим именем
префиксуются пути, — шаблон нечем ни открыть, ни приписать к пути. Завершающий
разделитель MUST отбрасываться, повторы MUST отбрасываться, а сам состав MUST
приводиться к одному порядку независимо от порядка объявления.

Пустой список MUST отклоняться разбором — той же причиной, что `project.tools:
[]` и `project.edit_paths: []`: объявление, не называющее ни одного каталога,
почти наверняка забытая правка, а не «вложенных репозиториев нет». Отсутствие
ключа MUST NOT быть ошибкой и MUST означать однорепозиторное дерево.

Ключ MUST приниматься только в проектном конфиге: в глобальном он MUST
отклоняться тем же правилом и тем же сообщением, что остальные ключи секции.
В отличие от остальных ключей секции, документ пайплайна MUST NOT принимать его
верхним ключом `project` — состав вложенных репозиториев описывает форму
состояния дерева, а она обязана быть одна на дерево: два пайплайна одного
проекта с разным составом снимали бы в одном каталоге несравнимые между собой
якоря. Отказ MUST называть ключ.

Пространство подстановки `${project.*}` MUST NOT пополняться этим именем:
значение читает движок, а не документы. Обращение к нему MUST отказывать
действующим сообщением о составе пространства.

#### Scenario: Объявление в проектном конфиге

- **WHEN** `.stepcast/config.yml` содержит `project.nested_repos: [public-site, vendor/sdk]`
- **THEN** действующая конфигурация несёт оба каталога

#### Scenario: Ключ не объявлен

- **WHEN** `.stepcast/config.yml` не содержит `project.nested_repos`
- **THEN** разбор конфигурации проходит, а состав вложенных репозиториев пуст

#### Scenario: Пустой список

- **WHEN** `.stepcast/config.yml` содержит `project.nested_repos: []`
- **THEN** разбор завершается ошибкой, называющей файл и ключ

#### Scenario: Непригодное значение элемента

- **WHEN** элемент списка — пустая строка, абсолютный путь, путь с сегментом `..` или путь с символом шаблона глоба
- **THEN** разбор завершается ошибкой, называющей файл и ключ

#### Scenario: Объявление в глобальном конфиге

- **WHEN** `~/.stepcast/config.yml` содержит `project.nested_repos`
- **THEN** разбор завершается ошибкой о ключе, недопустимом в глобальном конфиге

#### Scenario: Объявление в документе пайплайна

- **WHEN** документ пайплайна содержит `project: { nested_repos: [public-site] }`
- **THEN** разбор документа завершается ошибкой, называющей ключ

#### Scenario: Обращение подстановкой

- **WHEN** документ содержит `${project.nested_repos}`
- **THEN** разбор завершается ошибкой с перечнем имён пространства `project`, среди которых этого имени нет

#### Scenario: Отчёт о конфигурации

- **WHEN** пользователь выполняет `stepcast config` в дереве с объявленным составом
- **THEN** объявленные каталоги напечатаны именами и с указанием источника, а не счётчиком
