## Работает

- **Склейка повторно объявленных путей контекста**: файл, разрешённый при сборке контекста более одного раза — на разных уровнях, дважды на одном уровне или явным путём вперемешку с глобом, — входит в собранный контекст единственной записью. Тождество считается по абсолютному пути после раскрытия, а не по тому, как путь написан. Склеенная запись стоит на месте первого объявления (порядок «выходы предшественников → пайплайн → работа → шаг»), а файл читается один раз. Способ передачи выбирается по самому сильному из объявлений — явный `inline` сильнее вставки по `auto`, вставка сильнее передачи путём, — независимо от того, на каком уровне какое объявление встретилось; `inline` с любого уровня делает запись непонижаемой при превышении `context.max_tokens`. `context.json` называет для такой записи все уровни объявления полем `declared_in`, а `origin` остаётся уровнем места записи. Оценка размера и понижения `applyBudget` считают склеенную запись один раз, поэтому повтор больше не может вывести контекст за предел, которого он на самом деле не превышает. `stepcast context` печатает склеенные записи перечнем следом за разрезом по уровням: разрез относит такую запись к уровню её места, и без перечня ноль у уровня не отличить от «на этом уровне ничего не объявлено». Путь под `context.deny`, названный на нескольких уровнях, даёт одно событие `context.denied`, а не по одному на объявление.

## Известные ограничения

**Повтор между сообщениями общей сессии не склеивается.** При `session: shared` унаследованный контекст уходит в первое сообщение, а собственный контекст следующих шагов сессии собирается отдельным вызовом `assembleContext`, которому уже отправленные записи не видны. Файл, объявленный шагом сессии повторно, будет отправлен второй раз.

**Витрина не показывает уровни объявления.** Разрез по уровням в витрине строится из `context.json` по полю `origin`, поэтому склеенная запись видна там целиком на своём уровне-источнике, а `declared_in` не отображается: уровень, объявивший файл повторно, выглядит в витрине пустым. В `stepcast context` и в самом `context.json` уровни объявления названы.

**`context.json` с `declared_in` не читается движком прежней версии.** Схема отчёта строгая: поле добавлено обратной совместимостью снизу вверх (запись без него по-прежнему читается как объявленная однажды), но откат движка под уже записанным таким журналом схема отклонит — та же оговорка, что и у `lane` в `status.json`.
