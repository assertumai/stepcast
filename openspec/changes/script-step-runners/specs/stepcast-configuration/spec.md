## ADDED Requirements

### Requirement: Таблица раннеров объявляется секцией runners

Конфигурация SHALL содержать секцию `runners` — записи вида «имя → argv-префикс `command` и необязательный список расширений `extensions`», пополняемые и глобальным, и проектным конфигом.

Встроенный слой MUST поставлять записи `node` (`.js`, `.mjs`, `.cjs`),
`node-ts` (`.ts`, `.mts`, с `--experimental-strip-types`), `python3` (`.py`) и
`sh` (`.sh`) — на тех же правах, что прочие встроенные умолчания, с
происхождением «встроенное умолчание» в `stepcast config`. Имя записи MUST
состоять из букв, цифр, дефиса и подчёркивания; `command`, названный слоем,
MUST быть непустым списком непустых строк — строковой формы у него нет, потому
что правил разбиения строки на слова у движка нет; каждое расширение MUST
начинаться с точки. Слои MUST сливаться по листьям, как `backends`, в обе
стороны: запись вправе назвать одни `extensions` либо один `command`,
перекрывая одноимённую поле за полем, а не отменяя её целиком. Запись,
действующая после слияния всех слоёв, `command` иметь MUST: раннер, ни в одном
слое её не назвавший, — отказ разбора конфигурации с его именем, потому что
пустая команда дала бы argv из одного пути скрипта, то есть запуск файла
напрямую.

Отчёт `stepcast config` MUST печатать действующие `command` и `extensions`
записи значениями, а не их количеством: это единственный отчёт, отвечающий на
вопрос «чем исполнится файл этого расширения» и показывающий, какой слой
перехватил расширение.

Секция MUST быть допустима в обоих конфигах: в отличие от команды бэкенда,
раннер — обычно имя в `PATH`, и зависимость репозитория от него принадлежит
репозиторию.

#### Scenario: Встроенная таблица есть без всякой конфигурации

- **WHEN** ни один файл конфигурации секции `runners` не содержит
- **THEN** действующая таблица содержит `node`, `node-ts`, `python3` и `sh`, и `stepcast config` называет их источником встроенное умолчание

#### Scenario: Проект пополняет таблицу

- **WHEN** проектный конфиг объявляет `runners.uv.command: [uv, run, --script]`
- **THEN** действующая таблица содержит и встроенные записи, и `uv`, а происхождение `uv` называет файл проектного конфига

#### Scenario: Слияние по листьям

- **WHEN** домашний конфиг объявляет только `runners.python3.command: [python3.12]`
- **THEN** запись `python3` сохраняет встроенный список расширений и получает новую команду

#### Scenario: Слияние по листьям в обратную сторону

- **WHEN** домашний конфиг объявляет только `runners.python3.extensions: ['.py', '.py3']`
- **THEN** запись `python3` сохраняет встроенную команду и закрепляет за собой оба расширения

#### Scenario: Запись без команды

- **WHEN** ни один слой не назвал `command` объявленного раннера
- **THEN** разбор конфигурации отказывает, называя раннер и ключ `command`

#### Scenario: Форма записи проверяется

- **WHEN** конфигурация объявляет `runners.uv.command: "uv run"` либо расширение без точки
- **THEN** разбор конфигурации отклоняет значение, называя файл и ключ

#### Scenario: Отчёт называет команду и расширения

- **WHEN** проектный конфиг объявил `runners.uv` с расширением `.py`, и напечатан `stepcast config`
- **THEN** отчёт показывает команду `uv` и её расширения значениями, называя рядом слой, который их дал

### Requirement: Расширение, названное дважды, разрешается слоем или отказом

Расширение, закреплённое за разными раннерами в разных слоях конфигурации, SHALL принадлежать записи ближайшего слоя: проектный конфиг важнее домашнего, домашний — встроенной таблицы.

Два раннера **одного** слоя, назвавшие одно расширение, MUST быть ошибкой
конфигурации с именами обоих: между собой они несравнимы, и выбор по порядку
ключей документа был бы решением случая. Явный `runner` на шаге MUST оставаться
сильнее любого закрепления расширения.

#### Scenario: Проект перехватывает расширение

- **WHEN** проектный конфиг объявляет `runners.uv` с расширением `.py`, а встроенная таблица держит `.py` за `python3`
- **THEN** скрипт `.py` без явного `runner` исполняется раннером `uv`

#### Scenario: Спор внутри одного слоя

- **WHEN** проектный конфиг объявляет два раннера с расширением `.py`
- **THEN** разбор конфигурации отказывает, называя оба имени и расширение

#### Scenario: Явное имя сильнее закрепления

- **WHEN** расширение `.py` закреплено за `uv`, а шаг объявляет `runner: python3`
- **THEN** исполняется раннер `python3`
