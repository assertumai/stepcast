## MODIFIED Requirements

### Requirement: Контракт источника — четыре глагола с JSON на входе и выходе

Источник SHALL принимать глаголы `index`, `select`, `write` и `check`, получать запрос JSON на стандартном вводе и отдавать ответ JSON на стандартном выводе. Ответ `select` MUST содержать перечень записей, каждая с `id`, `title`, оценкой `tokens` и ровно одним из `path` или `text`. Запрос `select` MUST нести исключительно поля `scope`, `id` и `budget`, каждое из них необязательно, и MUST NOT нести никаких иных полей. Запись контекста `knowledge: index` MUST разрешаться вызовом глагола `index` с запросом `{}`, а не вызовом `select`. Ненулевой код возврата MUST трактоваться как отказ источника.

#### Scenario: Отбор по области

- **WHEN** движок вызывает `select` с запросом `{"scope":["src/judge/**"]}`
- **THEN** источник отдаёт записи, чья область пересекается с указанной

#### Scenario: Оглавление контекста вызывает index, а не select

- **WHEN** запись контекста пайплайна или работы объявляет `knowledge: index`
- **THEN** движок разрешает её вызовом глагола `index` с запросом `{}`, и глагол `select` при этом не вызывается

#### Scenario: Запрос select не несёт полей вне контракта

- **WHEN** движок вызывает `select` по области или по перечню идентификаторов
- **THEN** запрос несёт только поля из `scope`, `id` и `budget`, и поля `index` в нём нет ни при каком селекторе

#### Scenario: Отказ источника

- **WHEN** источник завершается ненулевым кодом или отдаёт ответ, не проходящий схему
- **THEN** шаг проваливается с диагностикой, называющей источник и глагол, а контекст пустым не собирается
