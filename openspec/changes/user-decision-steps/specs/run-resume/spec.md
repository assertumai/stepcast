## ADDED Requirements

### Requirement: Перезапуск с шага выражается возобновлением, а не правкой журнала

Решение о перезапуске с шага SHALL выражаться возобновлением прогона с этого шага, и журнал исходного прогона MUST оставаться неизменным. Точка возобновления MUST быть той же, какую называет пользователь команде возобновления: работа целиком либо конкретный шаг работы. Шаги выше точки MUST переиспользоваться по совпавшему ключу, дерево MUST восстанавливаться по якорю последнего переиспользованного шага, а новый прогон MUST ссылаться на исходный тем же полем, каким на него ссылается всякое возобновление. Усечение записей исходного прогона MUST NOT применяться ни при каком исходе решения.

#### Scenario: Журнал исходного прогона цел

- **WHEN** прогон закончился решением о перезапуске с шага и продолжился новым
- **THEN** файлы исходного прогона не изменились, а новый прогон ссылается на него

#### Scenario: Шаги выше точки переиспользованы

- **WHEN** новый прогон возобновлён с выбранного человеком шага
- **THEN** шаги выше точки взяты из исходного прогона, а шаг перезапуска и всё ниже исполнены заново

### Requirement: Решение, записанное мёртвому прогону, применяется при возобновлении

Решение, записанное для прогона, чей процесс уже не жив, SHALL не теряться: приём решения MUST называть, что прогон не идёт, и MUST называть команду возобновления. Возобновлённый прогон MUST переисполнить ожидавший шаг и MUST применить лежащее решение первым же тактом опроса, не спрашивая человека второй раз. Срок такого ожидания MUST считаться заново от начала нового ожидания: применять срок, истёкший при мёртвом процессе, некому.

#### Scenario: Решение ждёт возобновления

- **WHEN** решение записано прогону с мёртвым процессом
- **THEN** приём решения называет это и команду возобновления, а запись решения остаётся в каталоге прогона

#### Scenario: Возобновление применяет лежащее решение

- **WHEN** прогон с записанным решением возобновлён
- **THEN** ожидавший шаг переисполняется и применяет лежащее решение, не заводя нового ожидания для человека

### Requirement: Возобновление не переспрашивает решение успешного шага

Шаг решения, завершившийся успехом, SHALL переиспользоваться возобновлением по общему правилу совпавшего ключа, и человека MUST NOT спрашивать второй раз. Шаг решения, переисполняемый по любой причине — несовпавший ключ, точка `--from`, обесценивание нижележащего графа, — MUST заводить новое ожидание и MUST спрашивать заново. Принятое решение в ключ шага MUST NOT входить: ключ отвечает на вопрос о действительности определения, а не о том, что человек решил.

#### Scenario: Успешное решение переиспользовано

- **WHEN** прогон с шагом решения, завершившимся успехом, возобновляется, и ключ шага совпал
- **THEN** шаг переиспользован, и нового ожидания не заводится

#### Scenario: Переисполняемое решение спрашивается заново

- **WHEN** возобновление начинается с шага выше шага решения
- **THEN** шаг решения переисполняется и заводит новое ожидание

#### Scenario: Правка поля шага делает решение недействительным

- **WHEN** перечень допустимых исходов шага изменён, и прогон возобновляется
- **THEN** ключ шага не совпадает с прежним, и человека спрашивают заново
