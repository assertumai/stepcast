# Scarp

Движок пайплайнов для разработки с ИИ-агентами.

Агент — это тип шага, а не оркестратор. Топология работ, условия перехода,
бюджеты, политика повторов и проверка результата описаны декларативно и
исполняются движком. Модель не решает, что делать дальше — она делает то,
что ей поручил текущий шаг, и отдаёт результат, который проверяется контрактом.

## Статус

Проектирование. Кода нет — зафиксированы формат и модель данных.

- [Формат пайплайна](docs/pipeline-format.md) — `scarp.yml`
- [Директория прогона](docs/run-layout.md) — состояние, resume, дифф, стоимость
- [Пример](examples/openspec-change.yml)

## Принципы

**Управление потоком детерминировано.** Порядок работ, ветвления и реакция на
отказ вычисляются движком из объявленного графа, а не выводятся моделью по ходу
дела.

**Результат шага проверяется контрактом.** У каждого шага объявлен `expect`.
Жёстким гейтом становятся только проверки, которые дешевле и надёжнее самой
работы: код возврата, схема, наличие файла, зелёные тесты. Оценка агентом-судьёй
доступна, но по умолчанию совещательная.

**Контекст передаётся файлами.** Шаг не наследует диалог предыдущего шага. Он
читает объявленные входы и пишет объявленные выходы. Следующий шаг получает
результаты, прошедшие проверку, а не протокол проб и ошибок.

**Повторы ограничены бюджетом, а не догадками.** Число попыток и потолок
пайплайна по деньгам, времени и токенам — единственные ограничители. Каждая
попытка записывается отдельно, поэтому шаг, который стабильно проходит не с
первого раза, виден в отчёте как диагноз промпта или спеки.

**Job не знает о пайплайне.** Работа описывает только то, что она делает, свой
бюджет и условие сходимости, и выносится в отдельный файл. Зависимости, условия
запуска и обработка отказа живут в пайплайне, на месте подключения. Поэтому
одна и та же job переиспользуется в разных пайплайнах без изменений.

**Ошибки ловятся до запуска.** `scarp lint` проверяет структуру пайплайна
статически: циклы, недостижимые работы, неразрешимые ссылки, цикл без бюджета.
Отрабатывает за миллисекунды, до того как потрачен первый токен.

## Раскладка

| | |
|---|---|
| Бинарник | `scarp` |
| Пайплайн | `scarp.yml` в корне репозитория или `.scarp/pipelines/*.yml` |
| Состояние | `~/.scarp/runs/<project>/<run>/` |
| Переменные | `SCARP_*` |
